## 1. v3600：D=64 → D=125 全保留

### 1.1 改动（`scripts/overfit.py` 头部注释原文）

```
# D=125：rfft2 真实网格 = WIN(5) x (patch^2*3/2+1 = 25) = 125，全保留不截断。
# 这是 v3600 相对 v2500 的唯一改动 —— 网格感的根因是 codec 里 spec[:, :D] 的
# 非对称硬截断（D=64 只留 h0,h1 全行 + h2 的 w0~13，h3,h4 整行丢弃）。
# 实测 D=64→125：往返 PSNR 28.63→49.82 dB，网格比 1.373→1.172（素材原值 1.111）。
D, GRID, PATCH, WIN, IMG, TS = 125, 32, 4, 5, 128, 6
# 真实频域网格尺寸（用于诊断分频段，不再用 0/16/32/48 均分——那会混淆 DC 与高频）
H_FFT, W_FFT = WIN, (PATCH * PATCH * 3) // 2 + 1
```

| v2500（D=64） | 1,135,658 | — |

差值来源：所有 per-channel 参数从 [64] 变 [125]（12 个 block × a_mu 125 + StandingWaveFFN 的 natural_freq 256→? 等），`aether_gif_model.py` 里 `each_prototype` 从 [16,128] 变 [16,250]。

### 1.5 `verify_dmodel_ceiling.py`：推翻旧结论的决定性脚本

脚本 docstring 原文记录了旧结论的谬误：

> 背景：2026-10-09 记录写「D=64 26.70 dB / D=125 全保留 26.75 dB，几乎无差别」，并据此得出「表征不是瓶颈，问题全在模型侧」。但同一行记录里 patch=8/D=485 那条写着「同样 14.84 dB（手算漏了 *10.0，真实 codec 26.70）」——**这个 26.70 是套用 D=64 的修正值，不是实测**。所以「D=125 无差别」从未被真实测过。

脚本对 7 个素材（台球/数字100/飞机/门票/闹钟/星座/新头像）× 3 个 D（64/100/125）逐一实测往返 PSNR、网格比、丢弃能量。结论（写入 overfit.py 注释）：**D=64→125 往返 PSNR 28.63→49.82 dB，网格比 1.373→1.172**。

### 1.6 `diag_grid_source.py`：网格感来源的三候选判决

脚本设计（docstring）：

```
三个候选：
  (A) FFT 变换本身有噪声      -> 纯往返误差应 > 1e-3
  (B) 逐 patch 独立 FFT 导致块边界不连续  -> 全图一次 FFT 应无网格
  (C) 频谱硬截断（只留 64/125）-> 全保留 125 应无网格
```

五个对照：① 原始素材 ② 全保留 125 ③ 前 64 个（非对称截断）④ 矩形低通 h<3,w<13（39 系数）⑤ Hann 窗平滑衰减。

结论记录在工作记忆中：**全保留 125 系数时网格比 = 素材原值，网格感完全消失；FFT 往返零噪声（误差 5.96e-07）**。

## 2. v3700_D125_修复烧焦 —— 当前画质基准

### 2.1 相对 v3600 的改动（diff 145 行，全在 `scripts/overfit.py`）

**新增约束一：高频增益约束（治烧焦感）**

```python
# ---------- v3700 新增：高频增益约束（治烧焦感）----------
# 只约束中高频(w12-18) 与 高频(w19-24)，DC/低频/中低不碰（它们由原 loss 负责）
HF_SEGS = [(12, 19), (19, 25)]
GAIN_TGT = 1.0         # 目标增益：输出/目标 的分段能量比 = 1.0（完全对齐）
GAIN_W = 0.5           # 该 loss 权重
HUBER_DELTA = 0.5      # 过冲 0.5 以内用 L2，超过用线性（防梯度爆炸）
```

**新增约束二：径向 Nyquist 过冲约束（治烧焦的物理成因）**

```python
# ---------- v3700 新增：径向 Nyquist 过冲约束（治烧焦的物理成因）----------
# 128px 网格的 Nyquist 半径 = 90.5px，取最后 3 个等宽 bin（r >= 72.4）作为「最高频环」。
# ⚠️ 口径修正（第一版踩坑）：不能用 r>=11（那是像素半径，对应 bin 1/2，不是高频），
#   也不能说素材在r>=11 处能量为0 —— 之前那张功率谱表**归一化到半径0**才显示 0.0000，
#   实际能量是非零的。真正接近 Nyquist 的是最后几个 bin。
# 素材在 r>=72.4 的能量=1.37e12（占总能量 99.99%），可安全作分母。
RAD_LO_FRAC = 0.80       # 取半径 >= 0.80 * rmax 的那一圈
RAD_CAP = 1.2            # 能量比上限（素材=1.0，模型不得超过 1.2倍）
RAD_W = 1.0
```

日志里的实际基准行：`[RAD] Nyquist 环(r>=72.4) 素材基准能量 = 8.4493e+07`。

**关键观察**：
1. `gain=0.0000`（终态）= 高频增益约束**完全满足**（两段都对齐 1.0 以内）。

4. 150 步冒烟（`smoke150_v1/smoke150.log`）：`PSNR=10.40 dB frame-diff model=15.95`，与 v3600 冒烟（10.40 / 15.92）几乎相同——前 150 步两个约束还没拉开差距。

## 3. v3700 的条件生成探索（v1→v4，5 个脚本）

这是「从重建到生成」转型的第一个实验室。所有脚本都在 v3700 目录，全部是单样本（8-ball）+ CLIP 条件的短训。

### 3.1 脚本清单（`scripts/` 实测）

| 脚本 | 用途 |
|---|---|
| `test_clip_dock.py` | CLIP 集成测试（定位单样本归一化 bug） |
| `test_cond_gen.py` → `_v2.py` → `_v3.py` | 条件驱动重建方案三代演进 |
| `test_cond_gen_v4.py` | **纯条件生成**（CLIP 感知损失，无像素重建 loss） |
| `test_conditioned.py` | 条件训练 |
| `preencode_clip.py` | 裁剪条件到缓存 `clip_cache/cond.npy` |
| `aether_gif_model_cond.py` | 条件版模型副本 |

- `wcos=+0.6148` 在上升（-0.3776 → 0.6148），功率加权下条件有效但弱；
- PSNR 13.73 dB，与 clip_dock 的 13.94 dB 同水平。

### 3.4 v4 方案设计（交接文档 §2.3）

- 完全移除像素级重建损失，只留 CLIP 感知损失：`L = -mean(cos_sim(clip(image_features), condition_features))`；
- 关键帧选择 `[0, T//2, T-1]`；
- 用冻结 CLIP 图像编码器提取生成 GIF 特征。

**状态**：交接文档 §0 一句话现状与 TODO 都写着「待启动短训验证」。`test_cond_gen_v4.py` 存在，但**没有任何 v4 训练日志**（outputs_real 里只有 clip_dock/conditioned 两个 GIF + 两份日志）。

### 3.5 条件向量的早期形态

`preencode_clip.py` 产出 `clip_cache/cond.npy`（裁剪后的条件缓存）。这与 v4200 的 `clip_cache/{text_emb,image_emb,image_ok,group_list}.npy` 四件套不同——v3700 时代还是「单样本单条件」，v4200 才扩展到 14145×2049。

### 3.6 v3700 条件探索的结论链

1. CLIP 特征直接重建物理场：**失败**（13.94 dB vs 22.46 dB 基线）。
2. 条件调制器驱动漂移场原型 + 像素重建 loss：**部分有效**（wcos 0.61）但用户明确指出「这不是真正的生成」（仍有 GIF 监督）。
3. 纯 CLIP 感知损失（v4）：**设计了，从未运行**。
4. 这三步的失败直接催生了 v4200 的架构：保留物理核、把「条件→吸引中心」做成可训练通路（CondFieldPredictor）、用「重建/生成双通路 + 直接监督」绕开梯度链过长问题。
