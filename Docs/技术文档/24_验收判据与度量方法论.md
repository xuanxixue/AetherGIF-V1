# 24_验收判据与度量方法论

> 本文档记录 AetherGIF-V1 项目全部验收脚本的判据定义、代码实现、修正历史与已知缺陷。
> 覆盖：`auto_accept.py`（v3000 系列，四项判据）、`accept_target.py`（v3500 系列，素材基准）、`eval_generalize.py`（v4200，已写未跑）、以及散落各版本的 150 步验证纪律。
> 所有阈值、代码行号、实测数值均来自脚本源码与版本说明原文。

## 1. 验收基准的三次演变（项目史主线）

### 1.1 第一次：codec 天花板基准（v3000J，auto_accept.py）

**判据**（`versions/v3000_修复版_方案D派生_3000步/scripts/auto_accept.py`）：

| # | 指标 | 阈值 | 为什么是这条 |
|---|---|---|---|
| 1 | 空间域对比度 std | ≥ codec 天花板的 **85%** | 直击第十五死穴（糊 = 动态范围被压缩） |
| 2 | PSNR vs codec 天花板 | 不低于 v2500 基线 **0.5 dB** | 修对比度不能把结构还原弄坏 |
| 3 | 频段能量占比偏差 | ≤ **1.5 个百分点** | 保住 v3000 修好的能量分布（v2500 在此项偏差 −79%） |
| 4 | 过曝占比 / 逐帧崩塌 | < 1.5% / 无 | 防 outlier 撑爆画面 |

**代码实现要点**：
- 基准 `gceil` = `decode_field_to_frames(field, ..., normalize=False)`（固定 clamp 口径），**不是**原始素材——两者口径不同（原始素材未经 4×4 patch + rfft2 截断），实测原始 std 反而低于天花板，直接比会失真；
- 频段按 `w = c % W_FFT`（W_FFT=25）切：w0(DC)/w1-6/w7-12/w13-18/w19-24，**这是对 v2500 时代"按 0/16/32/48 均分导致读数失真"的修正**（第十二死穴配套 bug #2）；
- 被测 checkpoint 走 `AetherGIFModel(use_qwen=False)` 前向，`texts=["台球"]`（use_qwen=False 时文本参数是随机初始化的 nn.Parameter，不影响，因为不走文本编码）；
- 退出码 0=PASS / 1=FAIL，可输出 JSON 供夜间看护脚本消费。

**判据有效性已验证**：用 v2500 基线跑该脚本 → 判出 **6 项 FAIL**（含对比度 76.8% < 85%），证明判据有区分度，不会把任何版本都判成 PASS。

### 1.2 第二次：原始素材基准（v3500，accept_target.py）—— 用户视觉反馈推翻

**事件**：v3500_e 用旧版验收"边界 19.92→19.32 降 3% PASS"，但用户看画直接判 FAIL：

> 图1（v3500_e）：布满密集的颗粒感和网点纹理，类似早期报纸印刷品；边缘锯齿、模糊，细节丢失；光影过渡受噪点干扰、衔接破碎，整体偏扁平。
> 图2（素材）：非常平滑、无颗粒；线条极其锐利；平滑的 3D 光影过渡，立体感和质感极强。

**数据完全印证，且暴露验收基准错误**：
| | 边界跳变 | 内部跳变 | 像素 std | Sobel |
|---|---|---|---|---|
| **素材（图2）** | **6.81** | **5.59** | **35.99** | **4.89** |
| v2500 | 19.92（2.9×） | 12.30（2.2×） | 27.81（77%） | 11.33（2.3×） |
| v3500_e（图1） | 19.32（2.8×） | 16.00（2.9×） | 26.96（75%） | 13.35（2.7×） |

**两个错误**：
1. **拿一个病号当健康标准**：v2500 边界跳变是素材的 4 倍，它本身重度噪点。拿它当降噪及格线，"降 3%" 也判 PASS；
2. **把噪点当细节保护**：edge-only 版的"内部跳变 16.00（130%）"曾是成果炫耀，相对素材它是 **2.9 倍**，正是用户说的"密集颗粒网点"。

**accept_target.py 新判据**（以原始素材为基准）：
| 指标 | 要求 | 对应用户诉求 |
|---|---|---|
| 边界跳变 | ≤ 素材 × 1.6 | 去颗粒网点 |
| 内部跳变 | ≤ 素材 × 1.6 | 去噪点 |
| 像素 std | ≥ 素材 × 65% | 立体感/光影 |
| Sobel | ≤ 素材 × 2.2 | 去锯齿粗糙 |

阈值依据（代码注释原文）：边界 ≤1.6× 是因为"天花板 6.81 是素材 4.995 的 1.36×"；std ≥0.65× 是因为 v2500 现状约 0.77×，0.65 给微调留空间。

**脚本结构**（`versions/v3500_微调_去LED网格_1000步/scripts/accept_target.py`，96 行）：
- `metrics(g)` 返回 dict：edge（边界跳变）/inner（内部跳变）/ratio（网格比）/std/sobel/fdiff；
- 边界掩码构造：`hb = [(j+1) % PATCH == 0 for j in range(dh.shape[2])]`，即差分后索引按 PATCH=4 切；
- Sobel 用 `np.diff` 的一阶差分模长近似（非标准 Sobel 算子），跨脚本对比时须确认口径一致；
- 四方对比打印：原始素材(目标) / codec天花板 / v2500(起点) / v3500-t(本版)，最后给 PASS/FAIL 总判定。

**验收线（用户原话）**：

- 目标不是"泛化出没见过的"，而是"**在见过的数据里组合出没见过的**"。

## 2. auto_accept.py 逐行判据实现（代码事实）

### 2.1 阈值常量（第 32-41 行）

```python
TH_STD_RATIO = 0.85     # 对比度 ≥ target 的 85%
TH_BAND_TOL = 0.015     # 频段能量占比容差（绝对占比，1.5 个百分点）
TH_OVEREXPO = 1.5       # 过曝像素占比上限（%）
TH_COLLAPSE_RATIO = 0.4
```

### 2.2 两处历史误报及修正（2026-10-12）

**误报 A —— 过曝单位错配**。原代码 `over = (...).mean() * 100` 得到的是**百分数** 1.23，却与 `TH_OVEREXPO = 0.015`（**小数**）比较，`1.23 > 0.015` 恒真 → 任何非零过曝都判 FAIL。1.23% 本来就低于 1.5% 阈值。已把阈值改为 `TH_OVEREXPO = 1.5`（百分数口径）。

**误报 B —— 崩塌判据不看 target**。原判据 `per[i] < per.mean()*0.4` 是**绝对阈值**，把 target 自身真实的低对比度帧也判成崩塌。实测：即使 **100% 还原 target**，仍有 5 帧（f04/f11/f19/f24/f29）落在 `per.mean()*0.4` 以下被误报。崩塌的物理含义是「模型这一帧比它本该有的样子平」，故改为**逐帧对标同位置 codec 天花板**：`per[i] < ceil_per[i] * 0.4`。修正后 v3000J 仍报帧 10~19 崩塌（比值 0.18），说明**这一项是真 FAIL，不是误报**。

### 2.3 频段能量口径（第 60-73 行）

```python
def band_energy(a_tar, a_out):
    for name, idxs in [
        ("w0(DC)", [c for c in range(D) if c % W_FFT == 0]),
        ("w1-6",   [c for c in range(D) if 1 <= c % W_FFT <= 6]),
        ("w7-12",  [c for c in range(D) if 7 <= c % W_FFT <= 12]),
        ("w13-18", [c for c in range(D) if 13 <= c % W_FFT <= 18]),
        ("w19-24", [c for c in range(D) if 19 <= c % W_FFT <= 24]),
    ]:
        et = (a_tar[:, idxs] ** 2).sum().item()
        eo = (a_out[:, idxs] ** 2).sum().item()
```
判定时归一化为占比再比较偏差：`dev = vo - vt`（绝对百分点），`abs(dev) > TH_BAND_TOL` 即 FAIL。

**注意**：D=64 时代 `W_FFT` 仍是 25（PATCH*PATCH*3//2+1），但 D=64 时只取前 64 个通道（h=0,1 全 + h=2 的 w0~13），w19-24 频段在 D=64 下**只覆盖 h=0,1 两行**——这是 D=64 截断导致的频段读数偏窄，D=125 后该问题消失。

### 2.4 PSNR 口径（第 132-135 行）

```python
def psnr(a, b):
    n = min(len(a), b)
    return 10 * math.log10(255.0 ** 2 / max(((a[:n] - b[:n]) ** 2).mean(), 1e-12))
```
被测是 GIF 产物灰度 vs codec 天花板灰度，**不是**系数域 PSNR。v2500 基线与被测同口径（都读 `overfit_honest.gif` 固定 clamp 产物）。

## 3. 平均值度量骗人的三类实例（第十五/十七/十八死穴同源）

这是本项目最核心的度量教训，单独成节。

### 3.1 实例一：log 域振幅比 + wcos 双过，视觉退化（第十五死穴）

- log 域振幅比 0.92~0.98（接近 1.0）+ wcos 0.9118（超越 v2500 的 0.893）→ 宣布修复成功；
- 实际出图明显更糊；
- 机理：两者都是平均值度量。一部分位置偏高、另一部分偏低 → 平均值完美；相位误差符号相反 → 加权 cos 很高。**对比度损失恰好在平均值里互相抵消**。

### 3.2 实例二：全局 std 99.4% 达标，帧 10~19 崩塌（第十七死穴）

- v3000J 全局对比度 std 34.1/34.3 = 99.4%，cst loss 归零；
- 逐帧实测：帧 10~19 的 model/天花板比值 0.18（真崩），帧 0~9 矫枉过正冲到 55~57（真值 44~46）；
- 机理：全局 std 被高对比帧主导，低对比帧被牺牲来抬全局值。

### 3.3 实例三：跳变均值达标，轮廓压平 45%（第十八死穴）

- v3500_t 边界/内部跳变均值全部达标（1.51×/1.29× 素材）；
- 分布诊断：p99 从素材 47 压到 26（轮廓糊），p50 从 0 变成 2（背景噪点没清干净）；
- 机理：素材是「大量零 + 少数大」的极端重尾（尾 5% 占 61.6% 能量），模型把所有跳变压到中等来凑均值。

### 3.4 判据（项目铁律）

**任何平均值形式的度量都不能单独作为验收依据**，必须同时报告：
1. **空间域**：对比度 std、动态范围 p1–p99、Sobel 锐度（相对 target 比例）；
2. **分布域**：分位数（p50/p75/p99）而非只有均值；
3. **逐帧/逐通道**：帧间 std、逐通道能量比，而非全局聚合。

## 4. 图像空间指标体系（accept_target.py 口径）

### 4.1 指标定义

| 指标 | 定义 | 方向 |
|---|---|---|
| 边界跳变 edge | 按 PATCH=4 切边界，边界处 \|diff\| 均值之和（水平+垂直） | 越低越干净 |
| 内部跳变 inner | 同上但取非边界位置 | 需保真（不能过低） |
| 网格比 ratio | edge/inner | 越接近素材 1.010 越好 |
| 像素 std | 全帧灰度 std | 立体感，不能塌 |
| Sobel | 一阶差分模长均值（近似） | 锐度，过高=锯齿 |
| 帧间差 fdiff | 相邻帧 \|diff\| 均值 | 运动轨迹 |

### 4.2 各版本实测总表（8-ball，128px，30 帧）

| 版本 | 边界 | 内部 | 网格比 | std | Sobel | 帧间差 |
|---|---|---|---|---|---|---|
| 原始素材（正确基准） | 4.99~6.81 | 4.94~5.59 | 1.010~1.021 | 42.8 | 4.20 | 7.92 |
| codec 天花板（架构上限） | 6.81 | 5.59 | 1.218 | 35.9~35.98 | 4.89 | — |
| v2500（方案 D 基线） | 19.92 | 12.30 | 1.620 | 27.8 | 11.33 | 7.96 |
| v3000J | 13.44 | 0.65 | 20.663 | — | — | 6.51 |
| v3500_e（edge-only） | 19.32 | 16.00 | — | 26.96 | 13.35 | — |
| v3500_t（texture+std守卫） | 7.55 | 6.37 | — | 26.93 | 5.36 | — |

（边界/内部有两组数是因为不同脚本用 5.00/4.93 或 6.81/5.59 口径——前者是原始 GIF 直接 resize，后者是 codec 天花板重建。**跨版本对比必须确认两边同口径**，这是 18 号文档记载的口径校准坑。）

### 4.3 关键读数解释

- **v2500 是"内外都有内容"**：边界 9.96 / 内部 6.15（v3000J 口径下 19.92/12.30），用户观感"细节到位"；
- **v3000J 是"结构性空洞"**：内部跳变 0.65 ≈ 原始 GIF 的 0.62（根本没有内部细节），但边界 13.44 = 原始 GIF 的 21 倍（能量全堆 patch 边界）→ "像被火烧糊了"；
- **v3500_t 的模糊**：均值三项达标但 p99 掉 45%（第十八死穴）。

## 5. 150 步验证纪律（项目调参铁律）

### 5.1 纪律内容

**改 loss 先跑 150 步比同步数指标，方向错立刻终止，别一上来跑 1000 步。**

依据（单样本记录 §6.3）：方案 B 跑偏时（a_out 从 0.16 飙到 0.655、中高 ratio 恶化到 14.9×），150 步检查拦下终止——若等 1000 步才发现，浪费 1 小时 GPU。150 步足以看出振幅比趋势。

### 5.2 150 步能判什么、不能判什么

| 可判 | 不可判 |
|---|---|
| loss 各项量级是否平衡（v3500 的 noise loss 650 万倍 bug 就是这样发现的） | μ 的绝对收敛（跨 6.6 log 单位需 ~1450 步，150 步谱未展开不等于方向错） |
| 指标方向（网格比降/内部跳变幻保/wcos 稳） | PSNR 终值（phase loss 未收敛） |
| 是否出现崩塌帧/过曝等急性病 | 全局 std 达标（v3000J 的教训：150 步达标可能是牺牲局部换的） |

**修正记录**（单样本记录 §9.8）："150 步适合判 loss 方向，但 μ 跨 6.6 个 log 单位需要更长窗口，不能因 150 步谱未展开就误判方向"——纪律本身也修过一次。

### 5.3 试跑隔离（血的教训）

**试跑必须带 `OVERFIT_TAG=<tag>`，产物落 `outputs_real/<tag>/`。**

起因：跑 150 步试跑时直接写 `outputs_real/overfit_ckpt.pt`，**覆盖掉已训好的 3000 步 checkpoint**。三道保险随之建立：

| 保险 | 实现 | 作用 |
|---|---|---|
| ① 输出隔离 | `OVERFIT_TAG` 环境变量 | 试跑绝不污染正式产物 |
| ② 周期保存 | 每 250 步存 `overfit_ckpt_stepNNNN.pt` | 中途崩溃可断点续训 |
| ③ 最佳留档 | 对比度最接近 target 的那一步存 `overfit_ckpt_best.pt`，永不被覆盖 | 训练后期退化也不丢最好的 |

**已知失效案例**：v3000J 训练启动于周期保存机制加入之前，用的是旧代码，中途没有 `_ckpt_stepNNNN.pt` 落盘；`overfit_ckpt_best.pt` 也不存在（`[SAVE]` 行在日志中出现 0 次）。评估不重启的理由：已跑 375 步（占 12%）对比度正处良好上升期、剩余约 3 小时崩溃概率低、已建立每小时自动化看护。

## 6. 度量口径陷阱清单（跨版本）

| # | 陷阱 | 实例 | 防范 |
|---|---|---|---|
| 1 | min-max 归一化被离群系数绑架 | v2500 出图 normalize=True → std 24.5 vs target 53.2；换固定 clamp 后 std 34.7、PSNR 18.0→20.0 | 禁 min-max 做质量评估；主口径分位裁剪(0.5%,99.5%) + 副口径固定 clamp |
| 2 |  Jensen 不等式误用 | `log(mean_N(a))` → bias −2.53, corr 0.8674 vs 正确 `mean_N(log(a))` → bias −0.51, corr 0.9953 | 诊断聚合顺序必须与 loss 完全一致 |
| 3 | 带符号误差做边界统计正负相消 | 边界/内部比值失真成 1e10 量级 | 边界统计必须用**平方能量** |
| 4 | TGT_STD 口径不一致 | contrast_loss 第一版用 numpy decode 路径算 target，std 差 100 倍 | target 常数必须与 loss 内解码同一条代码路径算出 |
| 5 | 逐帧 reshape 把 win 维当帧序 | `x.reshape(TS*WIN, GRID², pix)` 错的——N 里没有 WIN 维 | 帧序号 `f = t*WIN + w`，按 decode 真实 permute 校验（corr=0.99999, maxabs=0.26） |
| 6 | 目标值硬编码 | v3500 edge_ratio_t 在 patch 空间算出 2.966（图像空间口径 1.229），方向反了 | 目标值必须现场从 target 计算，口径一改硬编码就失效且不报错 |
| 7 | 新 loss 不单测量级 | v3500 noise loss 的 `.mean(dim=0)` 使 loss 量级 1,553,134（主 loss 的 650 万倍） | 新 loss 先单测量级再启动长训 |
| 8 | 绝对阈值判崩塌 | `per[i] < per.mean()*0.4` 把 target 自身低对比帧误判（100% 还原 target 也报 5 帧） | 逐帧对标同位置 codec 天花板 |
| 9 | encode/decode 双侧不同口径 | NORM=10.0 只在 encode 乘、decode 忘乘回 → 差 0.6 dB | 评估双侧必须同口径 |
| 10 | 频段按索引均分 | 0/16/32/48 均分混淆 DC 与高频 | 按真实 rfft2 网格 w=c%25 切 |

## 7. 验收判据的已知缺陷（未修）

1. **frame-diff 无判据**：所有脚本都测但无一项写进 PASS/FAIL（v2500 过冲 10.26 vs target 5.56 是已知缺陷，只在 v3500 守卫里要求"≥ v2500 90%"）；
2. **过曝是绝对阈值**：`TH_OVEREXPO = 1.5`（%），高调素材会被误判，相对 target 的过曝比例从未作为判据；
3. **天花板基准是单样本实测**：14145 个 GIF 的天花板分布无数据，跨素材验收时基准应不同但无据可依；
4. **两套基准未互校**：天花板基准（auto_accept）与素材基准（accept_target）从未同时跑同一产物对比；
5. **eval_generalize.py 零运行**：v4200 验收脚本从未执行（见 20 号文档 §2.1）；
6. **Sobel 是近似实现**：accept_target.py 用一阶差分模长，非标准 3×3 Sobel 算子，跨脚本数值不可直接比。
