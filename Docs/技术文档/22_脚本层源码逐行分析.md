## 1. `preencode.py` —— 离线 CLIP 预编码（309 行）

### 1.1 为什么离线（docstring 的账）

```
实测 PMNN 每步 3.78s（batch=1, N=6144）。若每步都过 CLIP：
  - 每步额外 0.3~0.8s（文本塔 XLM-R + 视觉塔 EVA-02）
  - 显存再吃 1.6GB，4GB 卡直接 OOM
离线后：
  - 训练单步只多一次 [B,2049] 的数组读入 + 一次 Linear，**开销 <1%**
  - 显存零占用
  - 单步可望降到 1.2s 以内 → 7 天能跑的步数翻 3 倍
```

⚠️ **预期与实测的差距**：「单步可望降到 1.2s 以内」——实测 0.2~0.29 步/s = 3.4~5.0 s/步。离线预编码确实把 CLIP 开销降到了 <1%，但单步仍慢，因为**实时 encode GIF 场**（87GB 缓存放弃后的代价，见文档 21 §3.5）成了新瓶颈。docstring 的预期没有兑现，且没有记录为什么。

### 2.2 坐标构造（infer.py 与模型 generate() 的口径一致性）

```python
def _coords(dur, device):
    from physics.kuramoto_sync import build_spacetime_index
    fps = 10
    T_step = max(2, dur * fps // 5)
    t, s = build_spacetime_index(T_step, GRID, GRID, device)
    return t, s
```

⚠️ **潜在口径分歧**：`model.generate(duration=dur, ...)` 内部也用 `T_step = duration * fps // self.time_step`（self.time_step=5）构造坐标，而 infer.py 在 generate **之后**又用 `_coords(dur, device)` 重建一次坐标传给 `_field_to_frames`。两次构造的公式相同（`max(2, dur*10//5)` vs `dur*10//5`——generate 里没有 max(2,...) 截断！），当 `dur=1` 时 generate 内部 `T_step = 10//5 = 2`（恰好也是 2），`dur=0` 时 generate 得 0（会炸）而 _coords 得 2。**dur≥1 时两者一致，dur=0 时不一致**。实际调用都带 `--seconds` 默认 1.2 → dur=1，安全。

## 4. `diag_compose.py` —— 记忆 vs 生成的三指标判决（130 行）

### 4.1 指标 1：同条件两次生成是否相同

```python
torch.manual_seed(0)      # 固定 seed，但 generate 内部仍用 randn/rand 采样 a0/θ0
...
with torch.no_grad():
    o1 = model.generate(duration=3, cond_vec=c_a)
    o2 = model.generate(duration=3, cond_vec=c_a)
d_a = (o1[0] - o2[0]).abs().mean().item()
d_t = (o1[1] - o2[1]).abs().mean().item()
rel = d_a / max(o1[0].abs().mean().item(), 1e-9)
print(f"  同条件两次输出：振幅平均差={d_a:.6f}  相位平均差={d_t:.6f}")
print(f"  相对差异 = {rel*100:.2f}%")
if rel > 0.02:
    print("  → 输出显著不同：模型在**生成**，不是在背训练样本 ✓")
else:
    print("  → 输出几乎相同：模型在查表/记忆 ✗")
```

判据 `rel > 0.02`（2% 相对差异）。注意 `torch.manual_seed(0)` 只固定了**诊断脚本**的随机源，`model.generate` 内部的 `torch.randn`/`torch.rand` 消耗的是同一全局随机源——所以两次 generate 的初态不同（第二次接着消耗随机流），实验设计正确。

```python
    for w in [0.0, 0.25, 0.5, 0.75, 1.0]:
        cv = (1 - w) * c_a + w * c_b
        f = model.cond_field(cv, t_coord, s_coord)
        fs.append(f)
        print(f"  w={w:.2f}  场均值={f.mean().item():+.5f}  absmax={f.abs().max().item():.5f}")
for i in range(1, 5):
    d = (fs[i] - fs[i-1]).abs().mean().item()
    print(f"    w={i*0.25:.2f} 与 w={(i-1)*0.25:.2f} 的差 = {d:.6f}")

ab = (fb - fa).abs().mean().item()
step_d = [(fs[i] - fs[i-1]).abs().mean().item() for i in range(1, 5)]
even = all(abs(step_d[i] - step_d[0]) < 0.6 * step_d[0] for i in range(1, 4))
if even and max(step_d) < ab:
    print("  → 插值路径平滑、且位于两个真实条件之间：学到的是**连续映射**...")
else:
    print("  → 插值不平滑，映射可能是有限查表 ✗")
```

双判据：
1. **even**：逐步差异均匀（每步差与第一步差相差 <60%）；
2. **max(step_d) < ab**：插值的总跨度小于两个真实条件的场差（插值路径「位于两者之间」而不是冲出去）。

### 5.2 `diag_grid_source.py`（123 行，同样 4 份副本）

```python
def decode_from_spec(spec, shape):
    rec = torch.fft.irfft2(spec, s=(WIN, PATCH*PATCH*3), dim=(-2,-1)).real * NORM
    rec = rec.clamp(-1.2, 1.2)        # ★ clamp 上界 1.2 不是 1.0
```

Sobel 用 `np.roll` 实现（无 cv2 依赖）：

```python
def sobel(arr):
    k = np.array([[-1,0,1],[-2,0,2],[-1,0,1]], dtype=np.float32)
    for f in arr:
        g = f.mean(axis=2)
        gx = np.zeros_like(g)
        for dy in (-1,0,1):
            for dx in (-1,0,1):
                gx += k[dy+1, dx+1] * np.roll(np.roll(g, dy, 0), dx, 1)
        out.append(np.abs(gx).mean())
```

⚠️ `np.roll` 是**循环边界**（不是 zero-padding），图像左右/上下边缘会互相污染——对 30 帧动画的边缘帧有微小偏差，但 128×128 的边界占比小（1/128），可忽略。

## 7. 脚本层总结论

1. **preencode.py 是工程质量最高的脚本**：三级失败闸（missing 警告/hit=0 致命/成功率<50% 致命）、断点续跑、原子写、进度节流、RSS 监控全部具备，且每个机制都有对应的事故注释。1:24:08 全量 14145 张 0 失败。
2. **推理侧三个脚本（infer/gen_from_trainset/diag_compose）都只用 strict=False 加载**，代码形态演进后旧 ckpt 的加载状态不可知——这是 v4200 「权重与代码不同步」风险的直接来源。
3. **判决性脚本（verify_dmodel_ceiling / diag_grid_source / eval_generalize）在 4 个版本各存一份副本、零输出存档**——最重要的三个实验结论只以注释形式存在。
4. **v3000 的 13 个诊断脚本输出同样零存档**。
5. 全项目共有的小毛病：死参数（`_stats` 的 tag、`CollateFn` 的 device、`n_heads_in`）、硬编码绝对路径（GIF_ROOT 两套定位方式）、`--seconds` 小数截断无警告。
