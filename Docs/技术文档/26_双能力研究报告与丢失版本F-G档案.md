## 第一部分：双能力前期研究报告（v3600 快照读码结论）

### 1.1 报告定位

- **日期**：2026-10-13 00:50；**状态**：纯研究，未改动任何代码；
- **触发**：用户决定"2500 步跑完（不论效果）即开始多数据集全量训练"，目标双能力：
  - 能力 A：图片 + 文字 → GIF；
  - 能力 B：文字 → GIF（纯文本，无需输入图）。

### 1.2 三句话摘要

1. **能力 A 的链路在架构上已经存在**，但当前是「作弊通路」——训练时直接把 target 场喂进漂移场，等于开卷考试。要变成真能力必须换成**可学习的图像编码器**；
2. **能力 B 缺一个关键模块**：模型没有「无 target 时的自持吸引子」。`DriftField.prototypes` 只有 16 个固定向量，与文本无绑定；
3. **两者不是两个模型，是同一模型的两个条件入口**——一次训练、两个推理模式，共享全部物理核参数。

### 1.3 现状盘点：三个条件入口（aether_gif_model.py forward）

| 通路 | 入口 | 现状 | 影响能力 |
|---|---|---|---|
| **文本** | `texts` → omega_bias_head / drift_target_head / kappa_scale_head / T_scale_head | `use_qwen=False` 时走 `self.text_param`（**单个可学习向量 `randn(1,896)*0.02`**） | 只影响 ω/κ/T 三个全局标量或逐通道偏置，**不携带内容信息** |
| **图像** | `target_field` → PhysicsBlock.forward(targets=...) → DriftField.forward(targets) | 训练时传真 target | **唯一携带像素信息的通路，但它是真值泄漏** |
| **噪声起点** | `a0`/`theta0` 随机采样 | `a0 = exp(randn*0.8-2.5)` | 起点随机，ω 确定性（记忆铁律：ω 每次前向重采样 = 每次换动力系统，无法学习） |

### 1.4 ★ 关键发现：训练时是「开卷考试」

```python
# aether_gif_model.py:211
a, theta, d = self.pmnncore.blocks[i](
    a, theta, omega, t_coord, s_coord,
    kappa=tf["kappa"] * kappa, T=tf["T"] * T,
    omega_d=tf["omega_d"],
    targets=target_field,      # ← 训练时把答案直接给漂移场
)
```

`DriftField.forward` 拿到 `targets` 后做两件事（`drift_field.py:224-232`）：
1. `tar = targets` 当吸引中心（`_attract_phase` 相位空间吸引）；
2. `theta_tar = atan2(im_t, re_t)` 取目标相位，算 `sin(θ_tar - θ_i)` 逐点精确吸引。

**这意味着**：
- 当时测出的任何"还原度"都不代表模型能力，因为模型**看到了答案**；
- `profile_cos` 0.996、`wcos` 0.998 衡量的是「物理核能把给定目标场演化多好」，**不是「模型能不能从零生成出这个场」**；
- 这也解释了为什么两天来画质一直修不好——**瓶颈从来不在模型侧，而在"模型根本没在学生成"**。

> ⚠️ 报告原文要求：**这条要写进后续所有验收报告**——单样本过拟合的指标 ≠ 生成能力指标，两者必须分开报。

### 1.5 `use_qwen=False` 的真相

```python
# aether_gif_model.py:106
self.text_param = nn.Parameter(torch.randn(1, self.text_dim, device=device) * 0.02)
```
- `text_dim = 896` 硬编码，恰好与 Qwen2.5-0.5B hidden_size=896 一致；
- `text_param` 形状 `[1, 896]`，forward 里 `.expand(len(texts), -1)`；
- **所有样本共享同一个向量，且与文本内容完全无关**——传 `"台球"` 还是 `"hatched"`，进入模型的向量一模一样。

**结论**：截至该报告时点，过去 2500 步的训练**文本通路等于不存在**，`texts=["台球"]` 从头到尾没有产生任何有效作用。

### 1.6 推理路径 generate() 是死代码

`aether_gif_model.py:238-304`，这条路径**从未被真正验证过**：
- 调 `self.qwen.encode([text])`——但 `use_qwen=False` 时 `self.qwen = None`，**直接 AttributeError**；
- 内部 `targets=None` → 漂移场退化到 `self.prototypes`（16 个 `[n_prototypes, 2D]` 随机向量）；
- `_field_to_frames` 里 `grid = int(round((N/T_step)**0.5))` 反推网格，`time_step=5` 与训练 `WIN=5` **恰好一致但是巧合不是设计**（默认值与 codec 无耦合）。

**结论（报告原文）**：`generate()` 是一条死代码，**需要重写而不是修补**。（v4200 后续确实重写了 `generate()`，见 21/22 号文档。）

### 1.7 能力 A 的候选图像编码器（按本机可行性排序）

| 方案 | 显存 | 可行性 | 备注 |
|---|---|---|---|
| 复用 Qwen 的视觉塔 | Qwen2.5-0.5B 是纯文本模型，**无视觉塔** | ❌ | 别考虑 |
| SigLIP/CLIP ViT-B/16 | ~0.4 GB (fp16) | ✅ 需下载 | 输出 512 维，与 text_dim=896 不同，需投影层 |
| 冻结 Qwen 隐状态做图像编码 | 0 | ⚠️ 折中 | 把图像 patch 序列当"句子"喂进去，零额外显存但非预训练视觉特征 |
| **复用现有 codec 反向** | 0 | ✅ **零成本，先试这个** | 参考图 → `encode_gif_to_field` 单帧 → `[N,2D]` 场，**与推理时物理场同构，天然对齐** |

**报告的建议路线**：第一个难关走"复用 codec"——零额外参数、零额外显存、编码空间与漂移场输入完全同构，逻辑自洽（"图和 GIF 是同一种物理场的两种来源"）。

**实际演进**：v4200 最终选了 **jina-clip-v2 图文双塔**（视觉塔 EVA-02 304M 上 GPU fp16 + 文本塔 XLM-R 561M 留 CPU fp32），不是本表任何一项——CLIP 路线是用户 2026-10-13 晚拍板（"试试这个双塔代替原 Qwen 模型"），本报告的候选表未包含它。**这是计划与实际的偏离，记录备查。**

### 1.8 能力 B 的三个根本缺口

**缺口 1：没有「文本→吸引子」的通路**。`DriftField` 只有 `targets`（训练真值）和 `self.prototypes`（16 个固定 `[2D]` 向量，与文本无绑定）。需要：
```
text --[Qwen]--> text_emb [896] --[映射]--> dynamic_prototype [2D] --> DriftField 吸引中心
```

**缺口 2：起点噪声无语义**。`a0 = exp(randn*0.8-2.5)` 纯随机。要做条件生成，起点应由文本调制统计特性（a0 随机合法——它是初始状态不是动力系统；ω 必须确定性才是铁律）。

**缺口 3：无 target 时漂移场的梯度**。`self.prototypes` 是 nn.Parameter 梯度能回传，但 `use_checkpoint` 分支（`drift_field.py:235`）训练时启用检查点、推理 `torch.no_grad()` 不走，两者数值行为需验证一致。

### 1.9 ★ 结构性矛盾：必须打破"必须有 target"铁律

记忆铁律「漂移场是唯一把 target 送进相位演化的通路」「两者缺一就死」与能力 B（无 target）直接冲突。报告指出：**这不是新增功能，是把「target 直连」换成「target 或文本原型」二选一或多路融合**。物理上漂移场需要一个吸引子，来源可以是图像编码（A）/文本映射（B）/推理时由输入条件决定。

**实际演进**：v4200 的解法是 `CondFieldPredictor`——条件→27 驻波基混合预测场，`use_cond_field=True` 时用预测场当吸引中心（见 09/19/21 号文档）。这条路比报告的"文本→动态原型"重得多（2,273,239 参数 vs 一个小 MLP），且引入了新问题（条件未分化，见 20 号文档 §4.1）。

### 1.10 难关拆解（六关，严格按依赖排序）

```
难关0 评测口径切开  ← 不做这个，后面全是盲飞
  ↓
难关1 修通 use_qwen=True 文本通路  ← 能力 B 的前提
  ↓
难关2 文本→动态原型  ← 能力 B 最小闭环
  ↓
难关3 图像编码器接入  ← 能力 A 真通路（可与2并行）
  ↓
难关4 多数据集训练管线  ← 需要 0/1/2/3 都在
  ↓
难关5 两能力联合训练与评测  ← 最终验收关口
```

**各关验证判据（报告原文）**：

| 关 | 判据 | v4200 实际状态 |
|---|---|---|
| 0 | 生成图不能是常量/纯噪声/过曝二值；逐帧 std 不能全塌；帧差与素材同量级；**不同文本生成的图必须可区分** | `eval_generalize.py` 已写未跑；可区分度即"条件分化"，**未达标**（见 20 号文档 §4.1） |
| 1 | 同一批训练中 omega_bias_head 对不同文本产出不同 ω；text_embs 方差在 batch 维非零；**先测 Qwen embedding 同质化风险**（cosine 全在 0.95+ 则要换 pooling 或换编码器） | 实际换成了 jina-clip-v2 双塔 + 离线预编码（text_emb.npy 204×1024）。**同质化风险未测**——预编码只验证了 14145/14145 成功，没验证文本两两余弦分布 |
| 2 | 固定 seed，5 个不同文本跑推理，输出两两必须有可测差异（像素 L2 > 阈值或 Sobel 场相关性 < 0.9）；**几乎一样 → 先查梯度回传，别急着加容量** | cond_field 混合权重跨基 std 0.00121（均匀基线 0.03634）、场差 5.7e-06——**正是报告预言的失败模式，且排查顺序（to_chan 零初始化/梯度回传/lr 分组）与报告判据一致** |
| 3 | targets 换成图像编码后 profile_cos 必然大幅下降（不再有真值捷径）——**这是预期行为不是坏事**；参考图建议用**另一张无关图**（防退化成帧插值）；必须配 text dropout（双能力共享关键技巧，类似 classifier-free guidance） | v4200 的 mix 模式 1/3:1/3:1/3 采样 = text dropout 的变体（文生/图生/图文各 1/3）。**实际采样分布未核对**（无运行日志） |
| 4 | holdout 按**番剧**划分而非按 GIF（防同番剧表情泄漏）；batch>1 时 DriftField `[B,N,N]` 显存成倍——先测 batch=2 | v4200 验证集按 **group** 划分（204 group，8%≈16 group，种子 1234，无泄漏已验证：`[SPLIT] 验证集独占 16 个 group，与训练集 group 重叠 0 个`）。batch 实测=1（见 25 号文档 §2.1） |
| 5 | 模式 A 输出与参考图同风格；模式 B 不同文本产出可区分 GIF（内容可糙不能千篇一律）；**两模式共用同一份物理核参数** | 未到达（全量训练从未启动） |

### 1.11 报告的风险清单与"核心设计约束"

风险清单（7 项）：Qwen embedding 同质化 / 图像编码退化成帧插值 / 两模式互相干扰 / DriftField [B,N,N] 显存爆 / holdout 泄漏 / 旧指标误导 / 改架构推翻 D=125 成果。

**核心设计约束（报告原文）**：
> 所有改造只动「条件入口」，物理核（PMNNCore / DriftField 动力学 / Kuramoto / StandingWaveFFN / TimeField / Thermodynamics）一行不改。D=125 已经把画质天花板抬到 49.82 dB（网格比 1.373→1.172），这个成果不能因为要做双能力而丢掉。

（注：49.82 dB 与 1.172 是 v3600 快照口径；v3700 复测全保留 125 系数为 PSNR 147.20 dB、网格比 1.062，见 17 号文档——两个数都记录，口径不同。）

### 2.2 方案 F 差异记录（第九、十死穴修复版）

**参数量指纹**：约 1,134,966（共享 μ 去重后）——与方案 H 相同，因为架构层面 F 和 H 只在**递推域**不同（F 是 log 域，H 是 log1p 域）。

**已知架构差异（相对方案 D）**：
1. `a_gamma` 拆成两个冻结常量 `a_gamma_lvl=0.5`（层级）+ `a_gamma_shape=0.1`（形状）；
2. 残差零均值 `res = res - res.mean(dim=1)`；
3. 层级递推 `m_new = m + γ_lvl·(μ − m)`、形状递推 `δ_new = (1−γ_shape)·δ + res`；
4. μ 在 block 间共享，顶层 `PMNNCore.a_mu`（初值 log(0.05)=−3.0）；
5. 递推域仍是 **log 域**。

**loss 差异**：`loss_amp = (log(a) - log(a_tar))^2.mean()`，纯 log 域相对误差。分组 lr：`a_mu ×100`。

**结果**：150 步验证 profile_cos 0.186→0.972、谱跨 1x→98x；1000 步 profile_cos=0.994、谱跨 638x，但频段比整体偏高 1.4×、frame-diff 11.21 反升（μ lr×100 震荡，日志末段 `谱跨 522↔909`）。

**为何丢失**：F 是"架构修复对了、但 loss 换 log 域 + μ lr×100 引入震荡"的中间态，随后被方案 G 替换。

### 2.3 方案 G 差异记录（第十二死穴前置）

**参数量指纹**：约 1,134,966。

**已知 loss 差异（相对 F）**：
```python
# 方案 G：log 域 + 软截断，不加幅度权重
EPS_A = 0.01
la = torch.log(a.clamp(min=EPS_A))
lt = torch.log(a_tar.clamp(min=EPS_A))
loss_amp = (la - lt).pow(2).mean()
```
μ lr ×80，1000 步：profile_cos 0.975、谱跨 822x（最接近 target 727x）、frame-diff 5.91。

**结果**：软截断把 62/64 通道的 target 真值钉在 log(0.01)=−4.605——**"屏蔽噪声"变成"屏蔽真值"**，非 DC 通道 μ 系统性偏高 4.1 个 log 单位（第十二死穴）。

**为何丢失**：G 是"发现软截断有害"的过渡态，随后被"去截断纯 log → 最终方案 H log1p"替换。

### 2.4 精确恢复的边界（诚实声明）

| 方案 | 参数量指纹 | block.py | overfit.py loss | 可恢复程度 |
|---|---|---|---|---|
| D（2500 步） | 1,135,658 | ✅ 已快照 | ✅ 已快照 | **完整恢复** |
| F | 1,134,966 | ⚠️ 仅差异描述 | ⚠️ 仅差异描述 | 不可精确恢复（架构同 H，仅递推域为 log） |

**F 的近似重建方法**（原文）：用 v3000 快照的 block.py，把 `L=log1p(...)` 改回 `log_a=log(...)`、`a_new=exp(...)`、μ 初值改 `log(0.05)=−3.0`，loss 改纯 log 无权重 + a_mu 分组 lr×100——即为 F 的近似重建（**非逐字精确**）。

## 3. 两份档案与后续版本的实际映射

| 报告/记录中的设计 | v3700 | v4200 实际 |
|---|---|---|
| 评测口径切开（难关0） | 未做 | eval_generalize.py 已写未跑（20 号文档 §2.1） |
| Qwen 文本通路（难关1） | CLIP 替换 Qwen（用户拍板 jina-clip-v2） | ClipConditionEncoder + 离线预编码 204 条文本 |
| 文本→动态原型（难关2） | ConditionModulator（16 原型，~2.3M） | CondFieldPredictor（27 驻波基，2,273,239） |
| 图像编码接入（难关3） | preencode_clip.py 单样本归一化 bug 修复 | 14145 张首帧预编码 + has_image 标志 |
| 多数据管线（难关4） | 8-ball 单样本 | 14145 GIF / 204 group / group 级 holdout |
| 联合训练（难关5） | test_cond_gen_v1~v4 | mix 模式 1/3:1/3:1/3，全量训练未启动 |

**演进总结**：报告的设计（小 MLP 映射 + codec 复用）在实现时被两次放大——条件编码器从 Qwen 换成 CLIP 双塔、吸引子从线性映射换成 27 基预测场。参数量从 ~3.6M（v3700）涨到 6,134,065（v4200）。报告的核心警告（"条件必须可区分，否则别急着加容量，先查梯度回传"）在 v4200 的卡点上完全应验。
