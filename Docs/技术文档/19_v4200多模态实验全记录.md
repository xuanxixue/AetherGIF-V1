## 1. 目标与架构定位

v4200 的目标（交接文档 §0 原文）：

> 把「只会重建」的物理架构升级成「能按条件组合生成」的内容生成器。核心物理核（PMNNCore）一行未改，只在调用侧加了一条「条件 → 预测场」的直连通路（`src/physics/cond_field.py`）。

### 1.1 架构图（交接文档 §2）

```
GIF → 3D FFT(rfft2, 真实网格 5×25=125) → 复值振子场[B,N,125×2]
  → PMNNCore(12 block 物理演化) → 逆 FFT → GIF
条件入口（v4200 改造）：
  cond_vec[2049] = text_emb[1024] + image_emb[1024] + has_image[1]
  → CondProjector(256→896) → 4 个物理调制头(omega_bias/drift_target/kappa/T)
  → 另有 cond_field(CondFieldPredictor) 直接把条件预测成「吸引中心场」
```

### 1.2 三种生成能力（同一模型三种条件采样）

| 模式 | text_emb | image_emb | has_image | 用途 |
|---|---|---|---|---|
| text | 真实 | 零向量 | 0 | 文生 GIF |
| image | 零向量 | 真实 | 1 | 图生 GIF |
| both | 真实 | 真实 | 1 | 图文生 GIF |
| mix（默认） | 1/3 : 1/3 : 1/3 随机 | — | — | 训练时三种混采 |

### 2.3 预编码脚本自身的坑（代码注释记录，全部实测过）

1. **路径退 3 级 vs 4 级**：曾写成 3 级，指向不存在的 `docx/data/gif_raw`，14145 张全部 `p.exists()` 为 False 被静默 continue，**脚本照样退出码 0**、打印「成功 0/14145」。修复：启动即断言 `GIF_ROOT.is_dir()`，hit=0 或 hit/n<0.5 直接 `SystemExit`。
2. **np.save 自动追加 .npy 后缀**：传 `"x.partial.npy.tmp"` 实际写成 `"x.partial.npy.tmp.npy"`，`os.replace` 找不到文件。临时名必须用 `"..._tmp.npy"`。
3. **断点续跑**：`image_emb.partial.npy` + `image_ok.partial.npy`，每 3 分钟原子写一次（段错误/断电最多损失 3 分钟）。
4. **攒 16 张就刷**：512×512 PIL 图常驻内存会挤占 CLIP 前向空间，攒 64 张时 preencode 段错误（exit 139）。
5. **CLIP 塔级分裂**（`clip_condition.py` `_ensure`）：视觉塔 304M 上 GPU fp16（1.73GB），文本塔 561M 留 CPU fp32（XLM-R 的 LoRA 分支每次前向对整个 250002 词表做 matmul，恒定额外 490MB，fp16 下 4GB 卡装不下）。
6. **不用 trust_remote_code**：transformers 5.x 对动态模块类身份严格校验，会报 `config.text_config is expected to be of type JinaCLIPTextConfig`；且实现文件有相对导入，必须先伪造合成包 `_jina_clip_impl`。
7. **不用 snapshot_download**：Windows 上建符号链接，失败时静默落成 0 字节空壳（du 显示 1.7GB 实际 config.json 是 0 字节）。改用 curl 直下到 `models/jina-clip-v2/`。
8. **image_size 必须是 512**：写 224 触发 eva_model 的 assert `Input image size (224*224) doesn't match model (512*512)`（视觉塔有绝对位置嵌入，不能插值降分辨率）。
9. **归一化常数必须用 CLIP 的** (0.4815,0.4578,0.4082)/(0.2686,0.2613,0.2758)，用 ImageNet 的会让图像塔输出接近噪声。
10. **bs 上限 4**：bs=8 峰值 2.63GB 但单批耗时从 0.83s 暴涨到 14.6s（换页抖动，反而慢 17 倍）。

## 4. 卡点：条件未分化（交接文档 §4，最关键的未完成状态）

### 4.1 问题描述

> 最新代码（`cond_field.py` 当前磁盘版本）做了两步重构，但**没跑完训练验证就中断**：
> 1. **chan_amp 从全局共享改成条件调制**（`to_chan` 层）：原来只有 27 个基权重 w 是条件相关的，chan_amp 全局共享，204 个 group 挤在 27 维里实在分不开。改成 `amp[b,k,c] = chan_amp[k,c] · (1 + tanh(to_chan(cond))[b,k,c]·0.5)`，条件自由度从 27 升到 27×250。
> 2. **supervise() 监督口径去归一化**：第一版做了 `lp/||lp||` 范数归一，把「整体幅度」这个自由度从 loss 里删掉了（而幅度正是 chan_amp 唯一的表达通道），导致 150 步后 chan_amp std=0.02015≈初值 0.02，几乎没动。改成只做**逐位置中心化**（去 DC 偏移），**保留幅度尺度**。

### 4.2 实测数据（全部是短训结果）

| 读数 | 值 | 来源 |
|---|---|---|
| 30 步时 cos 变化 | -0.0005 → +0.9951（相位对齐学了，幅度没学） | 交接文档 §4 |
| 150 步（实际 86 步中断）后条件场差 | **5.7e-06** | 交接文档 §0/§4 |
| 150 步后混合权重跨基 std | **0.00121**（均匀基线 0.03634） | 交接文档 §0 |
| chan_amp std（150 步） | 0.02015（初值 randn×0.02 的 std=0.02） | 交接文档 §4 |
| 40 步时场差（旧版 supervise 前） | 1.7e-06 | 交接文档 §3.C.4 |
| best.pt 里 prototypes std | 0.01963（初值 0.02，一动没动） | cond_prototypes.py docstring |

**解读**：5.7e-06 的场差意味着不同 group 的条件预测场**几乎没有区别**——模型对条件的响应可以忽略。混合权重 std 0.00121 只有均匀基线（0.03634）的 3.3%，即 softmax 权重几乎均匀分布 = 没有选择性。

### 4.3 已踩并修掉的坑（交接文档 §3.E）

1. **早停判据二误停**：batch=1 时 train loss 是单样本测量 vs val 是 48 样本均值，比值天然虚高。`gap_ratio` 从 1.15 提到 3.0。
2. **`update_baseline` 引用未定义变量 `step`**（NameError 死在第 2 步）。已修：显式传 step。
3. **cond_field 早期 scalar gate 梯度被 tanh 压死**（1.3e-08）。**已删 gate 参数**（CondPrototypes 里保留 gate 但 tanh(0)=0 起步；CondFieldPredictor 删了）。
4. **`--gen-weight` 从 2.0 加到 4.0 出现过 NaN**（预测场冲太大→漂移场 softmax 溢出）。**上限卡 2.0**。

### 4.4 交接文档自述的文档矛盾

### 5.3 `scripts/diag_compose.py` —— 区分「记忆还原」与「条件组合生成」的三指标

这是 v4200 最重要的验收脚本（虽然只有 40 步短训权重的输出）。设计：

**指标 1：同条件两次生成是否相同**
- 相同 → 模型在查表/记忆（背下训练样本）
- 不同 → 起点随机 + 条件引导 = 生成（扩散模型同款机制）
- 判据：`rel = d_a / mean|a|`，`rel > 0.02` 判「在生成」

**指标 2：条件空间连续性**
- 两个条件（Lucky-Star vs K-On）按 w∈[0,0.25,0.5,0.75,1.0] 插值，看预测场是否平滑变化
- 判据：逐步差异均匀（`|step_d[i] − step_d[0]| < 0.6·step_d[0]`）且 `max(step_d) < ab`（两个真实条件的场差）
- 平滑 → 学到**连续映射** f(cond)→field，中间条件（训练集没有）也有意义

**指标 3：信息量体检**
```
条件维度 = 2049
场维度   = 6144 × 250 = 1,536,000
压缩比   = 750 : 1
```
脚本原文结论：「单个条件不可能唯一确定一个场。750 倍有损压缩意味着模型学到的必然是**该条件下的典型场（条件期望）**，不是精确复现。」
驻波基压缩：27 个基 → 每基 250 维，可表达上限 27×250=6,750 维（相对场的 1,536,000 维），条件权重 27 维 → 连续插值有无限多种组合——这是组合能力的上限来源。

**状态**：`diag_compose.py` 存在且完整，但**没有任何运行输出存档**（无对应 log 文件）。三指标的实际读数未知。
