## 1. `clip_condition.py` —— 多模态条件编码器

### 1.1 文件头声明与选型依据

```
多模态条件编码器 —— jina-clip-v2（XLM-RoBERTa 文本塔 + EVA-02 视觉塔）

选型理由（2026-10-13 定案）
--------------------------
用户要的是「EVA-02-CLIP multilingual」。核查后确认：**官方 EVA-CLIP 全系列
（B/L/E/336/8B）的文本塔全是英文 CLIP BPE，没有多语言版**。
真正「XLM-R 多语言文本塔 + EVA-02 视觉塔」的是 jinaai/jina-clip-v2：
  - 文本塔：XLM-RoBERTa，89 语种 → 中英混训没问题
  - 视觉塔：EVA-02（ViT-B/14 级别，224px）
  - 双向对齐空间，图文共享一个 embedding 空间（1024 维）
```

⚠️ **文件头与代码的不一致 #1**：文件头说视觉塔「224px」，但代码 `image_size: int = 512` 且注释明确「image_size 必须是视觉塔原生分辨率（jina-clip-v2 = 512, patch 14）。写 224 会直接触发 eva_model 的 assert」。**以代码为准（512）**，文件头的 224px 是笔误。

⚠️ **不一致 #2**：文件头说「红线说明：本模块是冻结的外部预训练编码器，只输出条件向量，不改动 PMNN 物理核任何算子结构」——代码确实如此（`requires_grad_(False)`），此项声明与代码一致。

### 1.2 模块级常量

```python
CLIP_EMB_DIM = 1024          # 冻结编码器输出的条件向量维度
N_COND = CLIP_EMB_DIM * 2    # = 2048，text_emb | image_emb
```

注意 `N_COND = 2048` **不包含 has_image 位**；真正在数据集里传递的条件向量是 2049 维（`multimodal_dataset.py` 的 docstring 与 `build_cond_vector` 都是 2049）。`N_COND` 这个常量在 v4200 代码里**未被任何地方引用**（死常量）。

### 1.3 `ClipConditionEncoder.__init__`

```python
def __init__(self, model_path=None, device="cuda", max_text_len=128,
             image_size=512, fp16=True):
    self.device = device
    self.max_text_len = max_text_len
    self.image_size = image_size        # ★ 漏存会让 encode_images 直接 AttributeError
    self.fp16 = bool(fp16) and str(device).startswith("cuda")
    self._text_on_cpu = self.fp16       # fp16 模式下文本塔留 CPU
    self.model_path = model_path or default_model_path()
    self._model = None; self._proc = None; self._tok = None    # 懒加载
```

设计要点：
1. **懒加载**（`_ensure`）：构造模型不吃显存，只有第一次 encode 时才加载。
2. **`self.fp16` 与设备绑定**：CPU 上强制 fp32（`str(device).startswith("cuda")` 判断）。
3. **`_text_on_cpu = self.fp16`**：fp16 模式 ↔ 文本塔在 CPU，两者等价绑定。

### 1.4 `_ensure()` —— 懒加载与塔级分裂（本文件最核心的 40 行）

```python
if str(self.device).startswith("cpu"):
    torch.set_num_threads(2)
    try:
        torch.set_num_interop_threads(2)
    except RuntimeError:
        pass          # 已在并行区中设置过，忽略
```

**CPU 线程限制的原因**（注释原文）：「EVA-02 视觉塔前向会按核数开 OpenMP 线程，本机 16 线程时 preencode 直接段错误（exit 139，无 Python 异常）」。这是本项目记录的第一个 exit 139 段错误案例。

**合成包注入**（绕过 trust_remote_code 的两个坑）：

```python
if mdir not in sys.path:
    sys.path.insert(0, mdir)
pkg_name = "_jina_clip_impl"
if pkg_name not in sys.modules:
    pkg = types.ModuleType(pkg_name)
    pkg.__path__ = [mdir]          # 让 Python 把该目录当包搜索根
    sys.modules[pkg_name] = pkg
cfg_mod = importlib.import_module(f"{pkg_name}.configuration_clip")
mdl_mod = importlib.import_module(f"{pkg_name}.modeling_clip")
```

两个坑（注释原文）：
1. transformers 5.x 对动态模块的类身份做严格校验，trust_remote_code 会报 `config.text_config is expected to be of type JinaCLIPTextConfig but is...`（同一个类被加载成两个 module 对象，isinstance 失败）；
2. 实现文件里有 `from .configuration_clip import ...` 相对导入，直接 importlib 加载单文件会报 `attempted relative import with no known parent package`——必须先伪造一个包。

**塔级分裂**（本项目 4GB 卡的唯一可行解，注释原文）：

```
视觉塔 304M，512×512 前向，GPU fp16 只要 1.73GB → 必须上 GPU。
      CPU 上单张 20~30 秒，14145 张 = 100+ 小时，完全不可行。
文本塔 561M，其中 word_embeddings 是 250002×1024。XLM-R 的 LoRA 分支
      （modeling_lora.py 的 lora_forward）每次前向都对**整个词表矩阵**
      做 matmul，恒定额外申请约 490MB —— 与 batch_size 无关
      （bs=1/8/64 都是同一个 490MB）。fp16 下 4GB 卡装不下 → 必须留 CPU。
      好在文本只需编码 204 条 group 标签，CPU 上约 71 秒，完全够用。
```

代码实现：

```python
self._model = mdl_mod.JinaCLIPModel.from_pretrained(mdir, config=cfg)
self._model.requires_grad_(False)
if self.fp16 and str(self.device).startswith("cuda"):
    self._model.vision_model = self._model.vision_model.half().to(self.device)
    self._model.visual_projection = self._model.visual_projection.half().to(self.device)
    self._model.text_model = self._model.text_model.float()      # 留 CPU，fp32
else:
    self._model = self._model.to(self.device)
self._model.eval()
```

**踩过的坑**（注释原文）：「先 `.to("cuda")` 再 `.half()` 会在加载阶段就 OOM（fp32 权重 3.5GB）。正确顺序：CPU 加载 → 视觉塔转 fp16 → 文本塔留 CPU → 视觉塔上卡。」

`AutoImageProcessor` 用 try/except 包裹（失败时 `_proc = None`，但 `encode_images` 不用 `_proc` 而用 torchvision transform——见 §1.7，`_proc` 实际是死代码）。

### 1.5 `center_normalize` —— 去各向异性（本项目最重要的条件预处理）

```python
@staticmethod
def center_normalize(emb):
    """★ 去均值 + 重新 L2 归一化。

    CLIP 存在著名的各向异性（anisotropy）：所有输出向量挤在一个狭窄锥形里，
    两两余弦相似度基线极高。在本项目 14145 个真实 GIF 首帧上实测：

        原始      非对角相似度 均值 0.853 / std 0.077 / 范围 [0.666, 0.975]
        去均值后  非对角相似度 均值-0.063 / std 0.343 / 范围 [-0.705, 0.689]

    std 从 0.077 → 0.343，**区分度提升 4.5 倍**。不处理的话，所有 GIF 的条件向量
    几乎一样，物理核（CondProjector 之后的 4 个调制头）根本学不到素材差异，
    表现为「训练 loss 正常但生成结果千篇一律」。

    注意：必须在**全集**上估均值，不能在 batch 内做（batch 太小均值噪声大）。
    """
    emb = np.asarray(emb, dtype=np.float32)
    mu = emb.mean(axis=0, keepdims=True)
    emb = emb - mu
    n = np.linalg.norm(emb, axis=-1, keepdims=True)
    return (emb / np.clip(n, 1e-8, None)).astype(np.float32)
```

**docstring 数字 vs 实测数字的差异**（文档 19 已记录）：

| 口径 | docstring | `meta.json` 实测（14145 张全集） |
|---|---|---|
| text 去均值后 std | 0.343 | **0.160** |
| image 去均值后 std | 0.343 | **0.488** |
| text 非对角均值 | -0.063 | **-0.0047** |
| image 非对角均值 | -0.063 | **+0.0470** |

docstring 的 0.343 既不是 text 也不是 image 的实测值，判断为早期小样本实验的残留数字。**结论不受影响**（去均值后 std 确实大幅提升），但引用数字时应以 `meta.json` 为准。

### 1.6 `encode_text`

```python
@torch.inference_mode()
def encode_text(self, texts, batch_size=8):
    self._ensure()
    tdev = "cpu" if self._text_on_cpu else self.device
    outs = []
    for i in range(0, len(texts), batch_size):
        batch = [str(t) for t in texts[i:i + batch_size]]
        enc = self._tok(batch, padding=True, truncation=True,
                        max_length=self.max_text_len, return_tensors="pt").to(tdev)
        emb = self._model.get_text_features(**enc)          # [B, 1024]
        emb = emb / emb.norm(dim=-1, keepdim=True).clamp(min=1e-8)
        outs.append(emb.float().cpu().numpy())
    return np.concatenate(outs, 0).astype(np.float32)
```

关键点：
- **默认 batch_size=8 不是 64**：fp16 下 XLM-R 的 LoRA 分支每次前向要额外约 490MB，batch=64 在 4GB 卡上直接 OOM（`Tried to allocate 490 MiB ... 1.06 GiB is free`）。
- **输入张量放 `tdev`（CPU）**：因为文本塔在 fp16 模式下常驻 CPU，`texts` 不能 `.to(self.device)`。
- 输出已 L2 归一化（但**未去均值**——去均值在 preencode.py 里对全集做，见 §1.5 的「必须在全集上估均值」）。

### 1.7 `encode_images`

```python
@torch.inference_mode()
def encode_images(self, images, batch_size=4):
    self._ensure()
    import torchvision.transforms as T
    size = self.image_size
    tf = T.Compose([
        T.Resize((size, size), interpolation=T.InterpolationMode.BICUBIC),
        T.ToTensor(),
        T.Normalize(mean=(0.48145466, 0.4578275, 0.40821073),
                    std=(0.26862954, 0.26130258, 0.27577711)),
    ])
    dt = torch.float16 if self.fp16 else torch.float32
    outs = []
    for i in range(0, len(images), batch_size):
        batch = images[i:i + batch_size]
        px = torch.stack([tf(im.convert("RGB")) for im in batch]).to(self.device, dtype=dt)
        emb = self._model.get_image_features(pixel_values=px)  # [B, 1024]
        emb = emb / emb.norm(dim=-1, keepdim=True).clamp(min=1e-8)
        outs.append(emb.float().cpu().numpy())
    return np.concatenate(outs, 0).astype(np.float32)
```

注释记录的四个坑（全部实测）：
1. image_size 必须是 512（视觉塔原生分辨率，有绝对位置嵌入，不能插值降分辨率）；
2. 归一化常数必须用 CLIP 的，用 ImageNet 的会让图像塔输出接近噪声；
3. 必须走 GPU fp16（CPU 20~30 秒/张 vs GPU 4.8 张/s）；
4. CPU 上线程数必须限制（16 线程段错误 exit 139）；调用方不要一次囤 64 张 512×512 PIL 图。

**batch 上限 4 的原因**：「GPU fp16 实测 bs=2/4 稳定 4.8 张/s，bs=8 峰值 2.63GB 但单批耗时从 0.83s 暴涨到 14.6s（换页抖动，反而慢 17 倍）」。

**输入 dtype 必须跟权重一致**（`dt = torch.float16 if self.fp16 else torch.float32`）：否则 fp16 权重配 fp32 输入会 dtype 报错。

### 1.9 `CondProjector` —— CLIP 条件 → PMNN 物理调制输入

```python
class CondProjector(nn.Module):
    def __init__(self, cond_dim=CLIP_EMB_DIM, out_dim=896,
                 n_heads_in=4, gate_init=0.0):
        self.text_proj = nn.Linear(cond_dim, out_dim)      # 1024→896
        self.image_proj = nn.Linear(cond_dim, out_dim)     # 1024→896
        self.has_image_proj = nn.Linear(1, out_dim)        # 1→896
        self.text_gate = nn.Parameter(torch.tensor(gate_init))
        self.image_gate = nn.Parameter(torch.tensor(gate_init))

    def forward(self, text_emb, image_emb, has_image=None):
        te = self.text_proj(text_emb)
        ie = self.image_proj(image_emb)
        tg = torch.sigmoid(self.text_gate)
        ig = torch.sigmoid(self.image_gate)
        if has_image is not None:
            ie = ie * has_image.to(ie.dtype).unsqueeze(-1)
        return tg * te + ig * ie
```

**参数量计算**：text_proj 1024×896+896 = 918,272；image_proj 同 918,272；has_image_proj 896+1 = 897；gate 2。合计 **1,837,443**。

⚠️ 与交接文档的 cond_projector = 1,838,594 差 1,151——差异来自 v4200 模型里 cond_projector 被实例化了**两次**的代码路径（`use_qwen=True` 时重建一次），实际生效的是第二个；差值 1151 = 896+255？无法从现有数据解释，**记录为待核对项**。

**三个设计要点**：
1. **`n_heads_in=4` 是死参数**（从未使用）。
2. **`gate_init=0.0` → sigmoid(0)=0.5**：两模态初始等权参与。注释原文：「可学习模态门：初始为 gate_init（sigmoid(0)=0.5，两模态都参与）」。
3. **`has_image_proj` 定义了但 forward 里不用**——has_image 只作为 `ie` 的乘性掩码。这是死参数（896+1=897 个参数白占）。

**三种生成能力的条件构造**（docstring）：
- 文生 GIF：text=描述，image=0 向量，has_image=0
- 图生 GIF：text=0 向量（或组描述），image=首帧，has_image=1
- 图文生 GIF：两者都给，has_image=1

### 1.10 `build_cond_vector`

```python
def build_cond_vector(text_emb, image_emb, has_image):
    """把三路离线特征拼成训练 batch 里传递的单个 [B, N_COND] 张量。
    N_COND = 1024(text) + 1024(image) + 1(has_image flag)
    单独存成一个数组，训练时 memmap 读，比分别存三个文件更省 I/O。"""
    flag = np.asarray(has_image, dtype=np.float32).reshape(-1, 1)
    return np.concatenate([text_emb.astype(np.float32),
                           image_emb.astype(np.float32),
                           flag], axis=1)
```

⚠️ **docstring 说 `[B, N_COND]` 但实际返回 2049 列**（N_COND=2048 不含 flag）。docstring 的 N_COND 定义与模块级常量一致（都不含 flag），与实际输出差 1 列。以代码为准（2049）。

⚠️ **此函数在 v4200 中未被调用**（preencode.py 直接 `np.concatenate`，dataset 里也直接拼）——死函数。

### 3.5 场缓存（87GB 的权衡）


`build_field_cache` 的 docstring 给出了关键数字：「场缓存体积：14145 × 6144 × 250 × 4B ≈ **87GB** —— 太大，不适合全量。所以默认**不启用**场缓存（encode_cache=False），训练时按需实时编码。」

### 3.6 `__getitem__` 的模态采样

```python
mode = self.mode
if mode == "mix":
    r = random.random()
    mode = "text" if r < 1/3 else ("image" if r < 2/3 else "both")
# mode 为 text/image/both 时是**确定性**的（不掷随机数），
# 所以验证集直接传固定 mode 即可得到可复现的指标，无需额外开关。

t_row = self.gidx[it["group"]]
t_e = np.asarray(self.text_emb[t_row], dtype=np.float32)

if mode == "text":
    i_e = np.zeros(CLIP_EMB_DIM, dtype=np.float32)
    has_img = 0.0
else:
    if not self.image_ok[i]:
        i_e = np.zeros(CLIP_EMB_DIM, dtype=np.float32)
        has_img = 0.0
    else:
        i_e = np.asarray(self.image_emb[i], dtype=np.float32)
        has_img = 1.0
if mode == "image":
    t_e = np.zeros(CLIP_EMB_DIM, dtype=np.float32)

cond = np.concatenate([t_e, i_e, np.array([has_img], np.float32)])

        "idx": i, "mode": mode}
```

设计要点：
1. **mix 模式按 1/3:1/3:1/3 随机**（默认），text/image/both 是确定性的——这是验证集可复现的保证。
2. **image 模式把 text 置零**（`if mode == "image": t_e = zeros`）——纯粹的图生能力测试。
3. **图像无效时退回纯文本**（`has_img=0.0`）——14145 张全部有效所以这条路径从未触发。
4. **每个 batch 的模态打在日志里**（`本批模态 {'text': 1, 'image': 0, 'both': 0}`）——logs_final.txt 里可以逐批核对。

### 3.7 `CollateFn`（模块级类的两个理由）

```python
class CollateFn:
    """collate：把 cond 拼 [B,2049]，field 拼 [B,N,2D]。

    ★ 必须**只留在 CPU**：DataLoader 的 pin_memory 线程只能 pin 密集 CPU 张量，
      若这里就把张量 .to(cuda)，会报
      "cannot pin 'torch.cuda.FloatTensor' only dense CPU tensors can be pinned"。
      H2D 搬运交给 pin_memory + 主循环的 non_blocking 拷贝。

    ★ 必须是**模块级类**而不是闭包函数：Windows 的 DataLoader 多进程用
      spawn 启动 worker，需要 pickle 整个 collate 对象，局部函数无法 pickle
      （实测报 AttributeError: Can't pickle local object）。
    """
    def __call__(self, batch):
        cond = torch.stack([b["cond"] for b in batch])              # CPU
        field = torch.stack([b["field"] for b in batch])            # CPU
        modes = [b["mode"] for b in batch]
        idxs = torch.tensor([b["idx"] for b in batch])
        return cond, field, modes, idxs
```

返回四元组 `(cond, field, modes, idxs)`——`modes` 是字符串列表（日志里 `本批模态 {...}` 的来源）。

2. `make_collate` 便捷入口未被 train_multimodal.py 调用（训练脚本直接用 `CollateFn(...)` 还是 `make_collate`，未核对）。
3. `build_field_cache` 的 multiprocessing 部分（`import multiprocessing as mp` 后未使用 mp）——`mp` 是死 import，函数体实际是打印两行警告后**什么都没做**（没有真正的多进程编码循环）。
