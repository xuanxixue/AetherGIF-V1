# AetherGIF-V1 技术架构文档

> 版本：2026-10-25　｜　对应代码：`src/`（v4200 多模态条件版）
> 本文所有数字均来自本仓库实测日志，非估算。

---

## 1. 项目定位

AetherGIF 是一个**非 Transformer** 的视频（GIF）生成架构，用**物理动力学**替代注意力机制：

- **表征**：把视频编码成时空频域场（相位 + 振幅）
- **生成**：让振子场在 Kuramoto 同步 + 振幅演化下迭代 12 层
- **解码**：逆 FFT 还原为帧序列

**核心差异**：主流方案（Diffusion / 自回归）用几十步去噪或逐 token 预测；本架构**一次前向输出全部 30 帧**，因为时间轴被编码进了频率维度。

## 2. 数据流全貌

```
GIF (30帧 × 128×128)
   │  ① 分块 + 3D-FFT
   ▼
频域场 [N=6144, D=125 复系数]
   │  N = 6 时间帧 × 32 × 32 空间块；D = 5 时间频段 × 25 空间频点
   │  （每块 4×4×3=48 维 → RFFT 取 25 个频点 × 5 个时间抽样 = 125）
   ▼
初始态 (a₀ 振幅, θ₀ 相位) ←── CondInitPC ←── 三路条件向量 [1, 6147]
   │
   │  ② 12 层 PhysicsBlock 递推
   │     每层：Kuramoto 相位同步 + 振幅 log 域乘性演化 + 漂移场引导
   ▼
终态 (a, θ)
   │  ③ 逆 FFT（含窗函数，必须在 (0,0) 处 = 1.0）
   ▼
帧序列 → GIF
```

**关键量纲**：
| 符号 | 含义 | 取值 |
|---|---|---|
| `TS` | 时间步 | 6 |
| `GRID` | 空间网格 | 32×32 |
| `PATCH` | 块大小 | 4 |
| `WIN` | 每时间步帧数 | 5 |
| `IMG` | 分辨率 | 128 |
| `D` | 频域系数维度 | 125 |

## 3. 核心模块

### 3.1 Codec（`src/codec/gif_codec.py`）

| 函数 | 作用 | 实测指标 |
|---|---|---|
| `encode_gif_to_field` | GIF → 频域场 | — |
| `decode_field_to_frames` | 频域场 → 帧 | **往返 PSNR 49.82 dB**（D=125 全保留） |
| `load_gif_frames` | 读 GIF | 必须**逐帧 seek 后再 convert**，否则压成单帧 |

**重要**：这 49.82 dB 是**未压缩浮点表征**的精度，不是压缩率优势。
实测频域场体积是原始像素的 **4.17 倍**（float32）/ 2.08 倍（float16），
**RD 曲线上远不如 x264**（x264 用 8KB 达到 46.3 dB，本表征用 6000KB 才 52 dB）。
→ **本项目不以「高保真编码」为卖点**，价值在「可演化的场」。

### 3.2 物理核（`src/physics/block.py`）

`PMNNCore` 串联 12 个 `PhysicsBlock`，每块做三件事：

**① 相位演化（Kuramoto）**
```
θ_new = θ + κ·g(θ) + res
```
- `κ` 由 `TimeField` 逐层给出（深块能到 ~15.85），必须 clamp 有效值（`KAPPA_MAX`）
- `res` 是残差，经 `RES_LIMIT` 限幅：`res = RES_LIMIT·tanh(log_res/RES_LIMIT)`

**② 振幅演化（log 域乘性）**
```python
log_a_new = log_a + res - a_gamma * (log_a - μ)
```
- `a_gamma` 可学习（初值 0.3，实测学到 0.04~0.5）
- `μ = a_mu + mu_bias`，**这一行是整个项目的关键**（见 §4）

**③ 漂移场引导**
- 把 target 信息送进相位演化（正磁场不带 target 信息，缺了就死）
- 必须在**相位空间**定义（不是在振幅空间）

### 3.3 条件通路（`src/physics/cond_init_pc.py` + `src/data/clip_condition.py`）

**三路条件向量**（`build_cond_vector3`，共 6147 维）：

| 路 | 来源 | 维度 | 训练组合中的 `has` |
|---|---|---|---|
| 文本 | Qwen3-VL-Embedding-2B | 2048 | (1,0,0) 文生 |
| 首帧 | 同模型图像编码 | 2048 | (0,1,0) 图生 |
| 视频 | 同模型视频编码 | 2048 | (0,0,1) GIF本身 |
| 标志位 | has 三元组 + 拼接 | 3 | (1,1,1) 三路全给 |

**CondInitPC**（条件 → 逐通道初始态）：
```
cond [1,6147] → Linear(6147,512) → SiLU → Linear(512,512) → SiLU → LayerNorm
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
                    ▼                                                   ▼
        to_phase: Linear(512, rank) → Linear(rank, 768000)   to_amp: 同构
                    ▼                                                   ▼
        θ̂ = wrap(pre) 或 arctan(pre)·2                        â = softplus(pre)
```

**rank 是容量的主旋钮**（`COND_PC_RANK`）：

| rank | 总参数 | 备注 |
|---|---|---|
| 8 | 23.04M | 原始版本 |
| 16 | 35.34M | |
| 32 | 59.93M | |
| 64 | **109.12M** | 4GB 显存实测可训（峰值 3695/4096 MiB） |

## 4. ★ 核心问题与根因（本文档最重要的一节）

### 4.1 现象：所有素材生成同一个颜色

| 素材 | 素材 sat | 4 个条件生成 sat |
|---|---|---|
| 8ball | 5.35 | 6.76 / 6.85 / 6.82 / 6.89 |
| senpai | 10.58 | 5.80 / 5.93 / 5.76 / 6.00 |

**生成 sat 锁死在 6.0~6.9，与素材无关、与条件无关。**

### 4.2 根因：μ 是全样本共享的，而 γ 衰减把初值洗掉了

递推式 `log_a_new = log_a + res − a_gamma·(log_a − μ)` 展开 12 层：

```
m_12 = μ + (m_0 − μ)·(1−γ)^12
```

- `γ = 0.3` → `0.7^12 ≈ 0.014`
- `γ = 0.5` → `0.5^12 ≈ 2.4e-4`

**即：条件注入的初值 `m_0` 贡献只剩 1.4%~0.02%，终态层级 ≡ μ。**

而 `μ` 是**单个共享的 `[D]` 向量**（初值 `log(0.2)`），所以所有素材、所有条件都收敛到同一个 μ → 同一个 sat。

### 4.3 三次失败的修复尝试（按顺序）

| 尝试 | 假设 | 结果 |
|---|---|---|
| rank 8→64（23M→109M） | 条件通路容量不足 | ❌ sat 极差 **5.32 → 0.68**（更坍） |
| `ANCHOR_W` 0.3→0.8 | 条件被同步洗掉 | ❌ 相对判据仍 55/55 随机 |
| 逐层诊断 | 条件在中途衰减 | ❌ **L00 极差就只剩 0.25**，进入物理核前就没区别 |

### 4.4 最终定位：条件通路的输出动态范围被「平均化」压扁

在颜色通道（w=16，即 `c%25==16` 的 5 个通道）上：

| | 相位差异 std |
|---|---|
| 模型 `cond_init` 能产生 | **0.658 rad（37.7°）** |
| 真实素材需要 | **1.649 rad（94.5°）** |
| **覆盖率** | **39.9%** |

**loss 是跨样本平均的，模型用 40% 的表达力就能拿到接近最优的平均 loss，所以没有动力学满。**

### 4.5 已实施的两项修复

**① `THETA_PARAM` 参数化可切换**（`cond_init_pc.py`）
```python
# arctan 模式（旧）：θ̂ = arctan(pre)*2，导数 1/(1+pre²)，|pre|>3 时梯度≈0
# linear 模式（新）：θ̂ = wrap(pre)，导数恒为 1
```
**证据**：arctan 版训 300 步后 `to_phase[1] |w|` 只有 0.0131（几乎没动）。

**② `mu_head`：μ 条件调制**（`aether_gif_model.py` + `block.py`）
```python
_mu = a_mu + mu_bias        # mu_bias = MU_SCALE · tanh(mu_head(cond))
log_a_new = log_a + res - a_gamma*(log_a - _mu)
```
**思想：收敛到平衡点是物理性质（不该改），但每个条件应该有自己的平衡点。**

### 4.6 修复效果（2 素材，多轮迭代）

| MU_SCALE | 素材间 sat 差 | L1 达标 |
|---|---|---|
| 0.5 | −0.30（方向错） | 1/8 |
| 2.0 | +1.27（方向对） | 3/8 |
| 6.0 | +1.34（**饱和**） | 4/8 |
| 3.0（接 h） | +0.56（**退步**） | 0/8 |

**教训 1**：MU_SCALE 超过 2.0 后饱和 → head 学到的是「整体偏移」不是「条件差异」。
**教训 2**：`mu_head` 接 `cond_init.proj` 的 `h` 反而更差 —— `LayerNorm` 抹掉了「哪几路有输入」的信息。
**教训 3（判据设计）**：同一素材的 4 个条件输出**相同是正确行为**（它们指向同一目标），
之前误判为坍塌。正确判据是「**同素材内一致 + 跨素材分离**」。

## 7. 运行方式

```bash
# 环境：Python 3.12 + torch 2.5.1+cu121（RTX 3050 4GB 实测）
# 三挂路径（缺一即报错）：
#   sys.path += D:/AetherGIF-V1         # torch_accel_shim
#               D:/AetherGIF-V1/deps312 # 完整 transformers
#               D:/AetherGIF-V1/int8_deps
# from torch_accel_shim import install_full; install_full()  # 必须在 import transformers 之前

# 训练（2 素材，带 mu_head）
N_SRC=2 COND_INIT_PC=1 COND_PC_RANK=8 THETA_PARAM=linear MU_HEAD=1 MU_SCALE=3.0 \
USE_CKPT=1 OPT8BIT=1 DISC_W=8.0 COL_BAND_W=3.0 \
python scripts/train_guided.py 400

# 可视化演示（流式逐层渲染）
python viz/app.py --port 8100 --kind v4200
python viz/app.py --port 8101 --kind v3600
```

**显存纪律**：
- 文本/图像编码器（INT8 Qwen，2444MB）与生成模型（1~2GB）**永不共存**
- 109M 模型需 `USE_CKPT=1`（梯度检查点）+ `OPT8BIT=1`（8bit 优化器）
- **不能用 fp16**：相位是周期量（fp16 分辨率 1e-3 rad）、振幅跨 6 个数量级（高频会下溢成 0）

## 8. 双生态警告（重要）

本仓库存在**两套不兼容的模型代码**：

| | 根 `src/`（方案 D） | `docx/实验记录/versions/v4200_*/src/` |
|---|---|---|
| 参数量 | 1.13M / 2.02M | **23.04M**（rank8） |
| 文本维度 | 896 | **2048** |
| `a_gamma` | 0.5 固定 | 可学习 γ=0.3 |
| 条件初始化 | CondInitModulator | **CondInitPC**（须 `COND_INIT_PC=1 COND_PC_RANK=8`） |

**同进程无法同时加载两套**（顶层包名相同，`sys.path` 先插谁就拿谁）。
漏设 `COND_INIT_PC` 会静默退化成旧 Modulator（10.27M vs 23.04M），且 `RESUME` 会把 `cond_init.*` 当 shape 不匹配**静默跳过** → 条件通路随机初始化。
