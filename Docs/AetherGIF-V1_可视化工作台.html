AetherGIF-V1 可视化工作台

01核心问题：从「重建」到「条件生成」 P0

用户的原话定位：「它既然能够重建，就代表着它能够生成……用条件去重新生成，而不是用 GIF 作为引导去生成。」

生成能力的判决工具：diag_compose 三指标 从未运行

指标 1 · 记忆 or 生成

同条件两次生成是否不同。相同 → 在查表/背下训练样本；不同（rel = d_a/mean|a| > 0.02）→ 起点随机 + 条件引导 = 生成（扩散模型同款机制）。

指标 2 · 条件连续性

两个条件按 w∈[0,0.25,0.5,0.75,1.0] 插值，预测场是否平滑变化。平滑 → 学到连续映射 f(cond)→field，中间条件（训练集没有的）也有意义——这正是用户要的「在见过的里面组合出没见过的」。

指标 3 · 信息量体检

条件维度 2049，场维度 6144×250 = 1,536,000，压缩比 750:1。单个条件不可能唯一确定一个场——模型学到的必然是该条件下的典型场（条件期望）。驻波基 27×250=6,750 维是组合能力上限。

关键口径铁律（违背即出 bug，全部实测过）

通道 ↔ 网格映射

rfft2 真实网格 = 5 × 25 = 125。通道 c ↔ (h = c//25, w = c%25)。分频段必须按 w 切——按 0/16/32/48 均分会混淆 DC 与高频（第十二死穴踩过）。c=0/25/50 是 w=0 列，承载 target 97.2% 能量。h=0 占时间频率能量 79.72%。

量纲一致性

架构递推与 loss 必须同一变换：L=log1p(a) → m=mean_N(L) → m_new=m+γ_lvl(μ−m) → a_new=expm1(L_new.clamp(0,6))。改 loss 变换必须同步改 block.py 递推 + a_mu 初值（log1p(0.05)=0.0488 vs log(0.05)=−3.0，差 3.05 单位）+ μ 的 lr 倍率。判据 |mean_N(log1p(a)) − a_mu| < 0.01。

FFT 系数极重尾

a_tar 中位数 0.0015 / p90 0.18 / p99 5.4；69.4% 系数幅度 < 0.01，其 θ_tar 是纯数值噪声。振幅走 log1p、相位走 a_tar² 功率加权。8-ball 素材 std/mean = 5.750。

硬约束

① 除语言/条件模块外不得出现 Transformer/注意力/FFN；② 禁止注入数据先验（不用 target 谱初始化 μ、不用 set_amp_prior、不用时序中值造伪标签）；③ ω 必须确定性（每次前向重采样 = 每次换动力系统）；④ OU 平衡点必须 per-channel（每通道振幅均值跨 727 倍）。

03五个物理算子 PMNN 核心

物理核共 1,791,292 参数（v4200 与 v2500 方案 D 同代，一行未改）。核心矛盾：耦合结构是零参数结构先验（第二死穴），唯一可训练的是 ω 偏移、κ 缩放与驻波 FFN。

① TimeField 时间场

职责协议曲线 κ(t) 驱动演化深度
默认参数n_blocks=12 · κ_max=16 · t_c=0.3 · τ_c=0.15 · p=1.5 · 16 驱动频率 (0.5~3.0)
参数敏感性从未系统扫描

κ_max 8→16、t_c 0.5→0.3 是 R5「振幅爆炸急救」改的，非系统扫描。零训练时 cos 仅 0.11（指数趋近需 ~300 步深度 vs 只有 12 块）。

② KuramotoSync 相位同步

递推dθ = ω + struct + mf + κ·g
struct/mf零参数结构先验（grad_norm 恒 0）
可训练自由度ω 偏移 + κ 缩放（仅此）

对照 UN-0 架构「耦合矩阵 K 是最主要可学习参数」——AetherGIF 的耦合是零参数先验，这是架构层面核心差距。但「零 Transformer/注意力」硬约束禁止全可学习 K[N,N]，故走物理化路线。相位软饱和：dθ = ω_max·tanh(dθ/ω_max)，ω_max=8.0（Ω_max=2.0 会杀死动画，frame-diff 0.24）。

③ StandingWaveFFN 驻波 FFN

职责共振传递 · 同时改幅度和相位
相位头w2: D→2D 零初始化（R2 修法）
参数γ=0.3 · 4×4 模式 · T_ref=20 · X/Y_ref=32

共振传递函数是复值 |H(ω)|·e^{iφ(ω)}。R2 之前相位 loss 完全不降（drift/kuramoto/time_field 三个 grad_norm = 0.000000）；加相位输出头后 phase loss 首次实质下降 1.87→1.36，wcos 0.43→0.54。

④ DriftField 漂移场

职责唯一把 target 送进相位演化的通路
空间平均上限cos 0.42（R6 实测）
直接吸引cos 0.998
合并后cos 0.42 → 0.82

权重 = 相位余弦距离，力 = sin(θ_j^tar − θ_i)。v2500_D125_谱修复恢复了排斥项 V = V⁺ − λV⁻ 双分量，但其对 cos/PSNR 的贡献无单独消融数据。

⑤ Thermodynamics 热力学

职责（设计）U 能量 / S 熵 / F 自由能正则
实际状态零梯度接入 · 从未参与 loss
前置缺陷amplitude_entropy_channel 沿 N 维 softmax，与注释「每通道一个分布」不一致

所谓「热力学层已经在管这件事」的前提不成立——它根本没在管。v4000 方案 C 启用前必须先修实现。

09模型的优缺点 实事求是

👍 优点

  1. 小而完整：物理核 179 万参数完成 128×128×6 帧 GIF 的重建（v3700），不需要扩散模型的迭代采样
  2. 物理可解释：每个算子有物理对应（Kuramoto 同步 = 相位锁定、OU = 布朗运动+回复力、驻波 = 共振传递函数），不是黑盒注意力
  3. 重建质量已验证：v2500 PSNR 24.57 dB / 用户 85% 还原；v3500 微调后 LED 网格感大幅消退（边界 20.06→8.47）
  4. 编解码零噪声：FFT 往返误差 5.96e-07，全保留 125 系数时 PSNR 147.2 dB —— 网格感 100% 来自截断，与变换本身无关
  5. 调试方法论健全：18 个死穴全部留档（现象→根因→修法→验证数据），消融诊断工具链完整（diag_blur/diag_block/diag_spec/diag_which_ch/diag_outlier_energy）
  6. 4GB 显存可训：batch=1 干净档 + CLIP 塔级分裂方案，单卡 3050 全流程跑通（预编码 14145 张仅 1.5 小时）
  7. 条件通路与物理核解耦：PMNNCore 一行未改，条件只从调用侧注入——失败可回退，成功可独立归因

👎 缺点

  1. 还不会生成：核心目标「条件生成」零实证——条件场差 5.7e-06，三指标全不达标，全量训练从未启动
  2. 耦合是零参数先验：与 UN-0「K 是最主要可学习参数」相反，相位可训练自由度只有 ω 偏移和 κ 缩放（第二死穴）——这是架构层面核心差距，被「零 Transformer」铁律约束
  3. DC 通道容量失配（架构性）：3 个 DC 通道占 96~99% 能量，却与 0.2% 能量的高频共用同一条 FFN 残差路径。方块感、糊感的总根源
  4. 步速极慢：0.2~0.29 步/s → 7 天只能跑 15~150 步，warmup 就要 300 步。不治理连验证都做不完
  5. 振幅学习偷懒：a_out 反复钉死在 0.2 附近（v2500 与 v4200 都有）；模型倾向用「整体压低振幅」「抬绝对值」等捷径应对 loss（第八死穴副作用、v3500 两个失败模式）
  6. 死代码与档案缺口：cond_prototypes.py（~1.55M 参数）已弃用未清理；三个判决脚本零输出存档；v3000K 终态无记录；v2500 原始权重已丢失（重跑版）
  7. 验证循环可能有 bug：「最佳验证 loss inf @ step 0」未排查；v4200 的 overfit.py 实际未被使用
  8. 环境脆弱：C 盘仅剩 258MB、提交上限 36.7GB 隐形炸弹、OpenBLAS 线程未锁死会静默挂死、Windows 中文用户名导致编码错乱

工程纪律（13 条，全部从事故中得出）

  1. 跑训练前先 py_compile（曾经训练结束后有人改脚本留半成品变量）
  2. 试跑必须带 OVERFIT_TAG（曾因无 tag 覆盖已训好 ckpt）
  3. 改 loss 先跑 150 步比同步数指标，方向错立刻终止
  4. 验收前先 ls 确认 overfit_ckpt_best.pt 存在
  5. 改 loss 变换必须同步改递推域 + μ 初值 + lr 倍率
  6. 诊断谱包络必须与 loss 聚合顺序一致（Jensen 陷阱）
  7. 加权方案必须先算权重分布（a_tar² 让 DC 独占 99.9%）
  8. 边界统计必须用平方能量（带符号误差正负相消）
  9. numpy/torch import 前必须锁死线程数
  10. 批量产物必须先落 outputs 再分析（曾 150 步试跑覆盖 3000 步 ckpt）
  11. preencode 启动即断言 GIF_ROOT.is_dir()，hit 率 <50% 直接 SystemExit
  12. np.save 临时名必须用 _tmp.npy 结尾（自动追加 .npy 陷阱）
  13. 所有 .cmd 批处理保持纯 ASCII（Windows cmd GBK 解析中文报错）
