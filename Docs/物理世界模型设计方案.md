# 基于物理振子架构的世界模型设计方案

> 调研时间：2026-10-25
> 基线架构：AetherGIF-V1（物理振荡子场，相位 θ + 振幅 a，12 层 Kuramoto 递推，109M 参数可训于 4GB）
> 本文档只做**技术方案**，不做商业判断。

## 一、2025–2026 世界模型格局调研

### 1.1 五条技术路线

| 系统 | 机构/时间 | 规模 | 核心方法 | 生成像素 | 动作条件 |
|---|---|---|---|---|---|
| **V-JEPA 2** | Meta 2025.6 | 1.2B | 潜空间预测（JEPA），不重建像素 | ❌ | ✅（62h 机器人数据） |

| **Marble** | World Labs 2025.11 | — | 3D-native，Gaussian Splats，持久场景 | ✅（3D） | ❌ |

### 1.2 关键量化事实

- **Physics-IQ 物理准确性最高分仅 24.1%** → 物理正确性是全领域开放问题
- **V-JEPA 2 规划速度比 Cosmos 快 30×**（因为不做像素重建）
- **Dreamer 4 单 GPU 实时（~60 FPS）**，靠 shortcut forcing 做到 **K=4 次前向/帧**
- **Genie 训练用 3 万小时互联网游戏视频、零动作标签**，隐动作空间仅 **8 个离散值**
- **Dreamer 4 用 5000 万 (state, action, reward) 元组离线数据**，零环境交互拿到 Minecraft 钻石

### 1.3 三种"世界模型"含义（不能混用）

| 含义 | 代表 | 本质 |
|---|---|---|
| **潜空间动力学**（为控制/规划服务） | Dreamer, V-JEPA, MuZero | 状态转移函数 `s_{t+1}=f(s_t,a_t)` |
| **生成式模拟器**（为渲染服务） | Sora, Genie, Cosmos | 可步进的像素/3D 环境 |
| **空间表征**（为持久场景服务） | Marble | 显式 3D 几何，不强调动力学 |

**AetherGIF 属于第一类**（潜空间动力学），只是潜空间是**物理量**而非黑箱 embedding。

## 二、三个可直接借鉴的技术（附实现映射）

### 2.1 ★ Genie 的 Latent Action Model（解决"没有动作标签"）

**做法**：从连续两帧推断"什么动作导致了这次转换"，动作空间压到 **8 个离散值**，完全无监督。LAM 只在训练时用（提供动作目标），推理时由用户指定动作。

```
输入：帧对 (z_t, z_{t+1})
输出：离散动作 a_t ∈ {0..7}
损失：用 a_t 重建 z_{t+1}，端到端学
```

**为什么这是本项目的关键**：
AetherGIF 目前的死穴是"没有动作数据集"（GIF 里没有控制信号）。**LAM 让这个问题消失**——只要能拿到视频序列，就能自动发现"可控维度"。

**物理化改造（本方案的差异点）**：

Genie 的隐动作是**离散 token**（8 个码本项），用户的架构可以提供**更好的物理形式**：

```
动作 = 加在 Kuramoto 方程上的外力场
dθ_i/dt = ω_i + Σ_j W_ij sin(θ_j−θ_i) + κ(t)·g_i + **F_action(t, i)**
```

动作编码器输出的是一个**低维控制向量 u ∈ R^k**（k=8~16），通过控制矩阵 `B` 映射到振子场：

```python
# 新增模块
self.action_enc = nn.Linear(action_dim, 64)          # 若有无监督则用 LAM
self.B_ctrl = nn.Sequential(                          # 控制矩阵，低秩
    nn.Linear(64, rank),                              # rank=8
    nn.Linear(rank, d_model)                          # → [D] 逐通道力
)
# 在 PhysicsBlock 递推中加入
theta_new = theta + coupling + res + B_ctrl(u).unsqueeze(1)   # [B,1,D] 广播到 N
```

**优势**：动作有明确的物理含义（力/相位推动），可解释、可外推。Genie 的 8 个离散 token 无法解释"这个动作是什么"，用户的力场可以。

### 2.2 ★ Dreamer 4 的 Shortcut Forcing（解决 rollout 太慢）

**做法**：训练模型用**固定少步数**（K=4）从噪声跳到目标，而不是逐步去噪。核心是把"信号水平 τ"和"步长 d"作为条件输入网络：

```
ẑ_1 = f_θ(z̃, τ, d, a)          z̃ = (1−τ)z_0 + τ z_1
```

网络知道"我这一步要跨多大"，因此 4 步就能出帧。

**为什么适配本项目**：AetherGIF 现在的 12 层递推是**固定步长**（每层一小步），若要 rollout 100 步就是 1200 次层计算。Shortcut forcing 可以训练模型学"跨步"——**让 12 层直接对应"跳几步"**，用 `d` 条件控制跳跃幅度。

**改造方案**：
```python
# 现状：12 层固定演化，无步长概念
# 改造：把层索引 t 与步长 d 解耦
#   输入增加 (τ, d) 嵌入，输出预测"d 步之后"的状态
layer_t = i / (n_blocks-1)           # 空间/演化位置
emb = LayerEmbed(t) + StepEmbed(d)   # 新增步长条件
```

**预期收益**：rollout 100 步的推理成本从 `100 × 12 = 1200 层计算` 降到 `100/k × 12`（k 为平均跨越步数，取 4 则降 4 倍）。

### 2.3 ★ Dreamer 4 的稳定性工程（已验证的坑）

Open Dreamer（JAX 复现版）报告，**稳定性占开发时间最大份额，且多数问题发生在 loss 正常下降时**——MSE 平滑改善但生成质量退化。六条已验证的修复：

| 修复 | 内容 | 对本项目的映射 |
|---|---|---|
| 优化器 | LaProp → **Muon**（LaProp 随机尖峰） | 当前用 AdamW8bit，可对比测试 |
| **EMA 必须** | 扩散/流推理必须用 EMA 权重 | 当前无 EMA，**建议加入** |
| **精度边界** | **参数保持 fp32，BF16 只用于 matmul 输入**，归一化与输出头用 fp32 | 与本项目"不能用 fp16"的结论一致，但更精细：**可以 BF16 matmul，不能 BF16 参数** |
| 预测空间 | x-prediction + v-space loss | 可对比 amp/phase 的预测空间选择 |
| 最优传输 | minibatch barycentric OT 稳定 rollout | 可考虑 |
| 逆模型正则 | **用"从 latent 反推 action"防止捷径** | 与现有 `DISC_W` 同思路，可复用 |

**最后一条最重要**：Dreamer 4 发现模型会学"预测下一帧=当前帧"这种捷径（重建好、动力学无用），于是加**逆模型**（从 `z_t, z_{t+1}` 反推 `a_t`）作为正则——如果反推不出动作，说明 latent 丢弃了动作相关信息。

**这对 AetherGIF 直接适用**：当前的"模式坍塌"本质上就是模型用"平均解"拿到低 loss。加逆模型正则可以强制 latent 保留区分性信息。

## 三、物理版世界模型设计

### 3.1 状态定义（沿用现有，是优势）

```
s_t = (a_t, θ_t) ∈ R^{B×N×D} × R^{B×N×D}
     振幅场            相位场
```

**相对主流的优势**：

| 维度 | V-JEPA / Dreamer | AetherGIF |
|---|---|---|
| 状态性质 | 黑箱 embedding | **物理量**（振幅/相位） |
| 转移机制 | 学出来的网络 | **微分方程**（Kuramoto） |
| 可解释性 | 无 | 每个量有物理含义（同步度 r、能量 U） |
| 外推 | 分布外易崩 | **物理定律可外推**（未验证，但是结构性优势） |

### 3.2 动作条件（核心新增）

**方案 A：无监督隐动作（Genie 路线，推荐先做）**

```
① 训练 LAM：从 (z_t, z_{t+1}) 编码出 u ∈ R^8，用 u 重建 z_{t+1}
② 冻结 LAM，用 u 作为动作条件训练动力学
③ 推理时用户给 u，物理核把 u 转成力场
```

**方案 B：有监督物理动作（若有标签数据）**

直接给控制量（关节角速度、方向盘、推力），走 `B_ctrl` 映射。

**本方案建议**：先用 A 打开局面（数据门槛低），后续有标注数据时切 B。

### 3.3 转移算子（物理化 rollout）

```
s_{t+1} = Φ(s_t, u_t; t)

Φ 的内部：
  12 层 PhysicsBlock 递推，但：
  ① 初始态 = s_t（**继承上一帧，不是重新从条件生成**）
  ② 每层加入动作力：+ B_ctrl(u_t)
  ③ 层索引 t 与步长 d 解耦（shortcut）
```

**关键改动**：现在是"条件 → 全片"，改成"状态 → 下一状态"。这是从**生成器**变成**模拟器**的本质区别。

```python
# 现状（生成）
a, th = model(cond_vec=cv, t_coord=t, s_coord=s)   # 一次出 30 帧

# 改造（模拟）
for step in range(horizon):
    a, th = model.step(a, th, u_t, d=4)            # 一次出 1 步（跨 4 个原始步）
    rollout.append((a, th))
```

### 3.4 ★ 长期稳定性（本架构的独有优势）

主流方案靠 loss 硬压或 EMA；**本架构可以靠物理约束**：

| 机制 | 物理依据 | 实现 |
|---|---|---|
| **能量守恒** | 无外力时 `U = −Σ W_ij cos(θ_j−θ_i)` 应守恒 | 监控 `|ΔU|`，超阈值加惩罚 |
| **阻尼耗散** | 真实系统有耗散，防能量爆 | 相位加 `−γ·∇V(θ)`，振幅已有 `γ` |
| **序参量约束** | 同步度 `r` 不应跳变 | `r_{t+1} − r_t` 加平滑惩罚 |
| **相位锚定** | 防长期漂移 | 已有 `ANCHOR_W`，需改为 per-step |

**为什么这是优势**：Dreamer 4 的稳定性问题是"loss 下降但质量退化"，属于**不可诊断**的失败；物理约束提供的是**可测量的失败信号**（能量漂移、r 跳变），能提前发现。

### 3.5 训练目标

```
L = L_pred + λ_1·L_inverse + λ_2·L_energy + λ_3·L_action_ctrl
```

| 项 | 定义 | 作用 |
|---|---|---|
| `L_pred` | 预测态与真实态的 log1p 振幅差 + 功率加权相位差（沿用现有 `loss_amp + loss_ph`） | 基础预测 |
| **`L_inverse`** | 从 `(s_t, s_{t+1})` 反推 `u_t` 的交叉熵/MSE | **防捷径**（Dreamer 4 验证有效） |
| **`L_energy`** | `|U(s_{t+1}) − U(s_t)|`（无动作时）或 `|U_{t+1} − U_t − W_u|`（有动作） | **物理守恒** |
| **`L_action_ctrl`** | 不同 `u` 产生的轨迹差异应 > 阈值 | **动作可控性** |

`L_action_ctrl` 是判据也是损失：**同一初始态，两个不同动作必须产生可测差异**，否则"动作条件"是假的。

## 四、与主流方案的定位对比

| 维度 | Genie 3 | Dreamer 4 | V-JEPA 2 | **本方案** |
|---|---|---|---|---|
| 规模 | 11B+ | 1.6~6B | 1.2B | **目标 25~110M** |
| 训练数据 | 3万小时游戏 | 5000万元组 | 100万小时 | **起步 22 个 GIF** |
| 硬件 | 256 TPUv5p | B200 | 大规模集群 | **4GB 笔记本** |
| 状态 | 离散 token | 离散 token | 连续 latent | **物理量（相位/振幅）** |
| 转移 | MaskGIT | Block-causal Transformer | 预测器 | **微分方程** |
| 动作 | 8 隐动作 | 27 二值+121 类别 | 机器人动作 | **力场（连续）** |
| 物理保障 | 数据驱动 | 数据驱动 | 数据驱动 | **显式守恒律** |

**诚实定位**：本方案在**规模上差 2~3 个数量级**，不可能在生成质量上竞争。唯一可能的差异化是：

> **用显式物理约束换数据效率**——在数据量少 1/1000 的情况下，靠物理归纳偏置达到可用的动力学精度。

这个命题**尚未验证**，但它是这个架构唯一值得下注的理由。

## 五、实施路径（按 4GB 硬件现实排序）

### 阶段 A：动作条件原型（4GB 可做）

| 步骤 | 内容 | 判据 |
|---|---|---|
| A1 | 实现 LAM（帧对 → 8 维隐动作） | 隐动作能区分不同帧间转换（聚类可分） |
| A2 | 实现 `B_ctrl` 动作注入 | 同一初始态 + 两个不同 u → 轨迹差异可测 |
| A3 | 小规模验证 | 在 22 个 GIF 上，动作可控性 wcos 差异 > 0.3 |

**这一步不需要新数据**（用现有 GIF 序列即可）。

### 阶段 B：rollout 改造（4GB 可做，显存紧）

| 步骤 | 内容 | 判据 |
|---|---|---|
| B1 | 把"一次出全片"改为"逐步出帧"，状态继承 | 能连续生成 2 倍长度而不崩 |
| B2 | 加 shortcut（步长条件 d） | K=4 能达到 K=1 的预测质量 |
| B3 | 加能量守恒/序参量约束 | 100 步 rollout 不发散 |

### 阶段 C：规模化（需 ≥24GB 显存）

| 步骤 | 内容 |
|---|---|
| C1 | 参数扩到 500M~1B，验证 scale 曲线是否单调 |
| C2 | 数据扩到 100+ 小时带动作视频 |
| C3 | 3D 表征（体积频域或多视角一致性） |

**关键前置**：C1 必须先做，因为**架构的 scale 性至今未验证**（23M→109M 时 22 素材 sat 极差从 5.32 降到 0.68，是负向证据）。在 scale 性未验证前投入 C2/C3 是高风险。

## 六、风险清单

| 风险 | 依据 | 缓解 |
|---|---|---|
| **架构 scale 性可能不成立** | 23M→109M 有负向证据 | 阶段 C1 先验证 |
| **物理准确性未必优于数据驱动** | 全领域 Physics-IQ 最高 24.1%，说明显式物理也不易 | 先用小场景对比测试 |
| **4GB 显存做不了 rollout** | 长序列激活爆显存 | 梯度检查点 + 短窗口 + 分块 |
| **LAM 在小数据上可能学不出有意义的动作** | Genie 用了 3 万小时 | 先用合成数据（可控运动）验证机制 |
| **没有动作标注数据** | GIF 无控制信号 | 走 LAM 无监督路线 |

## 七、最小可验证实验（建议第一个做）

**目的**：验证"物理核能否被动作控制"，这是一切的前提。

**设计**：
```
数据：22 个 GIF 中挑 3 个有明确运动的（如 8ball 滚动、senpai 挥手、idolmaster 摆动）
步骤：
  1. 训练 LAM（3 个视频，帧对 → 8 维隐动作）
  2. 用 LAM 输出的 u 训练 B_ctrl 注入
  3. 测试：固定初始帧，给 u_1 和 u_2（差异最大的两个隐动作）
     各 rollout 5 步，比较轨迹差异
判据：
  · 两条轨迹的相位场 L2 距离 > 阈值（初始态相同时）
  · 且 u_1、u_2 各自的结果在多次采样下稳定（方差小）
```

**这一步用 4GB 卡、现有数据、约 1 周可完成。**

**如果这条失败**，说明当前架构不具备动作可控性，世界模型路线需要重新设计（可能需要改变状态定义或转移算子结构）。

**如果成功**，就拿到了世界模型的第一张入场券——可以对外说"我们的物理核支持动作条件推演"，这比任何生成质量指标都有说服力。
