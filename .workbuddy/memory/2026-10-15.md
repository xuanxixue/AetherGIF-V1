### ★ max_length 必须动态放宽（新增坑）
官方 `_preprocess_inputs` 硬传 `truncation=True`，视频 token 数 ≈ 帧数 × 每帧patch。

## ★ 官方 Qwen3VLEmbedder 的三个硬编码坑（全部实测撞过）

`Qwen3VLEmbedder.__init__`（`Qwen3-VL-Embedding/src/models/qwen3_vl_embedding.py`）：

1. **硬编码 `.to(device)`**：
   ```python
   device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
   self.model = Qwen3VLForEmbedding.from_pretrained(...).to(device)
   ```
   没有开关能关。只要CUDA 可用就把整份权重塞进 4GB 卡 -> 加载阶段就 OOM。
   **解法**：构造期间monkeypatch `torch.cuda.is_available = lambda: False`，
   拿到 CPU 模型后恢复，再自己流式分配。

2. **不能传 `device_map`**：官方接着调 `.to(device)`，而 accelerate 的 offload 模型
   禁止再 `.to()` -> `You can't move a model that has some modules offloaded to cpu or disk.`

3. **不能传 `trust_remote_code`**：官方内部已硬传，重复传 ->
   `got multiple values for keyword argument 'trust_remote_code'`

## ★ GPU 交叉执行的实测边界（4GB 卡的天花板）

| 方案 | 结果 |
|---|---|
| 整份 fp16 上 GPU | 需 4058 MiB，可用仅 3300 MiB -> OOM |
| 视觉塔常驻 + 语言层 offload | hook 没覆盖 `get_input_embeddings()` -> 设备不一致 RuntimeError |
| 全模型 `cpu_offload_with_hook` | hook 生效，但前向时embedding 表(1.2GB)+视觉塔占满 -> OOM |
| **纯 CPU fp32（当前采用）** | **PASS，文本 4.6s / GIF 471.7s** |

**结论：4GB 显存放不下 2.1B 模型的 fp16 权重（4.06GB），差 700MB。**
要真上 GPU 必须降位宽（int8 = 2.1GB，需 bitsandbytes）或换更小的 embedding 模型。
**交叉计算的价值在于降显存峰值，不在于提速** —— 本机瓶颈是显存容量，不是算力。

## cond_field 条件分化诊断链（fit1~fit4 + 150 步验证，2026-10-15 傍晚）

### 问题与定位过程
300 步训练 FAIL：sup 300 步只降 0.8%、src1 坍缩到素材 A。诊断脚本确认
场差 6.83e-4（机制通了）但 chan_amp std=0.0211≈初值 0.02（谱形状没学）。
梯度被 to_chan 吸走。

**fit1**（`test_cond_field_fit.py`，纯拟合隔离结构 vs setup）：lr=1e-3 只有
−5.4%/200 步、chan_amp 涨 3.85 倍且仍在加速 → 中间态，两因素都有。
**fit2**（3 条件 × 400 步）：27 基 lr=3e-3 发散（240 步回弹）、64 基 lr=1e-3
最好（−9.1%）但幅度有限；lr=3e-3 是发散上限 → **结构问题为主**。
**结构性发现：驻波基底无 DC 模式**——`StandingWave3D` 模式序号从 1 起
（`arange(1, n+1)`），所有基三维度全振荡，谱包络的缓变成分张不住。
**fit3（修复 1：补 DC 基）**：`StandingWave3D` 加 `mode_offset` 参数
（默认 1 兼容旧行为，0 → m∈{0..n-1} 含 DC；基数量不变=把最高频换最低频）。
64 基 offset=0 lr=1e-3 → **−19.9%**（offset=1 的 2.2 倍）、场差 6 倍、
lr=2e-3 也不发散（DC 基让优化 landscape 平滑）。**PASS**。
**fit4（修复 2：einsum 等价显存优化）**：`cond_field.forward` 的
`einsum("bk,nk,bkc->bnc")` 反向会物化 [B,K,N,C]（64 基 786MB），等价分解为
`coeff=w.unsqueeze(-1)*amp; einsum("bkc,nk->bnc", coeff, sw)`（内部 bmm，
反向不物化大张量）。64 基 offset=0 lr=2e-3 复现 1.1769 ≈ fit3-E 的 1.1781
→ 数学严格等价。**27 基 offset=0（1.2075）与 64 基只差 2.6%** → 用 27 基
（生成通路显存 B=1 2.7GB 已知可行，一次一个变量）。

## 关键澄清：int8 的作用边界（防误解，2026-10-15）

- **int8 解决 = 离线预编码器上 GPU**：Qwen3-VL-Embedding-2B fp16 需 4058 MiB 塞不下 4GB 卡，int8 降到 2444 MiB；CPU 471s/GIF → GPU 1.8s/GIF。
- **int8 不解决 = 物理核训练显存**：训练瓶颈是 drift pairwise 激活 + 12 block 驻留张量（不是权重，物理核没有可量化的线性层大头）。
- 训练时根本不加载编码器（读离线 .npy），所以训练显存与 int8 无关。完整配置 D=125 训练只能 **batch=1**（交接铁律 B=1 2.55GB；B=2 分配器碎裂爆）。
- 换模型 jina-clip-v2(1024) → Qwen3-VL(2048) 后，旧 `clip_cache/*.npy` 维度已作废，正式训练前必须用 int8 重跑 preencode。
