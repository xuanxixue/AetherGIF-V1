### ★ 挖出并修复 20 个文件同源的运行时 bug
`gif_codec.resize_gif_to_10fps`：
```python
ndimage.map_coordinates(frames[..., c], t_new.reshape(1, -1), ...)
```
`frames[..., c]` 是 3D `[T,H,W]`，但 scipy 1.18 要求 n 维输入配 n 组坐标，
原写法只给 1 组 → `RuntimeError: invalid shape for coordinate array`，**codec 直接崩**。

修法：补齐 y/x 网格坐标（时间轴取 `t_new`）。已验证与「只对时间轴线性插值」结果**差异 0.0**。
共修复 20 个 `gif_codec.py`（根 src + 19 个版本快照，含 v2500_3DFFT_修复版那个签名不同的）。

**为什么此前没爆**：v4200 训练走 `scripts/preencode.py` 的**独立实现**，绕开了 codec 的 resize。
这是个潜伏 bug，一旦谁调用 `gif_to_target_field()` 就会炸。

### 修复 bug 1（最严重·静默白跑）：`COND_INIT_PC` 无默认值

- 现象：`train_guided.py` 启动时若**漏设** `COND_INIT_PC=1`，模型静默退化成旧
  `CondInitModulator` → 参数量 **10,273,206**（而非 23,044,534），
  且 `RESUME` 会把 6 个 `cond_init.*` 层当"shape 不匹配"跳过 →
  **条件通路整体随机初始化**，训练几小时等于白跑，日志只有一行不起眼的"跳过 N 层"。
- 证据：color 系列 ckpt 的 `cond_init.to_amp.1.weight` 全是 `(768000, 8)` = CondInitPC；
  而 `fix_r4/cond3_ckpt.pt` 是 `(30720, 16)` = 旧 Modulator。两者不可混。
- 修法：`train_guided.py` 补 `setdefault("COND_INIT_PC","1")` + `setdefault("COND_PC_RANK","8")`
  （显式设 `COND_INIT_PC=0` 仍可覆盖）。**`overfit_cond3.py` 不加默认值**，因为它服务
  fix_r 系列旧架构，加了反而破坏兼容。
- 验证：修复后不传环境变量 → `CondInitPC (rank=8)` / `23,044,534` /
  `RESUME missing=0 unexpected=0`，第 1 步 `loss=0.7052 wcos=+0.9225` 与 color4 原 log
  **逐位一致** = 等价续训。

### 修复 bug 2（数据安全）：`torch.save` 非原子 → ckpt 可被写坏

- color4_long 就是崩在这里：第 200 步 `torch.save(_sd, OUT_DIR/"guided_ckpt.pt")`
  抛 `PermissionError: [Errno 13]`（Windows 文件被杀软/索引/残留句柄短暂占用），
  100→200 步约 20 分钟白跑。更危险的是直接写目标文件，中途失败会留下**截断的 ckpt**，
  把上一份完好权重覆盖掉 —— 正是"模型损坏"的来源。
- 修法：两脚本各加 `_safe_torch_save()`：先写同目录 `.tmp<pid>`，成功后 `os.replace`
  原子替换，带 6 次递增重试。失败时**保留 .tmp**（不删），人工可改名恢复。
- 实测（4 种场景）：正常保存 ✓ / 原子覆盖已有文件 ✓ / 模拟文件占用 → 抛预期错误且
  **原 ckpt 完好无损** ✓ / .tmp 完整保留 ✓。

### 修复 bug 3（防误操作）：`RESUME` 路径不存在时静默从头训

- 原逻辑 `if _rp.exists():` 走 `else: print("路径不存在，忽略")` 然后继续 ——
  用户明确指定续训却静默变成随机初始化，且提示容易淹没。
- 修法：默认严格模式 `RESUME_STRICT=1`，找不到文件直接 `SystemExit(2)`；
  设 `RESUME_STRICT=0` 可退回旧行为。
- 附加：`RESUME` 若跳过**关键条件层**（`cond_init./cond_field./fft_bypass.` 的
  expander 层，排除 `.0.weight` 低秩层 —— 低秩随 `COND_LOWRANK` 变动属设计意图）
  → `SystemExit(3)`。实测误配 `COND_INIT_PC=0` 续训 PC ckpt 时精准中止并指出原因。

## ★ color3 的权衡发现（用户点名要记，第三十八死穴）

**color3_long = COLOR_W=2.0（从 color2 续，850 步）**：

| 指标 | color2（W=1.0） | color3（W=2.0） | 素材基准 |
|---|---|---|---|
| 纯生成 sat | 13.3 / 15.9（2.3×/1.6×） | **8.9 / 8.4 ≈ 素材水平** | 5.8 / 9.9 |
| 视频再生 sat | 6.9 / 12.6 ≈ 素材 | **2.1（洗白偏亮，均值 126.5 vs 95.8）** | — |
| 旁路差距 | **+0.15 dB**（首次兑现） | **−0.81 dB（退回）** | — |

- **结论：W=2.0 过度优化纯生成分支，把视频再生分支压垮了。**
  纯生成（从 cond 起步）与视频再生（有 fft_bypass 旁路）的**最优点不同**：
  W=2.0 让模型学会"不依赖旁路、自己就能干净"，于是旁路的相位贡献被边缘化。
- **可复用规律**：颜色 loss 权重不是越大越好。W=1.0 是分支均衡点（color2/color4 用），
  W=2.0 会牺牲旁路能力。调 COLOR_W 必须**同时看纯生成 sat 与视频再生 sat 两条曲线**，
  只看纯生成会误判为"成功"。
- ckpt 定位：color2 = 均衡（视频完美、纯 gen 2.3×）；color3 = 纯 gen 达标但视频塌；
  color4 = 期望兼得（W=1.0 从 color2 续）。
