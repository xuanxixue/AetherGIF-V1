## 「修复后质量反而不如 2500 步那次」的归因（重要）

用户质疑：方案 F/G 修复后视觉质量远不如方案 D 的 2500 步（overfit-12.gif，PSNR 21.04，
用户评价 85%）。实测归因如下，**不是模型变差，是三个可分离的原因**：

### 1. 出图口径是最大元凶（视觉崩塌的直接原因）
`outputs_real/overfit.gif` 用 `normalize=True`（min-max）。FFT 系数是极重尾分布，
模型输出的离群系数被 min-max 拉满量程，把 99% 的正常系数压成中灰：

| 解码口径 | pix_mean | 帧内 std | PSNR |
|---|---|---|---|
| target | 95.4 | 33.9 | — |
| D2500 min-max（用户看的那张） | 100.9 | 15.8 | 21.04 |
| G1000 min-max（崩了的那张） | **130.7** | **4.8** | 14.50 |
| G1000 固定 clamp | 78.0 | 29.9 | 17.78 |
| G1000 分位裁剪(0.5%,99.5%) | 91.6 | 39.9 | 15.91 |

→ min-max 下 std 从 33.9 塌到 4.8 = 整张图"糊成一片灰"。**方案 G 的 amp loss 让振幅
   整体偏低 + 存在少数离群系数（max=59.5 vs target 24，能量占比 0.4% vs 0.1%），
   min-max 量程被这 0.4% 的离群点绑架**。
→ **诊断纪律新增：出图一律用固定 clamp 或分位裁剪，禁止 min-max 做视觉评估。**
   min-max 只适合"看形状对不对"，不适合看质量。

### 2. 步数腰斩（2500 → 1000），loss 未收敛
方案 G 1000 步时 loss 仍在 2.16 下降中（overfit_out.txt 最后一行），a_out=0.73 仍
远离 target 0.195。方案 D 的 2500 步 loss 已到 0.32（降 6.7×）。
**用 1000 步的结果去对比 2500 步的结果，本身就是不公平对照。**

### 3. 相位确实进步了（不是退步）
`cos_eff`（功率加权）D2500=0.931 → G1000=0.895。方案 G 略低，但方案 D 的 0.931
是在振幅偏 2.3-3.0× 的情况下靠"过曝掩盖相位误差"得到的视觉假象。

### 结论
- **架构修复（正交分离 + 双 γ + 共享 μ + 分组 lr）方向是对的**，谱形状确实修好了
  （profile_cos 0.99、谱跨 229× vs target 727×）。
- **loss 改动（log 域无权重 + EPS_A=0.01 软截断）有害**：把 69.4% 近零系数的梯度
  归零，等于放弃了高频细节的监督 → 视觉上"网格感"（用户说的网格套在图上）没消掉。
- 用户对 D2500 的评价（网格感、偶尔震荡、对比度略不同、轨迹/残影/数字/配色都对）
  是准确的，D2500 确实是当前最好的 checkpoint。

### 待办（已与用户确认方向）
- 出图口径改固定 clamp / 分位裁剪，`overfit.py` 的 `normalize=True` 分支需改默认
- loss 回退到方案 D 的 AMP_P=0.5 log1p 口径，架构修复保留
- 跑满 2500 步做公平对照

## 第十二死穴最终定位：log 在 a→0 处无界（不是截断阈值的问题）

### 错误假设的修正链（三轮，每轮都被实测否掉）
1. **方案 G 加 EPS_A=0.01 软截断**："近零系数梯度是噪声，屏蔽掉"
   → 实测把 **62/64 通道的 target 真值钉在 log(0.01)=-4.605**，
     "屏蔽噪声梯度"变成"屏蔽真值"，非 DC 通道 μ 系统性偏高 4.1 个 log 单位。
2. **改纯 log 无截断**：DC ch25/ch50 误差 2.90→0.31（方向对了），
   但 ch0 从 +0.38 恶化到 −2.13，非 DC 仍差 2.50。
3. **真根因**：`log(a)` 在 a→0 时无界（log(1e-4)=−9.2）。
   实测 **ch25/ch50 各有 1748/6144 个位置 a<1e-4**（FFT 数值零，不是真零），
   这些位置 log=−13.8，比 ch0 的 +1.94 低 **15.7 个单位**，把整条通道的
   log 域均值硬拽到 −5.5/−5.9。
   **log1p 在 a→0 时→0（梯度=1，有界）**，log1p 域逐通道均值：
   ch0=2.093  ch25=0.344  ch50=0.234  ch1=0.154  ch55=0.0285（动态范围 73×，有界可学）

### 最终口径（方案 H）
```python
la = torch.log1p(a); lt = torch.log1p(a_tar)
loss_amp = (la - lt).pow(2).mean()   # 无幅度权重、无截断
```
- 不用 log：a≈0 处无界会把层级拽飞
- 不加 (a/a_max)^p：log1p 域已是倍数度量，加权=重新给 DC 加权，会压平谱（第七死穴）

### 150 步验证（去截断版，中间态）
- 谱跨 21×→309×、profile_cos 0.19→0.69 单调升、DC ch25 误差 2.90→0.31 ✅
- 但 ch0 +0.38→−2.13 ❌、frame-diff 13.58（target 5.39）❌ → 方向对但步数远不够

### 同时修掉的 4 个 bug/口径问题
1. **μ lr warmup**（新增）：log1p 域跨度 73×，×80 lr 起步会冲过头，
   线性 warmup 前 5%（最少 50 步）从 ×1 升到 ×80
2. **频段分组口径错误**（重要）：旧代码按 0/16/32/48 均分 64 通道，
   但真实 rfft2 是 **h_fft=3 × w_fft=25** 网格，通道 c ↔ (h=c//25, w=c%25)。
   均分把 w=0 的 DC（ch0/25/50，占 99.4% 能量）和高频混在一起，**频段比读数完全失真**。
   改为按真实空间频率 w 切：w=0(DC) / w=1-3 / w=4-9 / w≥10
3. **min-max 出图彻底禁用**（第十一死穴）：改分位裁剪(0.5%,99.5%) 作主口径，
   固定 clamp 作副口径。代码中已无 min-max 调用
4. **所有 log 均值口径统一到 log1p 域**，与 loss_amp 同量纲

### 训练期新增早停判据

## 第十三死穴（真正的架构 bug）：架构在 log 域递推 μ，loss 在 log1p 域——量纲错位

### 发现路径
500 步验证时 μ 报 −1.21，但模型实际层级是 +0.34，**两者差 1.55**。
这违反了我一直以为的"m 收敛到 μ"。追查后确认：

- `block.py`：`m_new = m + γ_lvl·(μ − m)`，其中 `m = mean_N(log a)`
  → **a_mu 的稳态目标是 mean_N(log a)**
- `overfit.py`：`loss_amp = (log1p(a) − log1p(a_tar))²`
  → **loss 惩罚的是 mean_N(log1p(a))**

两套量纲从第一步就不同。μ 拿着 log 域的结构去追 log1p 域的目标，
永远差一个变换，只能靠震荡硬凑（实测 μ 在 4~16 之间反复横跳，
ch0 从 2.18 冲到 8.99，pix_mean 掉到 19/95.3 全黑）。

### 修法：架构整体搬到 log1p 域（与 loss 严格同量纲）
```python
L = torch.log1p(a.clamp(min=0.0))          # a→0 时 L→0，梯度=1，有界
m = L.mean(dim=1, keepdim=True)            # 层级
m_new = m + γ_lvl·(μ − m)
L_new = m_new + delta_new
a_new = torch.expm1(L_new.clamp(min=0.0, max=6.0))   # 上限 expm1(6)=402
```
- **μ 初值必须同步改**：`log(0.05)=−3.0` → `log1p(0.05)=0.0488`
  （用错量纲差 3.05 个单位，PMNNCore 和 PhysicsBlock 两处都要改）
- 溢出保护：L_new 上限 6.0 → a ≤ 402，target ch0 最大 24，留 16.8× 余量

### 修复验证（`scripts/diag_log1p_fix.py`，5 项全过）
```
[验证1] |模型层级 − μ| mean=0.000305  max=0.000331  ← 修复前差 1.55
[验证2] μ 初值 = 0.0488 = log1p(0.05)✓
[验证3] target log1p 跨度 = 2.1685（有界可学）
[验证4] a_new 上限 expm1(6)=402.4，target ch0 max=24，余量 16.8x
[验证5] a.min()=0.0274 ≥ 0✓（expm1 保证非负）
```

### μ 学习率：80 → 5
log1p 域跨度只有 2.17（log 域是 6.6），×80 相当于过冲 20 倍。
×5 时爬完 2.17 需约 1450 步，在 3000 步预算内从容收敛。
**教训：改 loss 的变换时，必须同步检查架构递推的变换和所有相关超参的量纲。**

### 150 步验证（修复后）
- **非DC μ 层级误差 = 0.1487，已达标（判据 <0.3）**，且 0.055→0.149 单调可控、无震荡
- profile_cos 0.939
- ch0 μ=0.30（target 2.179，还在爬，1450 步到位）——**不是 bug，是步数**
→ 所有 bug 修完，已开跑 3000 步

## V3000 修复版：纠正两处旧记忆错误 + AC 过冲根因（下午，重要）

### 纠正旧记忆两处关键错误（实测，2026-10-11 下午）
1. **rfft2 真实输出 = (N, 5, 25) = 125 系数**，不是旧笔记的 75。
   win=5（时间维做完整 FFT，不截半）× s_dim//2+1=25（空间维 rfft 截半）= 125。
   所以 d_model=64 只保留 **51.2%** 谱，不是旧笔记的 85.3%。
2. **空间 DC 列 w=0 占 96.4% 能量**（全 125 通道口径），不是"前5通道98.07%/3个DC通道99.4%"。
   被 D=64 砍掉的 61 通道（主要是 h=2,3,4 的高频时间分量）只占 7.93% 能量。

### AC 分量过冲 = "噪声/颗粒感"的模型端根因（diag_amu.py 实测）
- v2500 的 12 个独立 a_mu **全程停在初值 log(0.2)≈-1.6**，频段间无差异（-1.4~-1.5），
  而 target 谱包络是 DC≈-3.15 / AC≈-8.73，差 5+ log 单位。μ 根本没学到。
- 后果：AC（低频/中频/高频）通道能量过冲 2~3.6 倍（c5=2.15、c40=3.28、c63=3.08），
  而空间 DC ratio=1.0 完美。这就是"方块/颗粒/噪声感"的来源：块均值对、块内细节过度锐化。
- **量纲错位机制**：a_mu 在 log 域递推、loss 在 log1p 域，AC 小通道梯度被 a/(1+a)≈0.02
  因子压抑 40 倍，学不动。

### V3000 修复方案（方案 D 派生，最小改动）
1. 共享 μ（12→1 份，第十死穴），参数量 1,135,658 → 1,134,954
2. 分组 lr：a_mu ×20
3. loss 域可切换：log1p / log（修第十三死穴量纲错位）

### 150 步短验证（决定性）AC 过冲 [DC/低频/中频/高频]
- log1p+权重0.5（方案D原样）：1.18/7.38/10.87/13.01 → 方向反，AC 收敛慢
- log+权重0.5：0.75/3.24/4.06/5.03 → 好但权重压制 AC
- **log+等权：0.25/1.06/2.51/3.28 → 低频直接校准到 1.06（最优方向）**
- 结论：log 域天然拉平重尾，**不该再加幅度权重**；但等权淹没了真 DC 通道 c=0（发暗）
- 已加 DC_WEIGHT 参数：只给 c=0 加权（承载 96% 能量），500 步验证中（task dy6M11）
