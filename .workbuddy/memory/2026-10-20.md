## 修复 fft4k 长训第 1 步崩溃（W2_NORM_MAX 梯度 hook 错误）

### 崩溃
`outputs_real/fft4k.log`：第 1 步 `(loss/ACC_K).backward()` 抛
`AttributeError: 'tuple' object has no attribute 'mul_'`，位置 `block.py:_clip_w2_grad`。
之前 dbg2（20 步）因 `RES_LIMIT=0.5` 但 W2_NORM_MAX 的梯度 hook 在 eval/浅层没触发，
长训每步 optimizer.step 才暴露。

### 根因（两层错误，都在「梯度 hook」这个实现选型上）
1. `register_full_backward_hook` 的 `gout` 是 **tuple 且不可索引赋值**：
   `gout.mul_()` 报 `'tuple' object has no attribute 'mul_'`，
   上版改成的 `gout[i] = _g * k` 会再报 `'tuple' object does not support item assignment`。
2. 就算不崩，缩放 grad_output 只是缩小当步更新量，**拉不回已经超标（实测 14.50）的权重范数**。

### 修法（改「step 后权重投影」，弃梯度 hook）
- `block.py`：`PhysicsBlock.__init__` 删掉 hook，改存 `self._w2_norm_max`；
  新增 `project_w2()` 方法：`n>mx` 时 `w.mul_(mx/n)`。数值口径不变、历史 ckpt 兼容。
- `block.py`：`PMNNCore.project_w2()` 对全部 block 调用。
- `overfit_cond3.py`：`opt.step()` 之后、`opt.zero_grad()` 之前插入 `model.pmnncore.project_w2()`。
- 依据：diag_clip_ffn_w2.py 直接缩放权重实测 corr(log a) 0.478→0.500。

### 验证
3 步冒烟（OVERFIT_TAG=smoke_w2）通过，no 崩溃。
2000 步长训已重投（task E8WoV0，fft4k），第 1 步正常输出 `loss=2.1373 hi/lo比=40.18`。

### 教训（memorize）
- **hook 选择**：register_full_backward_hook 的 gin/gout 是 tuple；要读读 weight.grad，
  不是 grad_output。任何「约束权重范数」需求，**直接做 step 后投影**最稳。
- 「在 eval 下测不出、训练才崩」的 bug：梯度类约束必须在**真实反向 + step**路径里冒烟，
  不能只在 eval/no_grad 下验证。

## 审查 + 两个架构级 bug 修复（18:17）

用户要求「先审查→再给修复方案→再修」，不要直接改码。审查结论分两层：

**第一层：目录勘误**。根目录 `D:/AetherGIF-V1/src`、`scripts` 是 v3600 旧快照；
v4200 现行代码在 `D:/AetherGIF-V1/docx/实验记录/versions/v4200_多模态CLIP产品版/`。
以后一律在 v4200 目录下作业。

**第二层：架构审查——找到两个「约束根本没生效」的 bug（都不在 loss 层，在物理链路本身）**：

1. **KAPPA_MAX 是空操作**。`aether_gif_model.py` 原文 `kappa = kappa.clamp(max=KAPPA_MAX)`
   的 `kappa` = `kappa_base * kappa_scale`（sigmoid 后 ≤2），而真正喂进块的是
   `tf["kappa"] * kappa`——深块 tf["kappa"] 涨到 ~15.85，乘积可达 ~31，κ·g 暴力
   同步把相位拉平。clamp 加在 call 侧也加错了量，等于第三十死穴第③破坏源一直没修。
   → 修法：改 clamp **有效 κ** = `tf["kappa"] * kappa`。

2. **A 方案条件锚用了 dtheta 而非 θ̂**。`anchor_t = dtheta.detach()`，但 θ̂ 模式下
   `dtheta = wrap(θ̂−θ0)` 含随机 θ0 分量。漂移场力 `sin(anchor−θ)` = `sin(dtheta−θ)`
   ≈ 依赖随机初相位，每块都在把相位往随机方向拽，**主动抵消** θ̂ 模式的第二十八
   死穴修复；且 supervise 监督的是 θ̂ 口径，锚却是 dtheta，两处不一致。
   → 修法：`anchor_t = theta0_m.detach()`（= θ0+dtheta ≡ θ̂ mod 2π，纯条件量）。

两条都是「改了但改错位置/改错量」的隐性失效，`py_compile` 三文件通过。
★ 教训：**clamp/投影类约束要验证它作用的对象是不是最终实际生效的那个量**；
「加了上限」不等于「上限生效」。
