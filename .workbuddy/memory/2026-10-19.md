
## 第二十八死穴：θ0 随机 + dθ 看不到 θ0 = 相位对齐的天花板恒为 0（2026-10-19）

★ **本阶段最重要的发现，结构级，不是调参问题。**

### 探针数据（scripts/diag_theta0_ceiling.py，纯数学）

θ_final = θ0 + dθ，θ0 ~ U(−π,π)，dθ = f(cond) 与 θ0 **独立**：

| dθ 情形 | cos(θ_final, θ_tar) |
|---|---|
| dθ = 理想修正量（依赖 θ0），bound=π/4 | +0.474 |
| 同上 bound=π/2 | +0.818 |
| 同上 bound=π | **+1.000** |
| **dθ 任意幅值 π/4→2π（8 倍），但与 θ0 独立** | **−0.003 ~ +0.002** |

⇒ **θ0 的随机分量没有任何通路能消掉。phase_scale 从 π/4 提到 π/2、
加绝对相位项，都是在给数学上无解的问题加权重。**这解释了
phabs500 之后 wcos 卡在 0.25 就再也上不去。

### 修法（θ̂ 模式，物理核零改动）

`cond_init.forward` 新增 `theta0` 参数。不为 None 时：
- `to_phase` 输出**不再当增量**，而当「目标相位预测 θ̂」，
  `θ̂ = arctan(pre) · π`（值域 (−π,π] = 全圆，**不乘 phase_scale**）
- `dtheta = wrap(θ̂ − θ0)` ⇒ `θ0 + dtheta ≡ θ̂ (mod 2π)`，随机初相位**完全抵消**
- `init_parts["theta_hat"]` 送进 diag，`supervise` 新增 `theta_hat` 参数：
  **监督 θ̂ 本身，不监督 dθ**（dθ 是含随机 θ0 的派生物）

### 验证

`scripts/diag_theta_hat_mode.py`：两次不同随机 θ0，同一条件
cos(θ0+dθ, θ_tar) 差异 **2.33e-10** ⇒ 随机 θ0 被完全抵消，结构修复生效。
旧模式 |dθ| 均值 0.0000（被 phase_scale 锁死）作对照。

150 步首验：wcos −0.0021 → +0.0234（旧结构同期恒≈0），hi/lo 55.28 → 45.82。

### 方法论铁律（新增，与「量级对账」同源）

**加性调制必须先问「注入量能否消掉底噪」。**
若 `x0` 含与调制量**统计独立**的随机分量，且调制量的输入里没有 `x0`，
则 `cos(x0 + Δ, x_tar)` 的上限恒为 0，与 |Δ| 大小无关。
此时任何 loss 加权、幅值放大、phase_scale 调整都是徒劳。
修法只有一个：**让 Δ 的输入包含 x0**（Δ := f(cond, x0) − x0），
或直接把 x0 换成条件预测量（Δ := θ̂ − x0）。

★ 推广判据：见到「指标卡在 0 附近不动、调 loss 无效」，
先算**信息论天花板**，再怀疑 loss。

### 第二十八死穴的**第二例：幅度侧 a0 抖动**（同构病）

θ̂ 模式投150 步后视觉是**近乎均匀灰场**（`_cmp.png` 实看，std 仅 1.71/1.83），
ac1=0.187、hi/lo 从 55.28降到 3.07。高频不爆了，但对比度整体塌成灰雾。

探针 `scripts/diag_a0_ceiling.py`：

| dlna 情形 | log 域平均绝对误差 |
|---|---|
| dlna 依赖 a0（理想修正） | **0.000000** |
| dlna 独立于 a0（取最优常数增益） | **1.7180**，σ=0.8 抖动 100% 残留 |

★ **乘性注入 ≠ 能消抖动**。`a0·exp(dlna)` 能整体平移分布、能改σ，
但消不掉**逐位置独立抽样**的随机结构 —— 这点与直觉相反，第一反应
容易误判成"幅度侧没问题"。落到像素域就是灰雾。

修法（与相位侧完全同构）：`to_amp` 输出改为**目标幅度预测 â**
（softplus 保正），`dlna = log(â) − log(a0)`，抖动被完全抵消。
`supervise` 新增 `a_hat` 参数：监督 `log(â)` 而非 dlna（同"不监督派生物"原则）。

验证 `scripts/diag_amp_hat_mode.py`：两次不同 a0，log 域 max|err| 3.576e-07，
差异 0.00e+00 ⇒ 完全抵消。

### ★ 教训：`hi/lo` 下降不等于变好

thetahat150：hi/lo 55.28→3.07（素材 0.01）看似大幅改善，
实际是**整体塌成灰雾**换来的。只看单一"变小"的指标会把
失真方向误判为进步。必须同时看 ac1 + sobel + std + **看图**。

###受控实验 `scripts/diag_stack_authority.py`

| 指标 | 值 |
|---|---|

| **corr(log a_out, log a_tar)** | **+0.1969（幅度只剩 20%）** |

⇒ **给模型一份完美的初态，物理栈跑完只剩噪声水平。**
这是**架构天花板**，不是训练不足。

### ★★ 为什么此前所有"物理栈无罪"的结论都是错的

`diag_stack_layerwise.py`（cos 从 0.0007 只走到 −0.0266⇒ 判物理栈无罪）
是在**随机初态**下测的。**随机初态本来就没结构**，
在没结构的输入上测不出栈会不会**破坏已有的好结构**。
测栈的**上限**必须喂它完美初态（受控实验），这是两种完全不同的测量。

★ **铁律：要判断某个模块是否"破坏信息"，必须喂它完美输入测上限。
在退化输入上测只能得到"它没变好"，不能得到"它没变坏"。**

### 根因（src/physics/block.py:185）

```python
log_a_new = log_a + res - self.a_gamma * (log_a - self.a_mu.view(1,1,-1))
log_a_new = log_a_new.clamp(-20.0, 5.0)
a_new = torch.exp(log_a_new)
```

`a_mu` 初值 `log1p(0.05)=0.0488`（此处实际用 `log(0.2)=-1.609`），
而 target 的 log1p(a) 均值在 0.3~2.1 量级。
⇒ **每层都在往一个远低于 target 的常数 μ 收敛**，
12 层累积 = 幅度结构被抹平 + 整体放大失真（实测 0.840→1.248）。

相位侧因为 Kuramoto 是**辛的/保结构**（cos 保住 78%），
所以θ̂ 修复见效；幅度侧的 OU 回复力是**耗散的**，问题全在这里。

### 与「禁止注入数据先验」铁律的关系

不能用 target 谱初始化 μ。所以修法方向必须是
**让 FFN 残差 res 有能力补偿系统性偏移**（res 已经在，但被 tanh(±e²)
与 μ 竞争压住），而非改 μ 初值。可选：
  1. 提高 res 的表达上限 / 减弱 γ 的耗散（改物理核，需权衡）
  2. 给每个 block 一个**可学习的 per-block 层级偏置**（不是 target 先验，
     是让层级收敛目标可学）
  3. 训练时初态给 target、生成时才用条件初态（teacher forcing 式的
     课程学习，先证明上限可达，再补条件通路）

### 当前所有实验的重新解读

- 之前几十轮调 loss 权重全部无效 ⇒ **架构上限就在那里**
- 第二十七/二十八死穴（量级对账、θ0 随机）确实是真 bug，已修，
  但**修完仍不够**，因为瓶颈在物理栈
- hat2_150 的灰雾（std 1.48）= 条件初态预测得再好，也被栈搅烂

## 用户质疑「是不是没有解码器」的排查（2026-10-19）

用户直觉：向量不可能直接还原成图片，缺解码器。**排查结论：可排除。**

### 硬数据（scripts/diag_codec_pure.py，纯解析，绕开 uint8/GIF/重采样）

| 测试 | 结果 |
|---|---|
| rfft2 网格 | (5, 25) = **125 = D，恰好填满，无截断** |
| 频域往返 max\|rfft2(irfft2(z))−z\| | **3.815e-06**（相对 1.589e-07，浮点级） |
| decode 输出 | 30×128×128×3，std 40.57，帧内相邻行差 3.204 |

⇒ `decode_field_to_frames` 是**参数为零的确定性精确逆**，
输入正确 field 就精确还原像素。**加可学习 decoder 不会有任何信息增益。**

### ★ 踩过的坑：测codec PSNR 时基准口径必须与 encode 一致

encode 内部有 `resample_frames(frames, TS=6)`（把 30 帧插值压成 6 个时间片），
decode 再按 WIN 展开回 30 帧。
第一次测基准直接用原始 30 帧 ⇒测出 **13.68 dB / 最大误差 255**，
看起来像 codec 坏了，其实是苹果比橘子。
另一次经uint8+GIF 重编码的往返测出相对误差 8.37e-03，
那也是 uint8 量化 + 时间重采样造成的，**不是 codec 的锅**。

★ **铁律：任何往返测试的基准必须走与被测代码完全相同的变换路径。
有损环节（uint8/GIF/重采样）会污染「可逆性」结论。**

### 结构上谁扮演了「解码器」

- `decode_field_to_frames`：固定逆 FFT，参数 0，精确
- `StandingWaveFFN`：输出 2D（幅度残差 + 相位残差），
  **实际上承担了「学出来的解码器」的角色**

所以不缺解码器，缺的是这个学出来的部分**有能力把结构送到输出端**。

### 最终定位（与第二十九死穴同一件事）

瓶颈 = 12 层物理栈在**破坏**已正确的幅度结构
（corr 0.197、PSNR 13.28 ≈ 噪声基线 13.03）。
修法必然要动 `block.py:185` 的 OU 幅度递推。

## 用户方案：第 4 路条件 = 3D FFT 场（探针已验证方向正确）

设计约束：RTX3050 仅 4GB，`hidden(512)→N×D(768K)` 全连接 OOM（1.46GB/层）。
⇒ 必须**逐位置解码器**：第 n 位置只看自己 2D 个 FFT 系数 + 少量全局低秩上下文，
参数量与 N 解耦（0.15M），显存 O(D)。

600 步结果（**完全不经物理栈**）：

| 配置 | cos | corr(log幅度) | 像素 std（目标 80.10） |
|---|---|---|---|
| 逐位置 + 全局0 | +0.2749 | **+0.8398** | 3.10 |

### ★ 关键对比

**幅度 corr 0.85 是完全不经物理栈拿到的**，
而物理栈跑完后只剩 **0.197**（第二十九死穴实测）。
⇒ FFT 条件通路在幅度维度上有**数量级优势**，
且它逐位置自带完整答案，不需要网络去"猜"全局结构 —— 这是 CLIP 向量做不到的。

### 但当前接法还差一环

corr 0.85 而像素 std 只3~5（目标 80）⇒ **幅度绝对尺度差 16~26 倍**。
FFT 系数极度重尾（p50=0.023 / p99=4.647，跨 200 倍），
均值化 MSE 被中位数主导，尖峰学不到。

试了**逐通道能量比log 差**（第十六死穴修法）：
  corr 0.85 → **0.36**（掉一半），std 比 0.60
⇒ **这个口径在本场景是错的**：per-channel 能量比只管通道间比例、
不管逐位置形状，把空间结构丢了。第十八死穴说的"平均值骗人"，
在通道维度上又成立一次。

★ **教训：能量比口径不能盲目套用。** 它解决的是"通道间比例"，
代价是牺牲"逐位置形状"。FFT 场需要的是**两者都要**的损失
（如形状项 + 尺度项分开加权），单用任一个都不行。

### 待决策（涉及架构大改，不擅自开工）

方案 1（最正）：FFT 场作第 4 路**逐位置旁路**，
     直连PMNNCore 初态（θ̂/â 模式），CLIP 三路仍走全局 cond_vec。
     两者相加/门控融合。
方案 2：把 FFT 场**降维成第 4 个全局向量**拼进 cond_vec（6147→+N'）。
     简单，但违背"逐位置才有答案"的本质。
方案 3：先只做方案 1 的**训练期旁路**（FFT 场只作为额外监督信号，
     生成时不用），先验证"物理栈上限能否被拉开"，再补条件通路。

★ 无论哪个方案，都必须同时解决**幅度绝对尺度**问题，
否则 corr 再高也只是"形状对、亮度全黑"。

   但那是「不同组不同收缩」的坏处；正确做法是**每组各学一个 μ，γ 共享**
4. **Kuramoto 相位**：κ（耦合强度）过大导致全同步。需要加「相位不被过度同步」的约束

### 踩坑

- `register_post_accumulate_grad_hook` 在 **Parameter** 上不是 Module 上（torch 2.5）
  → 改用 `register_full_backward_hook`（gin/gout）
- 不用 `spectral_norm`：它对矩阵做幂迭代归一化，会改数值口径，
  让**全部历史 ckpt 失效**
- 按行号批量替换 Python 源码时破坏了括号结构，逐个 py_compile 才定位到

### 接入第 4 路时的三个坑（全部是"变量作用域"类）

1. **`_CONDPFX` 定义在使用点之后** → NameError。
   Python 模块级代码按顺序执行，白名单必须定义在
   `model = AetherGIFModel(...)` **之前**。
2. **`_h0/_dt2` 在 `if DISC_W > 0` 分支内定义，诊断打印在分支外**
   → DISC_W=0 时 NameError。
   教训：**诊断打印不能假设上游分支一定执行过**。
3. **`_fs` 在旁路分支内赋值，融合点无条件引用** → UnboundLocalError
   （旁路关闭或 N 不匹配时）。
   教训：**融合/诊断代码不能假设上游分支一定执行过**，
   变量一律先初始化为 None 再在分支内赋值。

★ 这三条同源：**跨分支的变量必须先声明，后赋值**。
