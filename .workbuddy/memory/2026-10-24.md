### ★ 口径陷阱（差点误判）

`decode_field_to_frames(normalize=True)` 是 **per-clip 全局 min-max**，会把色差的绝对量一起缩放，
所以用它算的 sat（3.64/3.10）**不能**和训练日志里的 8.9/8.4 直接比。
三者口径不同：
- 颜色 loss 内部：`_decodable()` 返回 **±1 浮点域**
- 训练日志的 "sat 8.9/8.4"：另一套脚本的历史口径
- 素材 sat 5.77/9.90：**uint8 域(0-255)**

**以后报饱和度必须注明口径与域**，否则会得出互相矛盾的结论。

### 下一步攻坚方向（颜色）

- 颜色 = **同一空间频点下三个通道（R/G/B）的 DC 差异**；FFT 后 DC 落在 `c%25==0` 的
  content 列（c=0/25/50/75/100）。若这三条列被学成同幅同相 → 必然灰度。
- 待查：生成场在 content 列上三通道的 amp/phase 差异 vs target 的差异（这是最直接的病灶定位）
- 候选修法（按代价排序）：
  1. 提高 COLOR_W（但 W=2.0 已验证会压垮视频分支 → 需在分支均衡点附近小步试探，如 1.5）
  2. 给**颜色通道差异**单独加一项 loss（不缩放绝对亮度，只约束 R/G/B 间的相对差），
     避免和全局亮度/对比度项打架
  3. 检查 cond_init 是否把颜色信息传进去了（cond_vec 里有 CLIP 图像特征，颜色应可从那里取）

## ★★★ 颜色病灶确诊 + 修法（02:5x，本轮最重要成果）

### 决定性实验一：定位颜色载体

`s_dim = PATCH*PATCH*3 = 4×4×3 = 48`，**颜色通道 ch 是这 48 维的最后一位，周期=3**。
沿 48 维做 rfft 后，三通道差异必然落在 **w = 48/3 = 16**。

用 mask 实验验证（`tools/diag_color_loss.py` 同思路的 mask 测试）：

| 素材 | 完整 sat | 去掉 w=16 | 只留 w=16(+DC) |
|---|---|---|---|
| 8-ball | 6.36 | **0.51**（-92%，颜色消失） | **6.85**（+8%，颜色完整） |
| 前辈前辈 | 9.87 | **2.85**（-71%） | **9.79**（-1%，颜色完整） |

**结论：w=16 是颜色的唯一载体**，对应通道 **c ∈ {16, 41, 66, 91, 116}**（c%25==16 的 5 个时间频段）。
其余 120 个通道对颜色几乎零贡献。

### 决定性实验二：量化病灶

用 `tools/diag_color_loss.py` 逐 w 对比 target 与 color4 生成场的能量：

**8-ball**
- w=16：target 0.616 → 生成 0.103，**只有 16.8%** ← 颜色欠学
- w=0：target 2.10 → 生成 3.01，**143%** ← 亮度过学（过亮）
- w=12/15/17/20：生成是 target 的 13~17 倍 ← 那里生成的是噪声，不是色

**前辈前辈**
- w=16：target 1.140 → 生成 0.139，**只有 12.2%**
- w=0：target 3.18 → 生成 4.29，**135%**
- w=4~13/16/19/20 普遍缺口 0.15~0.49（中高频细节也缺）

**病因一句话**：低频（亮度 DC）过学、**颜色专用频点 w=16 严重欠学**、
中间频段被噪声填满。这也解释了为什么在空间域调 COLOR_W 效果有限 ——
sat 是全局平均量，梯度回传到单个 w 的路径被 25 个频点摊薄。

### 修法（已实施）

在 `src/train/spectral_loss.py` 新增：

```python
def loss_color_band(a_pred, a_tar, win=5, w_fft=25, col_w=16):
    """只对齐 w=col_w 这一列的 per-band log1p 幅度（单频点、独立权重）"""
    Lp = torch.log1p(a_pred.clamp(min=1e-8)).reshape(B, N, win, w_fft)
    Lt = torch.log1p(a_tar.clamp(min=1e-8)).reshape(B, N, win, w_fft)
    return (Lp[:, :, :, col_w].mean() - Lt[:, :, :, col_w].mean()).abs()
```

`train_guided.py` 新增三个环境变量：
- `COL_BAND_W`（颜色频点幅度对齐权重）、`COL_BAND`（默认 16）
- `DC_BAND_W`（**单侧**压 w=0 过亮，只在生成超过 target 时罚，避免整体压暗）

### 但问题也很明确：拉起来的是「彩色噪点」，不是「正确的颜色」

对比图 `outputs/_probe_tmp/color_fix_compare.png`：
- 8-ball 本该**几乎无彩（纯灰球）**，现在被染上**青蓝色杂色斑点**

### 根因（重要认知）

**颜色 = 幅度 + 相位**。我只约束了 w=16 的**幅度**，没有约束**相位**：
- 幅度起来了 → sat 上升 ✅
- 但相位随机 → 色相随机 → 变成"彩色噪点"而不是"正确的红/蓝/灰" ❌
- 而且 w=16 与高频噪点同一区间，加强幅度同时放大了噪点 → hilo 爆

### 下一轮修法（三件事一起）

1. **加 w=16 的相位约束**：`(1 - cos(θ_pred − θ_tar))` 只在 `c%25==16` 的 5 个通道上算，
   色相对齐后才是"正确的颜色"而不是随机彩色
2. **降 COL_BAND_W**：3.0 → 1.2~1.5（8-ball 已到 109.8%，明显过冲）
3. **配 HF_GUARD_W**：压住被一起放大的高频噪点

★ 教训记入长期记忆：**只打幅度频点 = 得到彩色噪点；必须幅度+相位成对约束**。

### 实测结果：彻底退化成「统一彩色噪点」

→ **模型的颜色输出是一个与条件无关的常数**，cond 对颜色的影响被完全抹平。
达标（比值>0.8）的素材：**2/22**（而且那 2 个是过饱和方向达标）。

**红绿蓝紫马赛克噪点**，完全没有结构、没有轮廓。

### 判据同步崩坏

- **hilo 1.07 / 1.67 / 1.91**（素材基准 0.01 / 0.04）→ 高频爆表约 100 倍
- PSNR 10.07 / 8.88 / 7.05，**低于或接近噪声基线** 13.03 / 7.44 / 6.21
- 低频塌陷（判据里明确写"低频塌"）
- 相对判据也从 PASS 变 FAIL

### 失败原因（对比 2 素材成功案例）

| 配置 | 素材数 | COL_BAND_W | COL_PH_W | 结果 |
|---|---|---|---|---|
| colband150_1024b | **2** | 3.0 | **0** | sat 6.33/6.48（素材 5.77/9.90）→ **成功，接近素材** |
| full22_col_1024 | **22** | 1.5 | **2.0** | sat 锁死 20.71，全素材无差别 → **失败** |

**结论：`COL_PH_W`（相位约束）是破坏性主因，22 素材放大了它。**

机制推断：
- w=16 是**高频通道**，本身就混着大量噪声能量
- 强行用 `(1−cos Δθ)` 对齐它的相位 → 模型被逼着在高频塞"结构化但错误"的内容
- 22 素材 + 850 步不够时，模型找到捷径：**全通道统一输出高频噪点**来同时压低
  所有素材的 loss（因为噪点在统计上"平均"地接近任何 target 的高频成分）
- 结果：sat 被噪点撑到固定 20，且与条件完全解耦

### 下一轮策略（回退 + 单变量）

1. **去掉相位约束**：`COL_PH_W=0`
2. 保留幅度约束 `COL_BAND_W=1.5`（2 素材时验证过方向正确）
3. **加强高频守卫** `HF_GUARD_W=4.0`（2.5 不够，hilo 仍爆 100 倍）
4. 从 `color4_resume_1023` 重新出发（**不要从失败的 full22 ckpt 续**）
5. 先跑 **150 步**验证方向，sat 若回到 6+ 再延到 850+

★ 记入长期铁律：**相位约束只对「低频/结构通道」安全；对 w=16 这种高频颜色载体，
强行对齐相位会诱发高频噪点。颜色优先只打幅度，相位靠泛化自然学出。**

### ★ 另修一个真 bug：`_oth = 1 - src` 在 N_SRC>2 时是负索引

`DISC_W` / `MARGIN_W` 两处都写死 `_oth = 1 - src`（"取另一个素材"）。

3. AdamW 的「梯度二阶矩」假设对物理系数不成立：κ/T/ω_d/γ 是动力学系数，

| **8bit 优化器状态** | `train_guided.py` 加 `OPT8BIT=1`，`bitsandbytes.optim.AdamW8bit`（0.50.2 可用） | Adam m/v 4x→2x |

## ★★★★ 真根因：μ_c 全样本共享，导致 sat 锁死成常数（10-25 08:30）

### 纠正前的误判

之前以为「2 素材时能区分（sat 6.33/6.48）」。**用 4 个条件交叉验证后推翻**：

| 素材 | 素材 sat | 4 个条件生成 sat | 比值 |
|---|---|---|---|
| src0 8ball | 5.35 | 6.76 / 6.85 / 6.82 / 6.89 | **1.26~1.29 全过饱和** |
| src1 senpai | 10.58 | 5.80 / 5.93 / 5.76 / 6.00 | **0.54~0.57 全欠饱和** |

**生成 sat 是一个固定常数 6.0~6.9，与素材、与条件都无关**（同素材 4 条件差 <0.15）。
即 **2 素材时也是坍塌的**，之前看到的"差异"是巧合（素材需求恰好跨在常数两侧）。

### 根因（写在代码注释里，一直没被当成问题）

`src/physics/block.py` 递推式：
```python
log_a_new = log_a + res - self.a_gamma * (log_a - self.a_mu.view(1, 1, -1))
```
- `a_mu` 是**全样本共享**的单一 `[d_model]` 向量（初值 `log(0.2)`）
- `a_gamma` 可学习，初值 0.3，实测会学到 0.04~0.5
- 注释原文：**`γ_lvl=0.5 ⇒ 12 块后层级收敛 0.5^12≈2e-4`（初值彻底洗掉，终态层级 = μ_c，与数据无关）**

**即：条件注入的初值 m_0 贡献只剩 2.4e-4，终态层级 ≡ 共享的 μ_c → 所有素材同一张谱 → sat 固定。**

这一条解释了全部现象：22 素材坍塌、2 素材颜色固定、ANCHOR_W 无效（锚只作用相位不作用层级 m）。

### 修复：μ 条件调制（μ = μ_c + head(cond_vec)）

`block.py`：
```python
_mu = self.a_mu.view(1, 1, -1)
if mu_bias is not None:
    _mu = _mu + mu_bias.view(mu_bias.shape[0], 1, -1)
log_a_new = log_a + res - self.a_gamma * (log_a - _mu)
```

`aether_gif_model.py` 新增 `mu_head`（`N_COND3 → 256 → d_model`，**零初始化**），
`mu_bias = MU_SCALE(0.5) · tanh(mu_head(cond_vec))`，`MU_HEAD=1` 开关。

**思想**：收敛到平衡点是物理性质（不该改），但**每个条件应该有自己的平衡点**。

### 参数量与兼容

23.04M → **24.65M**（mu_head 增加 1.6M）。
旧 ckpt 载入 `missing=4`（mu_head 的 4 个参数），零初始化起步不破坏已训好的 μ_c。

### ★ 更硬的证据：这是「模式坍塌」，不只是颜色不对

`full22_col_1024/summary.json` 里 `results.<条件>|src<i>` 是**长度 22 的 PSNR 列表**
（用素材 i 的条件生成 → 与 22 个素材分别比）。实测：

```
文生|src1 = [9.25, 8.85, 6.997, 10.46, 9.94, 9.05, 10.29, ...]
文生|src2 = [9.21, 8.55, 7.028, 10.58, 9.94, 9.12, 10.30, ...]
文生|src3 = [9.21, 8.64, 6.995, 10.52, 9.96, 9.06, 10.33, ...]
文生|src4 = [9.21, 8.60, 6.998, 10.54, 9.97, 9.08, 10.33, ...]
```

**src1~src4 四行几乎逐值相同**（同列差 <0.3 dB）。
→ 用不同素材的条件生成，得到的是**同一张图** → **条件通路整体失效 = 模式坍塌**。
这比"sat 固定"更严重：连空间结构都与条件无关。

**机制**：22 个素材 × 850 步，每个素材只被见约 39 次；模型发现
「输出一张统计上平均的图」能最小化 22 个 target 的平均 loss —— 这是捷径解。

**关键对策（下一轮必须加）**：`DISC_W`（判别 loss）目前一直是 0。
它的设计目的正是"让不同条件的输出互相远离"（`DISC_TGT_COS=0.60`、
`DISC_DTGT_COS=2.0`），**是治模式坍塌的现成武器**，此前从未启用。
