## ★ 网格感根因定位（20:40，用户朋友怀疑"FFT 往返有噪声"）

用户提问：朋友认为噪声来自 FFT 前向/反向传播。**结论：方向对了一半，机制说错了。
真凶是 `spec[:, :d_model]` 的非对称硬截断，不是 FFT 变换本身。**

### 决定性证据（`scripts/diag_grid_source.py`）
| 条件 | std | 边界 | 内部 | **网格比** | PSNR |
|---|---|---|---|---|---|
| 素材 | 80.49 | 22.78 | 21.44 | **1.062** | — |
| **全保留 125 系数（不截断）** | 80.49 | 22.78 | 21.44 | **1.062** | **147.20 dB** |
| 当前实现 前64（非对称截断）| 73.90 | 24.97 | 20.95 | **1.192** | 20.68 dB |
| 矩形低通 h<3,w<13（39系数）| 72.77 | 26.19 | 20.52 | **1.276** | 19.65 dB |
| Hann 窗平滑衰减（全125带窗）| 8.67 | 7.13 | 6.58 | 1.085 | 10.32 dB |

- **FFT 往返零噪声**：全保留时往返误差 5.96e-07（float32 精度极限），
  PSNR 147 dB，网格比 = 素材原值 1.062。**变换本身无噪声、无网格感。**
- 一旦 `spec[:, :64]`，网格比立刻 1.062 → 1.192。**网格感 100% 来自截断。**

### 截断形状是错的（GIF codec 第 276-279 行）
```python
spec = spec.reshape(N, -1)   # [N, 125]，索引 = h*25 + w
z = spec[:, :d_model]        # [N, 64] ← 取前 64 个
```
覆盖区域（# = 保留）：
```
h=0: #########################   全保留
h=1: #########################   全保留
h=2: ##############...........   只留 w=0~13，w=14~24 丢
h=3: .........................   整行丢弃
h=4: .........................   整行丢弃
```
**这不是低通滤波，是"半边低通 + 时间维高频整行砍掉"的非对称矩形窗。**
- 时间频率能量分布：h=0 占 **79.72%**，h=1 7.76%，h=2 2.39%，h=3 2.37%，h=4 7.76%
- h=3,4 合计 **10.1% 能量被完全丢弃**；h=2 的 w=14~24 也丢
- 总保留 89.8% / 丢弃 10.2%
- 对照：真正低通 h<3,w<13（39 系数）保留 88.4% 能量，**能量几乎一样但网格比 1.276 更差**
  → 说明「非对称」本身就是有害的，均匀丢弃反而更糟

### 结论修正（推翻 MEMORY.md 里"网格感是 D=64 截断的结构性产物"的说法）
- 截断**确实**是来源，但**不是"数量不够"，是"取法错了"**。D=64 只是症状。
- 之前记的"D=125 全保留只涨 0.05 dB"是因为**当时也是按前 125 个取**（125 = 全集，等价于不截断），
  那次测的其实是"截断 vs 不截断"，正好证明**不截断 = 147 dB 完美**。
  → **D=64 → D=125 应该能拿回 20 dB 以上**，之前 26.70 vs 26.75 的结论口径有问题，需重测。
- Hann 窗会把 std 压到 8.67（灾难），**不能用窗函数**。原因见下。

### Hann 窗为什么失败（重要陷阱）
`spec * (hann_h[:,None] * hann_w[None,:])` 把 h=0 的直流行（79.7% 能量）也乘上 <1 的窗系数
→ 直流被压 → std 崩到 8.67。**窗函数必须只作用在高频端，保留 h=0 和 w=0 全权**，
即窗在 (0,0) 处必须 = 1.0。任何窗函数方案都要先满足这一条。
