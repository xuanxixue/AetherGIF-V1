# AetherGIF-V1 蓝图：4GB 显存上的振子直生成 GIF 模型

> 基于 PMNN（物理矩阵神经网络）通用底层架构，用振子直接生成 3–10 秒、128×128 的低细节 GIF。
> 硬件约束：RTX 3050 Laptop 4GB / Python 3.12 / PyTorch 2.5.1+cu121
> 参考文档：`AetherMind-V5-300M-Instruct_技术文档.md`、`PMNN物理矩阵神经网络通用底层架构.html`、`技术报告_AetherSentry_Omni_V1.md`

---

## 0. 一句话结论

**能做，而且 4GB 绰绰有余。** 关键是不走「VAE 压缩 + 流匹配生成」的老路，而是让振子本身就是生成机制：把 GIF 切成 4×4 像素 × 5 帧的时空块，每块做一次 3D FFT 直接变成 64 个复值振子，PMNN 物理核在振子场上做相位演化，逆 FFT 拼回去就是 GIF。全程零 VAE、零外部解码器、零额外参数。

## 1. 目标规格

| 项 | 值 | 说明 |
|---|---|---|
| 分辨率 | 128 × 128 | 固定 |
| 时长 | **3–10 秒（可变）** | 训练时分桶，推理时按需 |
| 帧率 | 10 fps | 3s = 30 帧，10s = 100 帧 |
| 帧数范围 | 30–100 帧 | |
| 风格定位 | **线条表情包 / 简笔画 / 扁平动画** | 低细节，大面积纯色 |
| 硬件 | RTX 3050 Laptop 4GB | 训练 + 推理全在本地 |

### 1.1 为什么必须是低细节 GIF

这不是妥协，是架构匹配：

| 性质 | 对振子方案的意义 |
|---|---|
| 调色板 ≤ 8 色，大面积纯色 | 4×4 块绝大部分是 DC 分量，高频系数天然为零 |
| 线条粗、方向明确 | 一个 4×4 块通常只有 1 条边，方向单一 |
| 帧间运动小、渐进 | 5 帧时间窗口内时间频率低 |
| 无纹理、无光照、无阴影 | 不需要高频通道，d=64 是过剩配置 |

**一个 4×4×5 块的真实自由度只有 2–4 个**（一条边 = 方向 + 位置 + 强度 + 时间相位），而 3D FFT 给出 80 个复系数、我们取 64 个。信息密度极低，振子场不需要压缩信息，只需要学「线条该怎么动」。

**反面清单**：不要选实拍切片、自然纹理、粒子特效、复杂光影的 GIF。这类内容高频系数不稀疏，64 维截断会丢细节，且 4GB 上 N=20480 的训练吞吐会很难看。

## 2. 核心设计：振子直接生成，不套 VAE

### 2.1 之前被否掉的方案

| 被否方案 | 否掉理由 |
|---|---|
| SD VAE 压缩 + 潜空间流匹配 | VAE 是外部统计模型，振子只是塞在中间当装饰，等于把 PMNN 降级成「物理注意力模块」；且 VAE 解码 100 帧在 3050 上要 40–60 秒 |
| 像素级 patch 直接生成 | 128×128×100 = 1.64M 像素，N 太大，训练一步都跑不动 |
| 逐帧生成 + 插值 | 时间一致性没有结构性保证 |

**PMNN 的核心命题是：振子本身就是生成机制，复值场就是表示，相位动力学就是演化。** Un-0 已经证明纯 Kuramoto 相位动力学可以直接生成图像（ImageNet-64 FID 6.74），GIF 只是把振子网格从 2D 扩到 3D。

### 2.2 整体链路

```
原始 GIF (128×128×3, 30–100 帧)
   │
   ├─[1] 预处理：resize → 灰度化/调色板归一 → 10fps 重采样
   │
   ├─[2] 时空分块：4×4 像素 × 5 帧 → 每块 80 个实数值
   │
   ├─[3] 3D FFT → 80 个复系数 → 取 64 个最低频
   │      → z_i = a_i·e^(iθ_i)，a=|z|，θ=arg(z)
   │
   ├─[4] PMNN 物理核（12 轮，振子相位演化）
   │
   ├─[5] 逆 3D FFT（高频补零）→ 4×4×5 块
   │
   └─[6] 拼回 128×128×帧数 → 量化 → GIF 编码
```

编解码（步骤 3/5）是**固定数学变换，零参数、零显存**。只有步骤 4 有可学习参数。

## 3. 振子网格设计

### 3.1 分块与网格

| 维度 | 原始 | 分块 | 振子网格 |
|---|---|---|---|
| 空间 X | 128 px | 4 px | 32 |
| 空间 Y | 128 px | 4 px | 32 |
| 时间 | 30–100 帧 | 5 帧 | **6–20（可变）** |

- 空间振子数：32 × 32 = **1024**（固定）
- 时间步数：帧数 / 5，向下取整（末尾不足 5 帧的补最后一帧）
- **总振子数 N = 1024 × T_step**

### 3.2 各时长对应的 N

| 时长 | 帧数 | 时间步 T_step | 振子数 N |
|---|---|---|---|
| 3 s | 30 | 6 | **6,144** |
| 4 s | 40 | 8 | 8,192 |
| 5 s | 50 | 10 | 10,240 |
| 6 s | 60 | 12 | 12,288 |
| 7 s | 70 | 14 | 14,336 |
| 8 s | 80 | 16 | 16,384 |
| 9 s | 90 | 18 | 18,432 |
| 10 s | 100 | 20 | **20,480** |

### 3.3 变长处理：PMNN 天然支持

这是选 PMNN 的一个额外红利。AetherMind 技术文档 §8.5 明确写了「不 pad 变长前向」：

> 物理核心所有跨位置运算都按当前序列长度 N 动态计算，变长天然可跑。

所以：

- **训练**：按 T_step 分桶组批（沿用 §8.2 的 `bucket_batches` 思路），同桶内 batch 化，不做跨桶补齐
- **推理**：想要多长的 GIF 就直接构造对应 N 的噪声场，物理核按 N 动态计算
- **避坑**：不要用左 padding。AetherMind §8.5 记录过左 padding 会让驻波位置编码被污染、`<eom>` 概率从 0.0000 飙到 0.9998 导致生成塌缩

### 3.4 每振子维度

d = **64** 复通道（来自 4×4×5 块的 64 个最低频 3D FFT 系数）。

## 4. 编解码：3D FFT 同构映射

### 4.1 编码（GIF → 振子，只用于构造训练目标）

对每个 4×4×5 块（80 个实数值）做 3D FFT，得到 80 个复系数。按频率从低到高排序，取前 64 个：

```
z_{i,c} = FFT3D(block_i)[c],  c = 0..63

a_{i,c} = |z_{i,c}|      # 该时空模式的振幅（强度/能量）
θ_{i,c} = arg(z_{i,c})   # 该模式的相位（位置/结构关系）
```

对线条表情包，第 64–79 号高频系数几乎恒为零，**截断误差 ≈ 0**。这不是压缩，是同构嵌入。

### 4.2 解码（振子 → GIF）

```
block_i = Re(IFFT3D(pad64→80(z_{i,:})))   # 高频补零，取实部
```

拼回 (32×4) × (32×4) × (T_step×5) = 128×128×帧数，clip 到 [0,255]，量化成 GIF 调色板。

### 4.3 为什么用 FFT 不用 DCT

DCT 只给实系数，没有相位。FFT 直接给复系数 = 天然振子（幅度 → 振幅，辐角 → 相位），跟 PMNN 的 `z = a·e^(iθ)` 表示**零成本对齐**。这是这套设计最省事的地方。

## 5. PMNN 物理核心

### 5.1 参数对照表

| 组件 | AetherMind 300M（文本） | AetherGIF-V1（GIF） | 理由 |
|---|---|---|---|
| 物理块层数 L | 16 | **12** | 视频时空冗余比文本高，层数可减 |
| 通道数 d | 1024 | **64** | 由 FFT 截断维数天然决定 |
| FFN hidden | 4096 | **256** | 降 FFN 是主要省算力项 |
| 耦合秩 r | 96 | **32** | UN-0 稀疏性结论支持 |
| 振子数 N | ≤128（训练） | **6,144–20,480** | 可变长 |
| 驻波参考长度 | wave_ref_len=512 | **(20, 32, 32)** | 3D 时空，见 5.3 |
| 漂移场原型数 | 32 | **16** | GIF 模式种类远少于词表语义 |
| 输出头 | lm_head → 8192 词表 | **逆 FFT → 像素** | 零参数 |

### 5.2 单轮物理块数据流（沿用 AetherMind §5，不改结构）

```
(a, θ) [N, 64]
   ├─→ DriftField ──→ g                        ← V⁺ − λV⁻，复值距离 fp32
   ├─→ KuramotoSync(κ(t), g) ──→ θ_new         ← Euler dt=0.1，折叠回 [−π,π]
   ├─→ StandingWaveFFN(ω_d(t)) ──→ ffn_out     ← 洛伦兹共振 × 3D 驻波
   ├─→ a_new = softplus(LN(a + ffn_out))       ← 振幅非负；相位不做 LN
   └─→ Thermodynamics(κ, T) ──→ {U, S, F, r}   ← 诊断，不参与梯度
```

12 轮串联，每轮物理时间 t = i/(L−1)。

### 5.3 关键修改一：3D 驻波基

AetherMind 的一维驻波 `SW_m(p) = cos(2π(m+1)p/N_ref)` 只处理序列位置。视频要改成三维：

```
SW_{m_t,m_x,m_y}(t, x, y) = cos(2π m_t·t / T_ref) · cos(2π m_x·x / X_ref) · cos(2π m_y·y / Y_ref)
```

参考长度取振子网格尺寸：**T_ref=20, X_ref=32, Y_ref=32**。

> 必须沿用 P1-1 修复口径：N_ref 是固定的参考长度，**不能**用运行时序列长度。否则 3s（T_step=6）和 10s（T_step=20）下同一个 m 对应不同绝对波数，跨时长迁移直接报废。这是变长 GIF 最容易踩的坑。

### 5.4 关键修改二：双时间轴

必须分清两个「时间」，实现里搞混会出玄学：

| 轴 | 范围 | 作用 |
|---|---|---|
| **物理时间** t ∈ [0,1] | 深度方向 12 轮 | κ(t) 耦合强度课程、T(t) 温度退火、ω_d(t) 频率扫描沿这条轴走 |
| **数据时间** t_data ∈ {0..T_step−1} | GIF 帧序 | 作为振子的空间坐标之一参与耦合和驻波 |

两者正交。数据时间轴通过 **Toeplitz 因果衰减**实现时间一致性：

```
W_ij = exp(−λ_t·|t_i − t_j| − λ_s·‖p_i − p_j‖²)

λ_t：时间衰减（跨帧距离）  建议初值 0.5
λ_s：空间衰减（同帧内空间距离）  建议初值 0.3
```

这样「第 5 帧与第 6 帧的耦合」必然强于「第 5 帧与第 40 帧」——**结构性先验，不需要学**。零参数，纯结构。

### 5.5 时间场配置

沿用 AetherMind §4.1 的三条曲线，只改数值适应视频：

```
κ(t) = κ_max · σ((t − t_c)/τ_c)     # κ_max=8.0, t_c=0.5, τ_c=0.15
T(t) = T_max(1−t)^p + T_min          # T_max=1.0, T_min=0.05, p=1.5
ω_d(t) = ω_lo · (ω_hi/ω_lo)^t        # 由 natural_freq 低/高分位均值给出
```

`natural_freq` 保持 `nn.Parameter`，让时间场课程本身可训练（梯度可回传），否则是死参数。

### 6.2 推理

| 项 | 大小 |
|---|---|
| PMNN 权重 | 2 MB |
| 激活（无反向） | ≈ 150 MB（10s 档） |
| **总计** | **< 200 MB** |

|---|---|---|

## 7. 训练

### 7.1 目标构造

每个训练 GIF：预处理 → 分块 → 3D FFT → 目标振子场 (a*, θ*)。

### 7.2 初始化（推理同款）

```
θ ~ U(−π, π)          # 随机相位
a ~ softplus(N(0,1))  # 随机振幅
```

从噪声相位积到干净相位，这就是生成。训练时也用这个初始化。

### 7.3 损失

```
L = ‖θ_final − θ*‖²                                    # 相位对齐
  + ‖a_final − a*‖²                                    # 振幅匹配
  + λ_time · Σ_t relu(ε − ‖θ_{t+1,:} − θ_{t,:}‖²)      # 时间运动单边 hinge
```

**λ_time 用单边 hinge，不用 L2**（沿用 AetherMind §7 的 L_F 口径）：

```python
# 正确：只在帧间差过小时惩罚
L_time = torch.relu(eps - frame_diff).sum()    # eps = 0.05

# 错误：会奖励运动无限增大
# L_time = frame_diff.pow(2).sum()             # ← 不要这样写
```

### 7.4 三个必备护栏（从 AetherSentry 直接搬）

这三条是 AetherSentry 用一次重大失败换来的，不分场景，硬性要求：

**① 不在同一自由度上施加冲突约束**

AetherSentry §7.4 的根因：`l_sync`、`l_F`、`l_loc` 三项都在把 `r_seq` 推向 1，而定位判据 `d_sync = 1 − r_seq`，等于在最小化判据本身。30 epoch 后 `d_sync` 从 0.61 掉到 0.30 并方向反转。

> **规则：不要用一个量同时当「指标」和「被最小化的正则项」。**

本项目中：如果你想监控「视频里有多少动作」，用帧间差分能量作**只读指标**，不要让它进任何 loss。

**② 引入 F = U − T·S 前，确认 S 和 U 在同一坐标系**

AetherSentry §8.3：`U` 依赖时间维序参量、`S` 依赖通道维振幅分布，两者正交。加 `−T·S` 根本触不到 `r_seq` 饱和通路，梯度全落在振幅通道，窗口级从 0.6470 崩到 0.4563。

> **规则：引入「看起来正确」的项之前，先确认它与问题处在同一个自由度上。**

本项目中：S（振幅分布熵）在视频里可能全部落在空间通道，而你想修的问题在时间通道。若要加 F，S 必须显式计算在时间维度上（帧间振幅分布熵）。

**③ 配权 / 超参不跨 checkpoint 通用**

AetherSentry §5.5：14ep 权重需要正 `w_sync`，30ep 需要零/负（方向已反转）。这条规则两次阻止错误结论。

> **规则：换权重必须重扫配权，绝不能沿用旧值。**

本项目中：阶段 B 调好的 λ_time，阶段 C 必须重扫。

### 7.5 训练阶段

| 阶段 | 目标 | 冻结 | 数据 | 判据 |
|---|---|---|---|---|
| **A. 编解码验证** | 验证 3D FFT 64 维截断在线条 GIF 上的重建误差 | 物理核全冻结 | 500 GIF 抽样 | 截断 PSNR > 35 dB 才继续 |
| **B. 相位演化预训练** | 从噪声相位积分到目标振子场 | 无 | 5k–10k GIF | 训练不 OOM，单步 < 3s（3s 档） |
| **C. 时间一致性微调** | 开启 Toeplitz 时间耦合 + 时间 hinge | 无 | 同 B | 帧间相位差方差 > 0.1（非静帧） |

阶段 B 是主战场，占总训练量约 80%。

## 8. 推理

```
1. 指定时长 → 查表得 T_step → N = 1024 × T_step
2. 采样噪声场：θ ~ U(−π,π)，a ~ softplus(N(0,1))
3. PMNN 12 轮物理演化（Euler dt=0.1）
4. 取末轮 (a, θ) → 重组 z = a·e^(iθ)
5. 逆 3D FFT（64→80 补零）→ 取实部 → clip
6. 拼回 128×128×帧数 → 量化 → GIF
```

**没有 VAE 解码这一步**，也没有流匹配的 ODE 迭代采样。整个推理就是一次前向 + 一次确定性数学变换。3050 上预计 **2–5 秒出一个 GIF**。

## 9. 头号失败模式：全同步坍缩到静帧

这是视频生成独有的风险，文本模型里不存在。

### 9.1 机理

物理时间末段 κ(t) → 7.72（AetherMind §9 实测值），所有振子相位趋于一致。如果**时间通道**也锁死，所有帧变成同一张图，GIF 变成静态图片。

### 9.2 三道护栏

**(1) 时间通道 κ 单独控制，比空间小一个量级**

```
κ_time ≈ 0.2 × κ_space
```

**(2) 监控帧间相位差方差**

```python
frame_diff = (theta[t+1] - theta[t]).reshape(T_step-1, -1)
var = frame_diff.var()
# 每步记录。趋 0 = 锁死，立即调小 κ_time
```

**(3) 时间 hinge 只罚不动**

见 §7.3，`relu(ε − diff)` 形式。

### 9.3 验收指标

| 指标 | 阈值 | 含义 |
|---|---|---|
| 帧间相位差方差 | > 0.1 | 不是静帧 |
| 末层 r | 0.4–0.8 | 空间同步但未全坍缩 |
| r ≡ 1.0 且帧间无差异 | — | **已坍缩，停训** |

### 10.3 筛选流水线（关键：筛掉细节复杂的 GIF）

下载后必须过一遍筛选，只保留低细节的：

```python
# 伪码：低细节筛选
def is_simple_gif(gif_path) -> bool:
    frames = load_all_frames(gif_path)          # 解码全部帧
    if not (30 <= len(frames) <= 100):          # 3–10 秒 @ 10fps
        return False

    # ① 调色板颜色数：线条表情包通常 ≤ 8 色
    palette = unique_colors(frames)
    if len(palette) > 16:
        return False

    # ② 纯色区域占比 > 60%（大面积平坦）
    flat_ratio = mean(run_length_per_row > 8)
    if flat_ratio < 0.60:
        return False

    # ③ 空间边缘密度 < 15%（线条少）
    edge_ratio = sobel_edges(frames[0]) / (128*128)
    if edge_ratio > 0.15:
        return False

    # ④ 帧间运动存在但平滑（SSIM 0.5–0.95）
    ssim = mean_pairwise_ssim(frames)
    if not (0.5 < ssim < 0.95):
        return False

    return True
```

| 筛选维度 | 阈值 | 淘汰什么 |
|---|---|---|
| 调色板颜色数 | ≤ 16 | 实拍、复杂渐变 |
| 纯色区域占比 | > 60% | 纹理密集型 |
| Sobel 边缘密度 | < 15% | 细节丰富的插画 |
| 帧间 SSIM | 0.5–0.95 | 静帧（太高）/ 高频抖动（太低） |
| 时长 | 3–10 s | 超出目标规格 |

**TGIF（102K）里预计只有 10–20% 能过筛**，剩下约 1–2 万个，够用。Noto Emoji 全部能过筛但只有约 1,500 个，作为「干净种子集」先跑通流程。

## 12. 风险与替代方案

### 12.1 风险矩阵

| 风险 | 严重度 | 缓解 |
|---|---|---|
| 全同步坍缩（静帧） | **高** | §9 三道护栏 |
| 时间一致性差（闪烁） | **高** | Toeplitz 时间衰减耦合 + 时间 hinge |
| 64 维 FFT 截断丢细节 | 中 | 阶段 A 先验 PSNR；线条 GIF 高频稀疏，风险低 |
| 跨时长迁移断裂 | 中 | 驻波 N_ref 固定（P1-1 口径），不用运行时长度 |
| 4GB 训练碎片化 | 中 | `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` |
| 数据筛选后量不够 | 中 | TGIF + Noto + VTuber 三源合流 |

### 12.2 如果质量不够

| 方案 | 代价 | 收益 |
|---|---|---|
| 分块从 4×4×5 改 4×4×2 | N 翻 2.5 倍，激活 ~750MB | 时间分辨率翻倍，运动更细腻 |
| d 从 64 提到 128（加可学习投影） | +400 MB | 表达力翻倍 |
| L 从 12 提到 24 | +300 MB | 更深物理演化 |
| 两阶段：先 64×64 生成再 3D 超分 | 加一个 ~2M 参数超分网 | 训练成本降 4 倍 |

### 12.3 如果 4GB 实在吃不下

降级到 **64×64 分辨率 + 8×8 空间分块**：N 直接降到 1/4（10s 档 5,120 振子），训练显存 < 200MB，代价是分辨率减半。只作为保底，不建议起步就用。

## 13. 一句话总结

4GB 生成 3–10 秒 128×128 低细节 GIF 完全可行：**4×4×5 时空分块 + 3D FFT 同构映射**把 GIF 变成 6,144–20,480 个复值振子，PMNN 物理核在振子场上做 12 轮相位演化，逆 FFT 拼回去就是 GIF；编解码零参数，训练 < 700MB，推理 < 200MB；数据从魔搭 / hf-mirror / Noto Emoji 三条国内线路下载，严格筛选低细节 GIF；头号失败模式是全同步坍缩到静帧，用独立的时间 κ + 帧间差方差监控 + 单边 hinge 三道护栏防住。
