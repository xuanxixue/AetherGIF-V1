# AetherSentry Omni V1 技术报告

**副标题**：基于 PMNN v0.1 物理矩阵神经网络的生成式网络入侵精准定位系统

**版本**：V1（交付版）
**数据集**：CIC-IDS2017
**硬件约束**：RTX 3050 Laptop 4GB 显存 / Python 3.12 / PyTorch 2.5.1+cu121
**交付配置**：14 epoch 权重 + 融合配权 `(w_sync=1.25, w_energy=−0.75, mean)`

---

## 摘要

网络入侵检测的现有范式是**报警**：给定一个流量窗口，输出一个异常分数，超过阈值就告警。
这个范式在天花板处遇到一个结构性限制——当窗口内同时存在攻击流量与正常流量（本文称
**混合窗口**）时，报警器只能说"这个窗口有问题"，却**说不出是哪一条**。在本项目使用的
CIC-IDS2017 数据集中，混合窗口占全部窗口的相当比例，这意味着报警范式在最需要精度的
场景里退化为随机猜测。

AetherSentry Omni V1 提出并验证了另一种范式：**锁定**。它不做"这个窗口异常"的判断，
而是直接输出窗口内 64 条 flow 中**每一条**的定位分数、每条 flow 的**逐维特征归因**、
以及该异常在残差签名空间中属于**哪一种攻击模式**（无监督，不依赖标签）。定位能力由
PMNN v0.1（物理矩阵神经网络通用底层架构）的生成式重建残差提供，其核心是一个把
Kuramoto 相位耦合、共振-驻波前馈、漂移场以及热力学自由能统一在同一条状态方程里的
物理主干。

在 CIC-IDS2017 上，Omni 以 **53,825 参数**取得窗口级 AUROC **0.8244**，领先次优的
Flash-Win（0.7654）**5.9 个百分点**，而参数量仅为 Pro-Time（356,059）的 **1/6.6**。
在 Omni 独有的两个口径上：逐 flow 定位 AUROC **0.8239**；混合窗口 top-1 命中率
**0.5658**（报警范式的随机基线 0.3768，**1.50×**）；攻击模式无监督聚类纯度 **0.7237**
（随机基线 0.4086，**1.77×**），且已接近同 checkpoint 的有监督探针上界（0.6694）。

本报告同时**完整、不粉饰地**记录了一次重大失败：把训练规模从 14 epoch 扩大到
30 epoch 后，重建损失从 0.627 降到 0.169（训练/验证几乎重合，无经典过拟合特征），
但**定位指标全面退化**（窗口级 0.8046 → 0.6470）。我们用四组对照实验把根因钉死为
损失项 `λ₄ · l_F` 单向压制了定位判据本身所依赖的物理量 `r_seq`；随后**又用两组实验
排除了两条最自然的修复路径**（替换损失形式、调整权重强度）。这两次"失败的修复"
本身构成了本报告最有价值的部分——它们把问题精确定位到了"约束对象/约束形状"这一层，
而不是停留在调参层面。

## 1. 引言

### 1.1 问题背景

网络入侵检测系统（IDS）的工程目标长期被表述为一个二分类问题：给定一段流量记录，
判断它是否为攻击。围绕这个目标，学术界与工业界发展出了从签名匹配、统计异常检测到
深度序列模型的完整方法谱系。这些方法在"单条流量的二分类"上已经相当成熟，
但在真实部署中会遇到一个被系统性低估的困难：

**真实网络流量在时间上是不均匀的。** 一次端口扫描可能在 200 毫秒内产生上百条 flow；
一次 DDoS 洪泛会在几秒内灌入数万条连接；而扫描/洪泛之间的探测间隙里，同一窗口内
同时存在正常业务流量。工程上把流量按固定窗口切片后，**窗口内部几乎必然混合了
攻击 flow 与正常 flow**。

在本项目使用的 CIC-IDS2017 数据集上，按 W=64（每窗口 64 条 flow）切片后共得
**44,182 个窗口**，其中含攻击的窗口 **16,011 个（36.2%）**。而在含攻击窗口中，
**同时含正常 flow 的"混合窗口"有 11,738 个**——占含攻击窗口的 **73.3%**。

对报警范式而言，这 11,738 个窗口是无法处理的：模型对窗口内 64 条 flow 输出**同一个**
异常分数，因此当它判定"该窗口异常"时，运维人员拿到的信息**不包含**"是哪一条 flow
触发的"。若要在窗口内挑出一条 flow 来处理，最合理的策略是均匀随机选择——
命中率恰好等于"攻击 flow 在窗口中的占比"，也就是 **0.3768**。

这就是报警范式的**结构性天花板**：不是模型不够强，而是**输出形态里根本没有定位信息**。
提高模型的分类准确率无法突破这个天花板，因为天花板不在准确率上，在输出维度上。

### 1.2 从"报警"到"锁定"的范式转换

AetherSentry 系列的前三代模型（Flash / Pro / Max）都在报警范式内迭代：
Flash 用六大物理组件加外挂双层结构，Pro 用内嵌 MoE 四专家，Max 走"物理即主干"的
OFSS 五元组路线。三代模型的输出都是一个标量异常分。

Omni 这一代换掉了输出形态。它落到 PMNN v0.1 的完整四段链路，用**生成式重建**作为
异常判据的来源：

1. 模型只看正常流量训练，因此学会了"正常 flow 长什么样"；
2. 推理时，对窗口内每一条 flow 都做一次重建，得到重建残差 `r_flow = ‖x_i − x̂_i‖₂`；
3. 残差天然是**逐 flow** 的量，因此定位信息**内建在输出形态里**，不需要额外的
   分割头或注意力解释器。

关键区别在于：前三代对窗口内 64 条 flow **给同一个分**，其定位能力上限**等于随机猜**。
Omni 用生成式重建残差把定位做到 **1.50× 随机基线**，且这是在同一份权重上、
同时保住窗口级指标（0.8244，仍是四代最高）的前提下做到的——**"锁定"没有牺牲"报警"**。

### 1.3 本报告的组织

第 2 节交代 PMNN v0.1 的理论基础与统一状态方程；第 3 节给出 Omni 的工程实现；
第 4 节展开三层锁定机制；第 5 节专门讨论融合配权的方法论（这是本项目踩坑最多的地方）；
第 6 节报告全部实验结果；第 7 至第 9 节是一个完整的失败分析三部曲——
现象、根因、两次失败的修复；第 10 节归纳可复用的工程教训；第 11、12 节给出诚实的
局限与未来工作。

## 2. 理论基础：PMNN v0.1

### 2.1 物理矩阵神经网络的出发点

PMNN（Physical Matrix Neural Network）v0.1 的出发点是一个不太常见的类比：
**把神经网络的隐状态看作一个多体物理系统，把前向传播看作这个系统随时间的演化。**

主流深度学习的隐状态是实值向量，层间变换是矩阵乘法加非线性激活。PMNN 的做法是
把隐状态取成**复值场** `z = a · e^{iθ}`，其中幅值 `a` 承载"强度/能量"信息、
相位 `θ` 承载"关系/结构"信息。这个取法带来两个直接好处：

第一，**相位提供了一个天然的相对量**。在实值网络里，"两条 flow 是否相似"必须由
网络自己学出，而在复值表示里，相似性可以直接写成相位的接近程度——这正是
Kuramoto 模型描述"耦合振子能否同步"的语言。

第二，**涌现式的同步现象可以被直接用作判据**。当一组振子相位趋同时，序参量
`r = |mean(e^{iθ})|` 会从 0 升向 1；当它们分散时，`r` 保持低位。这个量是**无参数**的，
不依赖任何学习到的阈值。

### 2.2 统一状态方程

PMNN v0.1 的核心是把四个看似独立的模块统一进一条状态方程：

$$\frac{dZ}{dt}=\underbrace{M_\kappa(t)\cdot Z}_{\text{结构算子}}+\underbrace{\nabla_Z[-U+T\cdot S]}_{\text{自由能梯度}}+\underbrace{v_\varphi}_{\text{漂移场}}+\underbrace{\eta(t)}_{\text{涨落}}$$

四项分别对应：

- **结构算子** `M_κ(t)·Z`：由 K 值导航总线调度的相位耦合。核心是 Kuramoto 耦合项，
  用 Toeplitz 结构的权重矩阵 `W` 描述振子间的相互作用强度；
- **自由能梯度** `∇_Z[−U + T·S]`：`U` 是"有序化"能量，`S` 是熵。`−∇U` 驱向锁相，
  `+T∇S` 驱向均匀。温度 `T` 由总线按余弦调度从 `T_max` 退火到 `T_min`；
- **漂移场** `v_φ`：整流流匹配的速度场，承担生成任务；
- **涨落** `η(t)`：噪声项，提供采样随机性。

### 2.3 自由能与相位同步的同源性

PMNN v0.1 原文点破了一个容易被忽略的恒等式：**§3.4 的 XY 能量梯度正是 §3.1 的
Kuramoto 耦合项**。

$$\frac{\partial}{\partial\theta_i}\Big(-\sum_{ij}W_{ij}\cos(\theta_j-\theta_i)\Big)=\sum_j W_{ij}\sin(\theta_j-\theta_i)$$

也就是说，"相位同步"与"热力学-熵"在数学上**不是两个并列模块**，而是同一个自由能
`F = U − T·S` 的两面：`−∇U` 驱向有序（锁相），`+T∇S` 驱向均匀（熵压）。

**这个同源性是后文第 8 节全部失败分析的理论起点。** 它既解释了为什么 `l_F` 想
"对抗有序饱和"是很自然的想法，也埋下了一个陷阱：`U` 与 `S` 虽然同属一个自由能，
但**它们依赖的自由度并不相同**——这一点在第 8.2 节会被实验无情地揭示出来。

## 3. 架构实现

### 3.1 总体链路

Omni 的完整前向链路分四段：

```
                    ┌──────────── K 值导航总线 κ(t) · T(t) · ω_d ────────────┐
                    │                                                        │
  x [B,T,D]   ┌─────▼──────┐   ┌──────────────────────────────────┐   ┌──────▼──────┐
  ───────────▶│ ① 正子编码 │──▶│ ② 物理核心（K 步 ODE 数值求解）  │──▶│ ③ ELF 输出  │
              │ z = a·e^iθ │   │  §3.1 相位同步(Kuramoto+W矩阵)   │   │   融合      │
              └────────────┘   │  §3.2 共振-驻波 FNN              │   │ 整流流匹配  │
                               │  §3.3 漂移场 V⁺−λV⁻              │   │ v_θ(x_t,t)  │
                               │  §3.4 热力学-熵 F=U−T·S          │   └──────┬──────┘
                               │  §3.5 Heun/RK4 时间物理          │          │
                               └──────────────────────────────────┘   ┌──────▼──────┐
                                                                      │ ④ 反嵌入+门控│
                                                                      │ E + mode g(t)│
                                                                      └──────────────┘
```

输入端是 `x [B, T, D]`，本项目取 `T=64`（窗口内 flow 数）、`D=80`（每条 flow 的
特征维数：77 维数值列 + 3 维行为列，行为列保持原尺度不做标准化）。

### 3.2 正子编码层

第一段把实值输入提升到复值场：`z = a · e^{iθ}`。这一步的关键是**幅值与相位的职责分离**：

- **幅值 `a`** 承载"这条 flow 的某个特征有多强"——它是**能量通道**，后文
  `e_flow = mean_c |z_c|` 直接取自这里；
- **相位 `θ`** 承载"不同特征之间的相对关系"——它是**相位通道**，后文
  `r_seq`（序参量）与 `d_sync = 1 − r_seq` 都在这里。

**这次编码设计在事后被证明是理解整个退化问题的钥匙**：两个通道承载不同信息、
参与不同的损失项、并且在失败模式上互相独立。第 8 节的全部结论都建立在这个分离之上。

### 3.3 物理核心

第二段是 Omni 的主体，包含五个子模块：

**§3.1 相位同步层**：Kuramoto 耦合 `∑_j W_ij sin(θ_j − θ_i)`，`W` 采用
Toeplitz 结构（`W_ij = w_{|i−j|}`），参数随距离衰减，这让"邻近 flow 更容易同相"
成为一个**结构性先验**而非学习结果。序参量 `r_seq = |mean_c(z/|z|)|` 在此计算。

**§3.2 共振-驻波 FNN**：前馈部分不是普通的 MLP，而是构造为"驱动频率与外场频率
共振"的形式，允许解呈现驻波结构。这使得网络能在相位之外保留一定程度的
周期性表征能力。

**§3.3 漂移场**：`V⁺ − λV⁻` 形式的双分量漂移，正向分量负责把样本推向数据流形，
负向分量负责把样本推出低密度区。这与后面的 ELF 流匹配配合，共同承担生成职责。

**§3.4 热力学-熵**：自由能 `F = U − T·S`，其中
`U = −(r_t²).mean(dim=1)`、`S` 是通道维振幅分布（标准化后过 softmax）的归一化熵。
**注意这两个量的依赖维度**：`U` 依赖**时间维**的序参量 `r_t`，`S` 依赖**通道维**的
振幅分布。这个正交性是第 8 节的核心。

同时提供 `entropy_force()`：`+T∇_aS` 的显式等效形式，把振幅往均值拉（均匀化）。
低温时 `T` 小、熵压弱，振幅可分化以承载重建信息；高温时熵压强，探索性增强。

**§3.5 时间步进**：支持 Heun / RK4 两种数值积分。在 4GB 显存约束下最终采用
`HEUN=False, INTEGRATE_STEPS=4` 的配置（见 3.6）。

**K 值导航总线**在整段上方横贯，把"时间场"与"热力学"翻译成各层的调度标量：

- `κ(t) = κ_max · σ((t − t_c)/τ)`：同步相变强度，S 型课程调度；
- `T(t) = T_min + (T_max − T_min)·cosine(进度)`：温度退火，本项目
  `T_min=0.1, T_max=1.0`，实际训练期 `T ≈ 0.32`。

Max 只有 `κ(t)` 与 `T(t)` 两根轴；Omni 额外把**流匹配时间 `t` 也接进总线**，
使"物理退火时间"与"生成流时间"共用一根轴——这是"物理核心即速度场"这一命题的前提。

### 3.4 ELF 输出融合

第三段是 ELF（Embedding-Latent-Field）输出融合，承担生成任务：

- **整流流匹配（Rectified Flow）**：学习速度场 `v_θ(x_t, t)`，把噪声沿直线路径
  输运到数据分布。相比扩散模型，整流流的采样路径更直，少步数下质量更好——
  这对 4GB 显存下的推理预算是决定性的；
- **反嵌入 + mode 门控**：把隐空间表示 `E` 与模式门控 `g(t)` 组合，输出重建 `x̂`。

重建残差 `r_flow = ‖x_i − x̂_i‖₂` 是三层锁定的**第一层（空间锁定）的物理来源**，
同时也是诊断中判别力最强的单分量（单独 AUROC 0.78）。

### 3.5 参数规模与显存约束

Omni 的**唯一参数量为 53,825**（`core` 与 `elf` 共享主干）。这个数字在同类工作中
非常小：Pro-Time 是 356,059，Flash-Win 是 57,518，Max 是 44,330。Omni 用与
Flash 同量级的参数拿到了全面领先的指标。

4GB 显存带来的约束直接影响了实现：

- **减少"前向次数"比优化"单次算子耗时"更有效**。早期版本的 `omni_loss`
  要跑 3 次物理前向 × Heun 6 步 × 2 = 36 次算子求值，autograd 图峰值达 8GB，
  约 **16.8 秒/step**；压到 4 次求值后降到 **339 毫秒/step、2.07GB**，
  **约 50 倍加速**。这成为本项目最关键的一处工程优化。
- WDDM 模式下 Windows 的显存管理会被其他桌面进程（如 QQ.exe）挤占，
  训练前需要确认显存可用性，否则会触发 CUDA OOM。

## 4. 三层锁定机制

Omni 的输出不是单一分数，而是三层可解释的定位结果，外加一层物理证据。

| 层 | 输出 | 含义 | 是否 Omni 独有 |
|---|---|---|---|
| 空间锁定 | `flow_score [B,T]` | 窗口内**哪一条** flow 是攻击 | ✅ |
| 特征锁定 | `attrib [B,T,D]` + `topk_feats` | 该 flow **哪几维**特征异常 | ✅ |
| 模式锁定 | 残差签名聚类（`mode_lock.py`） | 它是**哪一种攻击模式**（无监督） | ✅ |
| 物理证据 | `sync / energy` | **为什么**判它异常 | ✅ |

### 4.1 空间锁定

定位分由三个可读分量融合而成：

```
flow_score = g(r_flow) + 1.25·g(d_sync) − 0.75·g(e_flow)

  r_flow = ‖x_i − x̂_i‖₂      重建残差（逐点主力，单独 AUROC 0.78）
  d_sync = 1 − r_seq_i       相位失同步
  e_flow = mean_c |z_i,c|    场能量（负权重）
  g(·)   = 全局统计量标准化（非逐窗口 z-score）
```

三个分量各自的物理含义清晰可读：重建做得多差、相位有多散、能量有多高。
这个"可读性"是设计目标之一——运维人员看到的不应只是一个黑箱分数。

### 4.2 特征锁定

`attrib [B,T,D]` 是残差的**逐维归因**：对每条被判异常的 flow，给出 80 维特征中
每一维的异常贡献，并按 top-k 输出最可疑的几维。这一层把"哪条 flow"进一步细化到
"这条 flow 的哪个字段不对"，是排查工作最直接的抓手。

### 4.3 模式锁定

第三层回答"这是哪一种攻击"。做法是**无监督**的：对全部攻击 flow 计算重建残差的
**归一化方向签名** `attrib = |x − x̂| / ‖x − x̂‖`，在这个签名空间里做 KMeans 聚类。
聚类过程**不使用任何标签**，簇标签与真实攻击类型之间没有任何对应关系——
纯靠签名方向对齐。评估时把簇标签与真实类型做匹配，得到纯度（purity）。

### 4.4 物理证据层

`sync / energy` 两个量给出"为什么判它异常"：相位失同步说明该 flow 的相对关系
与正常模式偏离；场能量说明其幅值结构异常。这两个量与 `r_flow` 相互独立，
构成一种三源交叉验证的读法。

## 5. 融合配权方法论

本节单独成章，因为配权是本项目**踩坑最多、也最容易产生错误结论**的地方。

### 5.1 三个分量的物理含义

三个分量来自不同的物理量，量纲不同、值域不同，**不能直接相加**：

- `r_flow`：重建残差的 L2 范数，正值，随异常程度单调增；
- `d_sync = 1 − r_seq`：相位失同步度，`r_seq ∈ [0,1]` 因此 `d_sync ∈ [0,1]`；
- `e_flow`：场能量，正值。

### 5.2 全局标准化 vs 逐窗口 z-score

早期版本对三个分量做**逐窗口 z-score**——这在直觉上更"干净"，因为每个窗口内部
都被拉到 μ=0、σ=1，分量之间可比。

**但逐窗口 z-score 只能做窗口内排序。** 一旦评估目标是窗口级（跨窗口比较），
逐窗口标准化会把窗口之间的**绝对差异抹平**——每个窗口看起来都一样"峰谷分明"，
但峰值的绝对高度信息已经丢失。实测窗口级 AUROC 会掉到 **0.4315（低于随机）**。

正确做法是用**全局统计量**标准化：`g(v) = (v − μ_global) / σ_global`，
其中 `μ_global, σ_global` 在全体样本上一次性统计（`fit_loc_stats`）并冻结。
这样窗口内排序与窗口间可比性同时得到保留。

### 5.3 负权重的发现

初版对三个分量做等权相加，结果 `r_flow` 单独 AUROC **0.7883**，融合后反而掉到
**0.5268**——**融合把一个强信号稀释掉了**。

按判别力配权后仍有问题：`e_flow` 单独 AUROC 不高（约 0.71），粗网格扫描时
`w_energy=−1.5` 把窗口级从 0.8052 抬到 0.8305，代价是逐 flow 从 0.8046 掉到 0.7855。
据此曾判定"应取 `w_energy=0`"。

**这个判定是错的**，错在只看单口径。细网格扫描发现
`(w_sync=1.25, w_energy=−0.75)` 让**两个口径同时提升约 2 个百分点**。
原因由分层分析（`_resid.py`）揭示：

- `corr(r_flow, e_flow) = +0.77`——两者高度冗余；
- 控制住 `r_flow` 后，`e_flow` 的层内方向**反转为 0.298**。

也就是说，`e_flow` 的独立判别力不高，是因为它携带的信息与 `r_flow` 大量重叠；
减去它实际上是在**做去冗余**，把 `r_flow` 里混入的"能量成分"剥离出来。
**负权重不是"惩罚一个弱信号"，而是"消除一个强信号的冗余分量"。**

### 5.4 CV2 严格验证协议

配权是在同一份数据上选出来的，存在选择偏差风险。为此设计了 **CV2 协议**：

1. 把数据随机分成 A、B 两半；
2. **只用 A 半**扫描配权、选出最优配置；
3. 把 A 半选出的配置**原样**拿到 B 半上评估；
4. 重复 30 次独立分半，对配对差值做 t 检验。

结果（30 次全胜）：

| 选择目标 | 窗口级（新 vs 原） | 逐 flow（新 vs 原） |
|---|---|---|
| win | 0.8211 vs 0.8054（**胜 30/30**，t=+22.16） | 0.8041 vs 0.8039 |
| flow | 0.8070 vs 0.8054 | 0.8339 vs 0.8039（**胜 30/30**，t=+30.96） |
| **both** | **0.8230** vs 0.8054（胜 30/30） | **0.8249** vs 0.8039（胜 30/30） |

A 半选出的配置高度一致（`1.25/−1.0` 9 次、`1.25/−0.75` 9 次、`1.0/−1.0` 7 次），
说明**新配权是真实效应而非过拟合**。

### 5.5 交付配权

最终交付配置为 `(w_sync=1.25, w_energy=−0.75, agg=mean)`。相对原始配置 `(1.5, 0.0)`：

| 口径 | 原始 | 交付 | 变化 |
|---|---|---|---|
| 窗口级 AUROC | 0.8246 → | 0.8244 | +1.98 pp（相对 0.8046 基线） |
| 逐 flow AUROC | 0.8239 | 0.8239 | +1.96 pp |
| 混合窗口 top-1 | 0.5658 | 0.5658 | **+6.11 pp**（1.34× → 1.50×） |

另在 **8,000 窗口独立子集**上复核混合窗口 top-1 为 0.5081 → 0.5593（+5.1 pp），
与全量幅度一致，排除抽样偶然。

**最重要的方法论结论**：**融合配权不能跨 checkpoint 通用。** 同一个 `d_sync`：
14ep 权重需要**正**权重（`w_sync=1.5 → 0.8052`，`1.25 → 0.8244`），
30ep 权重需要**零/负**权重（`w_sync=1.5 → 0.6505`，`3.0 → 0.4574`，方向已反转）。
**换权重必须重扫配权，绝不能沿用旧值。** 这条规则在后续实验中两次阻止了错误结论，
也一次差点被我违反（见 8.4）。

### 6.7 评估协议细节

评估的两个口径在实现上差别很大，值得单独说明，否则数字容易被误读。

**口径 A（窗口级报警）**：把窗口内 64 条 flow 的 `flow_score` 聚合为一个窗口分
（本项目用 `mean`），然后对全部 44,182 个窗口计算 AUROC / AUPRC。
这是与 Flash / Pro / Max 唯一可比的口径，因为前三代只输出窗口分。

**口径 B（逐 flow 精准锁定）**：不做聚合，直接把全部 44,182 × 64 = 2,827,648 个
flow 级分数与其逐 flow 标签做 AUROC / AUPRC。这一口径**只有 Omni 能产出**，
因为前三代的输出里根本没有 flow 级分数。

**混合窗口 top-1**：只在"窗内既有攻击又有正常"的 11,738 个窗口上计算。
对每个这样的窗口，取 `flow_score` 最高的那条 flow，看它是否真的是攻击 flow。
随机基线由该窗口的攻击占比决定，全体平均为 **0.3768**——这正是报警范式
（窗内同分）能达到的上限。

**阈值口径的说明**：逐 flow F1 使用 q=0.95 分位数作为阈值，把正例率压到 5%，
而真实攻击 flow 占比远高于此。这是为了在"误报率受控"的实用场景下报告性能，
但代价是 F1 数值偏低（0.5649）。因此**横向比较应以 AUROC / AUPRC 为准**，
它们与阈值无关。

**同协议原则**：所有对照实验（含全部失败分析实验）必须使用同一份数据、
同一 `W=64`、同一评估脚本、同一随机种子。诊断脚本 `_diag.py` 强制要求
指定 `--n-win` 与 `--seed`，就是为了保证跨 checkpoint 的对照是干净的。

## 7. 全量训练退化：现象与根因

### 7.1 现象

把训练规模从 14 epoch / 15,000 正常窗口扩大到 **30 epoch / 25,354 正常窗口**后：

| 指标 | 14 epoch | 30 epoch | 变化 |
|---|---|---|---|
| 训练重建 loss | 0.627 | **0.169** | ↓ 大幅改善 |
| 验证重建 loss | — | 0.16867 | 与训练几乎重合 |
| 窗口级 AUROC | 0.8046 | **0.6470** | **↓ 退化** |
| 逐 flow AUROC | 0.8043 | **0.6511** | **↓ 退化** |
| 混合窗口 top-1 | 0.5047 | **0.3852** | **↓ 退化到随机** |

这是一个**非常反直觉**的现象：重建质量大幅提升（loss 降到 1/4），
训练与验证几乎重合（无经典过拟合特征），但定位指标全面崩溃，
混合窗口定位甚至退化到随机基线（0.3768）。

**"训练得更充分"反而变差了**——这说明问题不在泛化，而在**训练目标本身**。

### 7.2 排除法实验矩阵

为定位根因，设计了三组单变量对照实验（全部 30 epoch / 25,354 窗口，同协议）：

| 实验 | 权重文件 | 改动 | `d_sync` 逐 flow AUROC | 结论 |
|---|---|---|---|---|
| full | `omni_cic_30ep_regress.pt` | 基线（λ₄=0.10, λ₂=0.05, λ_loc=0.05） | **0.3005** ❌ 反转 | 退化复现 |
| nosync | `omni_cic_nosync.pt` | 关 λ₂=0, λ_loc=0 | **0.2710** ❌ 反转 | **不是正则的锅** |
| **nofree** | `omni_cic_nofree.pt` | **关 λ₄=0** | **0.6729** ✅ | **✅ 元凶锁定** |

同时发现一个重要的**保护性事实**：

| 分量 | 14ep | 30ep full | 30ep nosync | 30ep nofree |
|---|---|---|---|---|
| `r_flow` 重建残差 | 0.7863 | 0.7862 | 0.7782 | — |
| `d_sync` 去同步 | **0.6133** | 0.3017 | 0.2710 | **0.6729** |
| `e_flow` 场能量 | 0.5928 | 0.7028 | 0.7699 | — |

**`r_flow` 在所有配置上都是 0.78 左右**——**PMNN 的重建/生成能力自始至终完好无损**。
崩掉的只是定位分量的**性质**，不是模型本体。这一条直接关系到项目目标
"PMNN 的核心生成能力不能丢"——它是保住的。

### 7.3 元凶锁定

`d_sync` 与 `λ₄` 呈现**严格的同开关关系**：唯一改动 `λ₄`，`d_sync` 从 0.3005
（跌破随机基线，**方向反转**）回到 0.6729（反超 14ep 交付版的 0.6067）。
终态 `l_sync` 同步从 0.0013 回到 0.0807（**×62**）。

而关掉正则（nosync）后 `d_sync` **反而更糟**（0.2710 < 0.3017）——
**正则不是元凶**。

### 7.4 机理

三项损失都在把 `r_seq` 推向 1：

- `l_sync = mean((1 − r_seq)²)`：显式地要求 `r_seq → 1`；
- `l_F = mean(U)`，其中 `U = −(r_t²).mean`：最小化 `U` ⟺ 最大化 `r_t²` ⟺ `r_seq → 1`；
- `l_loc = std(r_seq)`：最小化它要求 `r_seq` 在不同 flow 间**尽量一致**。

而定位主力分量是 `d_sync = 1 − r_seq`——**这三项损失合起来等价于在最小化定位判据本身**。
模型于是学会了"无论输入什么都输出全同步"，`d_sync` 从独立判据退化成噪声，
甚至方向反转。叠加选优判据 `vl` 也含 `l_sync`，等于专门挑"把 `d_sync` 压得最死"
的那个 epoch，构成**双重伤害**。

**这是本项目最重要的一条工程结论**：

> **不要用一个量同时当"异常指标"和"被最小化的正则项"。** 那等于亲手把判据驯化成常量。
> 物理量若要承担判别职责，训练目标里就不能压它的绝对值。

## 8. 两次失败的修复尝试

根因明确后，很自然会想到两条修复路径。**两条都失败了**，而失败的方式各自
提供了重要的信息。

### 8.1 尝试一：改用完整自由能

第一个想法来自 PMNN 原文：既然 `l_F` 只取了自由能的**能量项** `U`，而完整的自由能是
`F = U − T·S`，其中 `−T·S` 正是"对抗有序饱和的那一半"，那就该用完整 `F`。
`aux["F"]` 一直存在却没用。跨项目实证也支持这个方向：Max 的 NSL 任务上，
完整 `F` 版（0.9141）确实优于残缺 `U` 版（0.8957）。

实现只用一行：

```python
l_F = (aux["F"] if getattr(cfg, "L_F_MODE", "U") == "F" else aux["U"]).mean()
```

并在 30 epoch 上做单变量对照实验（`omni_cic_freefix.pt`）。

### 8.2 结果：不仅是无效，而且有害

**训练期**：`l_sync` 与 `l_loc` 的轨迹与基线**逐位重合**（27 轮，四位有效数字），
`Δ(l_F) = −0.2838 ± 0.0034` 是近似常数。第一眼看起来像"这个改动没生效"。

**但 val 列与分量诊断显示两版不是同一个解：**

| epoch | B `l_fm` | full `l_fm` | B `l_energy` | full `l_energy` |
|---|---|---|---|---|
| 5 | 0.42006 | 0.42072 | 0.21703 | 0.21585 |
| 20 | 0.28279 | 0.27973 | 0.10023 | 0.09842 |
| 30 | 0.25734 | 0.25407 | 0.08691 | 0.08524 |

`Δval ≈ −0.0257`，恰好等于 `λ₄ · T·S = 0.10 × 0.284 = 0.0284`。

**权重无关的分量诊断（同协议 n=3000 / seed=0）：**

| 分量（逐 flow AUROC） | full 30ep | freefix（F 版） | 判读 |
|---|---|---|---|
| `r_flow` 重建残差 | 0.7837 | 0.7840 | 逐位相同 |
| **`d_sync` 去同步** | 0.3009 ❌ | **0.2938** ❌ | **未被修复** |
| **`e_flow` 场能量** | 0.7123 | **0.8296** | **+0.117，唯一大变** |
| 口径 A 窗口级 | 0.6470 | **0.4563** | **低于随机** |

全量评估：窗口级 **0.4563** / 逐 flow **0.4327** / 混合窗口 top-1 **0.3748
（0.99× 随机）**——**这是全部实验中最差的一版，甚至低于随机基线**。

### 8.3 机理：通道正交

答案藏在 `free_energy()` 的实现里：

```python
a  = z.abs()                                   # 通道幅值
p  = softmax((a − mean(a)) / std(a), dim=-1)   # 标准化后沿通道 softmax
S  = −Σ p·log p / log(C)                       # 归一化熵 ∈ [0,1]
U  = −(r_t²).mean(dim=1)                       # 只依赖时间维序参量 r_seq
F  = U − T·S
```

- **`U` 依赖时间维的序参量 `r_seq`**——这正是退化发生的地方；
- **`S` 依赖通道维的振幅分布**——它的来源就是 `e_flow`。

两者**在坐标系上正交**。所以加 `−T·S` **根本触不到 `r_seq` 饱和通路**，
梯度全部落在振幅通道，把 `e_flow` 推强；而融合权对 `e_flow` 是**负**的
（`w_energy=−0.75`，用于修正它与 `r_flow` 的冗余），推得越强罚得越狠
→ 窗口级从 0.6470 崩到 **0.4563**。

**教训**：**引入一个"看起来正确"的项之前，先确认它与问题处在同一个自由度上。**
`F = U − T·S` 在符号上确实表达"有序 vs 熵"的对抗，但在**这个架构的坐标系里**，
两个量根本不在同一个通道上。

### 8.4 一次判读失误与更正（诚实记录）

基于"`l_sync`/`l_loc` 27 轮四位数吻合 + `Δ(l_F)` 近似常数"，
我曾在报告中判定"**熵项无梯度 ⇒ 该改动是 no-op**"。

**这个推理是错的。** 常数偏移只说明熵项对损失**数值**的贡献稳定，
**推不出它对参数没有梯度**。val 列（`l_fm` 系统性差约 1.3%）与分量诊断
（`e_flow` AUROC 0.7123 → 0.8296）都证明两版不是同一个解。

这条更正已被永久记录在 `docs/failure_analysis.md` §9.0 中。
**判读规则更新**：判定"两次改动是否等价"，必须覆盖 **val 列与各分量通道**，
而不是只看与自己假设相关的那几个数。

### 8.5 尝试二：λ₄ 强度扫描

既然形式变换无效，第二条路径是只调**强度**——在交付骨干同一规模
（14ep / 15,000 窗口）上扫 `λ₄ ∈ {0.01, 0.03, 0.05}`，与 `λ₄=0.10` 逐项可比。

**训练期（单调、干净）：**

| `λ₄` | 终态 `l_sync` |
|---|---|
| 0.01 | 0.1048 |
| 0.03 | 0.0200 |
| 0.05 | 0.0116 |
| 0.10 | 0.0049 |

**`λ₄` 确实是控制 `r_seq` 饱和速度的正确旋钮**——这一点已被四组实验交叉确认。

**评估期（每格独立重扫配权后的 split-half holdout，公平口径）：**

| λ₄ | holdout 窗口级 | in-sample | 各自最优配权 | 逐 flow | 该格 `d_sync` 逐flow |
|---|---|---|---|---|---|
| 0.01 | 0.8057 | 0.8007 | (1.0, −1.5, mean) | 0.7216 | **0.7545** |
| 0.03 | 0.7545 | 0.7737 | (0.7, −0.7, mean) | 0.7358 | **0.3486** ❌反转 |
| 0.05 | 0.7984 | 0.8023 | (2.0, −1.5, mean) | 0.7369 | 0.7217 |
| **0.10（基线）** | **0.8259** | **0.8352** | (1.5, −1.5, p90) | **0.7855** | 0.6067 |

**裁决：三格 holdout 全部低于基线 0.8259。`λ₄=0.10` 保持最优，交付版无需改动。**

> **一次差点犯的错**：若图省事、直接沿用为 `λ₄=0.10` 调好的配权去评估三格，
> `λ₄=0.05` 会给出混合窗口 top-1 **0.5769**，**看起来反超交付版的 0.5658**。
> 但配权不跨 checkpoint 通用，此读数不成立。每一格独立重扫后，
> 它的 holdout 只有 0.7984，远低于基线。**这是 §5.5 那条规则第二次救回一个错误结论。**

### 8.6 一个意外发现：非单调性

`d_sync` 逐 flow AUROC 随 `λ₄` 的变化**不是单调的**：

| λ₄ | 0.01 | **0.03** | 0.05 | 0.10 |
|---|---|---|---|---|
| `d_sync` 逐flow AUROC | **0.7545** | **0.3486** ❌ | 0.7217 | 0.6067 |

中间的 `λ₄=0.03` **崩塌到方向反转**，而两侧的 0.01 与 0.05 都健康。
这说明退化**不是"推力大小"的单调节点问题**，而存在**共振式的不稳定区**——
`l_F` 与 `r_seq` 之间存在非线性耦合。

这个发现直接改变了 v1.1 的方向选择：既然单纯调小 `λ₄` 会撞上不稳定区，
修复就应该在**约束形状**上动手（例如给 `r_seq` 加单边上限，只惩罚超过 0.95 的部分），
而不是继续在权重数值上打转。

## 9. `d_sync` 的窗口级甜点

§8.5 中出现了一个需要解释的现象：`λ₄=0.01` 的 `d_sync` 逐 flow 判别力**最强**
（0.7545，远超基线的 0.6067），窗口级却只有 0.8057。而 `λ₄=0.10` 的 `d_sync`
逐 flow 较弱（0.6067），窗口级却最高（0.8259）。

为拆解这个 gap，用离线脚本 `_win_gap.py`（读 sweep 缓存，不占 GPU）在**同一样本**上
（n=8000，`yw` / `lf` 逐位一致）做了对照：

| 权重状态 | 训练期 RMS(1−r_seq) | 逐flow `d_sync` | 窗口级 `d_sync` | 失效形态 |
|---|---|---|---|---|
| 30ep full | 0.036（最低） | **0.3005 反转** | 低 | **推太狠 → flow 级反转** |
| **14ep（交付骨干）** | **0.070（中）** | 0.6067 可用 | **0.7326 强** | **✅ 两端都在可用区** |
| 30ep nofree | 0.284（最高） | **0.6729 强** | **0.5618 反转** | **不推 → 窗口级反转** |

**决定性判据**：只保留 `r_flow + w_sync·d_sync`，看加正权重时窗口级 AUROC 是升还是降：

| | w_sync=0 | 0.5 | 1.0 | 1.5 | 2.0 | 3.0 |
|---|---|---|---|---|---|---|
| **14ep** | 0.6692 | 0.7414 | 0.7864 | 0.8052 | 0.8120 | **0.8137** 单调↑ ✅ |
| **nofree** | 0.6528 | 0.6413 | 0.6271 | 0.6189 | 0.6145 | **0.6092** 单调↓ ⚠️ |

**nofree 的 `d_sync` 在窗口级是反向的**——这解释了为什么它的最优配权是 `w_sync=0`。
铁证：把 14ep 的最优配置 `(1.5, −1.5, p90)` 强加到 nofree 上 →
**0.8305 崩到 0.5905（−0.24）**。不是配权没调好，是**方向反了**。

**核心结论**：`d_sync` 的窗口级可用性存在一个**甜点**——

- 推得太狠（30ep full）：`d_sync` 在 **flow 级**反转；
- **不推（λ₄=0）：`d_sync` 在窗口级反转**；
- **只有中间（14ep）两端都在可用区**。

所以 `λ₄=0` **不是修复**，而是把失效模式从一个方向换成了另一个方向：
对 30ep 是改善（口径 B 0.6511 → 0.7702），但窗口级 0.7294 + 口径 B 0.7702
**两项皆输给 14ep 的 0.8244 / 0.8239**。

同时得到一个反直觉的推论：**14ep（15k 窗口 / 14 epoch）在窗口级与 flow 级双料最优**
——"训练规模越大越好"在本架构上是错的，`λ₄` 的破坏是**随训练轮数累积**的。

### 9.5 诊断工具链

本节的全部结论来自一套五件的诊断工具链。它们的职责边界清晰，且刻意设计成
**尽量不占 GPU、可与其他任务并行**，这对 4GB 单卡环境是必要的。

| 工具 | 职责 | 关键设计 |
|---|---|---|
| `_diag.py` | 定位分量拆解：分别给出 `r_flow` / `d_sync` / `e_flow` 的单独 AUROC / AUPRC，以及正常/攻击 flow 上的均值与分位 | 支持 `--ckpt` 做多权重对照，**强制同 `--seed` 同 `--n-win`**，否则对照无效 |
| `_sweep.py` | 融合配置网格扫描（含**负权重**方向），给出 Top-10 配置 | 首次运行把分量原始值 dump 成 `_sweep_v2_*.npz` 缓存，之后重扫仅需数秒 |
| `_cv.py` / `_cv2.py` | 配权稳健性：重复随机分半交叉验证 + 配对 t 检验 | CV2 协议规定"A 半选参、B 半独立报告"，消除选择偏差 |
| `_resid.py` | 分层分析：控制 `r_flow` 之后各分量的真实方向 | 这是发现 `e_flow` 负权重必要性的关键一步 |
| `_win_gap.py` | 窗口级 gap 诊断 | **完全离线**，只读 npz 缓存，不占 GPU，可与训练并行 |

**一个重要的设计选择**：`_diag.py` 与 `_sweep.py` 的分工是刻意的。
`_diag.py` 回答"**每个分量单独有多强**"，`_sweep.py` 回答"**怎么组合最好**"。
两者混在一起会导致一个常见错误：看到某分量单独强就以为它该拿大权重——
而 `e_flow` 正是反例（单独 0.71，最优权重却是负的）。

**npz 缓存的隐性价值**：缓存把"重新分析"的成本从"一次完整前向（约 6 分钟）"
降到"一次矩阵运算（秒级）"。这使得**在不占 GPU 的前提下反复回到同一批数据做
新假设的检验**成为可能——§9 的甜点分析、§8.4 的交叉配权验证都是这样完成的。
在单卡、且训练经常占满显存的环境里，这个能力比它看起来更重要。

## 10. 工程实践与教训

### 10.1 配权方法论（五条）

1. **融合别把强信号稀释掉**。等权相加把 `r_flow` 的 0.7883 稀释到 0.5268。
   必须先单独测每个分量的判别力，按判别力配权。
2. **归一化方式决定口径**。逐窗口 z-score 只能做窗口内排序；跨窗口比较必须用
   全局统计量标准化，否则窗口级 AUROC 会掉到 0.5 以下（实测 0.4315）。
3. **聚合方式要实测**。窗口级用 `mean` 显著优于 `max`/`p90`/`top-k`——
   `max` 会被正常窗口里个别高残差 flow 拉高，判别力反降。
4. **单项"无正贡献"≠ 该系数应设为 0**。必须做细网格**双目标**扫描。
   只看单口径会漏掉组合效应（`e_flow` 的负权重即为一例）。
5. **配权不跨 checkpoint 通用**。同一个 `d_sync`：14ep 需要正权重，
   30ep 需要零/负权重（方向已反转）。**换权重必须重扫。**

### 10.2 实验设计（三条）

6. **超参在测试集上选，必须 split-half 复现**。本次 A 半选参 0.8099 →
   B 半独立复现 0.8187（偏差 −0.0089），证明非过拟合。
7. **"两次 run 某几列四位数吻合"不足以判定改动等价**。必须覆盖 val 列与各分量通道。
   我曾据此误判"no-op"，差点漏掉一个有害改动。
8. **损失项与判据要在同一"坐标系"里**。`l_F` 与问题不在同一个自由度上，
   加它只会在错误的通道上加力。

### 10.3 训练目标设计（一条，最重要）

9. **不要用一个量同时当"异常指标"和"被最小化的正则项"。**
   `d_sync` 是定位主力判据，而 `l_sync`、`l_F`、`l_loc` 三项都在压 `r_seq → 1`。
   训练越久，判据越失效（30ep 时单独 AUROC 从 0.61 掉到 0.30 并反转）。

### 10.4 工程实现（三条）

10. **4GB 显存下，减少"前向次数"比优化"单次算子耗时"更有效**。
    36 次求值 → 4 次求值带来约 50 倍加速（16.8 s/step → 339 ms/step）。
11. **Python 3.12 的 `sys.path` 不含脚本目录**，入口脚本需显式
    `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))`。
12. **训练在写 checkpoint 时，别让其他脚本读同一个文件**。
    推理脚本必须支持 `--ckpt` / `--device`，用已验证的备份权重 + CPU 跑，
    与训练彻底隔离。

### 10.5 工具使用（两条）

13. **改 Python 文件后必须 `ast.parse` 校验**。编辑工具若 `old` 含行尾换行而
    `new` 不含，会**吞掉换行**把两行粘成一行；在 f-string 里手写 ASCII 双引号
    也会提前截断字符串。
14. **带 ASCII 双引号的代码片段不要走字符串精确替换**，
    改用脚本按行定位重写更稳（本项目在 `aux["U"]` 上踩过）。

## 11. 局限（诚实标注）

1. **窗口级 F1 口径不统一**：各代阈值口径不同（Omni 用 q=0.95 分位数，
   把正例率压到 5% 而真实异常率 36%），故 F1 不宜横向比较；
   AUROC / AUPRC 与阈值无关，是主要判据。

2. **训练轮次被 `λ₄ · l_F` 锁死在 14 epoch**。当前 checkpoint 为 14 epoch /
   15,000 正常窗口。扩大训练规模反而退化（30ep 窗口级 0.6470 vs 14ep 0.8046），
   元凶已由 `λ₄=0` 实验钉死。**但两条最自然的修复路径都已被实验排除**：
   - **换形式（U→F）**：`S` 与退化所在通道正交，反而把窗口级推到 0.4563；
   - **调强度（A′ λ₄ 扫描）**：三格 holdout 全部低于基线，且发现非单调不稳定区。
   v1.1 必须换**约束对象**（跨样本方差）或**约束形状**（单边上限）。

3. **混合窗口 top-1 为 0.57**：攻击在时间上常连续成段，定位分最高点可能落在
   攻击段边缘而非中心；top-5 / top-10 已达 **0.75 / 0.83**，
   说明"定位到邻域"是可靠的。

4. **CIC 单数据集**：尚未在 NSL-KDD 或跨数据集上验证泛化性。

5. **模式锁定只做到"物理族"粒度**：11 类攻击仅聚出 3 个主导族
   （洪泛 / 扫描 / 爆破），同族内的细分类型（如 DDoS 与 DoS Hulk，二者都是洪泛）
   区分不足。精细类型识别需引入签名之外的时序上下文特征。

6. **模式锁定是无监督的，不应与有监督分类比**：报告纯度时同时给出随机基线与
   有监督探针，是为了避免"用聚类碰运气"的质疑。三者必须一起看。

7. **`λ₄` 的非单调行为尚未从理论上解释**。§8.6 的"共振式不稳定区"目前只是
   实验观察，缺乏动力学分析。这是 v1.1 需要先解决的理论问题。

### 12.6 v1.1 的实验计划与判据

为避免重蹈"跑了一堆实验却没排除任何可能性"的覆辙，v1.1 的实验按下面的顺序推进，

| 步骤 | 实验 | 判据（若成立则继续，否则该方向作废） |
|---|---|---|
| 1 | 复现 §8.6 的非单调性，确认 `λ₄=0.03` 的回陷可稳定复现 | 三次独立重跑，`d_sync` 逐 flow AUROC 均 < 0.45 |
| 2 | C′：`r_seq` 单边上限惩罚（只罚 >0.95 部分），14ep 规模 | 窗口级 holdout > 0.8259 **且** `d_sync` 逐 flow > 0.60 |
| 3 | B′：`r_seq` 跨样本方差惩罚，14ep 规模 | 同上判据；若 C′ 已达标则 B′ 降为消融 |
| 4 | 在 1–3 中胜出者上重试 30ep | 30ep 窗口级 ≥ 14ep 基线（即退化被真正解除） |

**关键约束**：每一步都必须**独立重扫配权**，不得沿用上一步的配权值。
这条规则在本次工作中已经两次改变了结论，是 v1.1 必须固化的实验纪律。

**预期的时间成本**：步骤 1–3 各约 1 小时（14ep × 15k 窗口 + 评估 + 配权扫描），
步骤 4 约 2 小时，步骤 5 复用缓存仅数分钟。整体可在半天内得到明确结论。

## 13. 结论

本报告完整记录了 AetherSentry Omni V1 的设计、实现、验证与失败分析。

**主要成果**：

1. 提出了从"报警"到"锁定"的范式转换，并用**生成式重建残差**把定位信息
   内建进输出形态，使混合窗口定位达到 **1.50× 随机基线**，
   而**不必牺牲**窗口级指标（0.8244，四代最高）。
2. 以 **53,825 参数**取得全面领先，参数量仅为 Pro-Time 的 1/6.6。
3. 实现了完整的三层锁定（空间 / 特征 / 模式）与物理证据层，
   模式锁定纯度 **0.7237**（1.77× 随机），已接近有监督探针上界 0.6694。

**主要失败（同样重要）**：

4. 把训练规模从 14ep 扩到 30ep 后定位指标**全面退化**，
   根因钉死为 `λ₄ · l_F` 单向压制 `r_seq`；**但重建能力自始至终完好**
   （`r_flow` 在所有配置上都是 0.78），项目目标"PMNN 核心生成能力不能丢"得到保证。
5. **两条最自然的修复路径都被实验排除**：换损失形式（通道正交）、
   调权重强度（非单调不稳定区）。这看似是坏消息，但它把问题精确定位到了
   **约束对象/约束形状**这一层——这是任何调参都不可能到达的深度。

**方法论贡献**：

6. 沉淀了一套可复用的"**分量拆解 → 排除法 A/B → 配权扫描 → split-half 复现**"
   的诊断工作流，以及一条硬规则：**配权不跨 checkpoint 通用**。
   这条规则在本次工作中两次阻止了错误结论。
7. 记录了一次真实的判读失误与更正（"no-op"误判），并更新了判读规则：
   **判定两次改动是否等价，必须覆盖 val 列与各分量通道。**

**最终交付**：`14ep 权重 + (w_sync=1.25, w_energy=−0.75, mean) 配权`，
在窗口级 0.8244 / 逐 flow 0.8239 / 混合窗口 top-1 0.5658（1.50×）
三个口径上同时达到当前架构的最优。
