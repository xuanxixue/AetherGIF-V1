## 为什么 F/G 的精确代码丢了

项目历史上从 10-10 深夜到 10-11 凌晨，方案 D → F → G → H 连续演进，期间**只维护了一份
`scripts/overfit.py` 和一份 `src/physics/block.py`**，改完就覆盖，没有留存任何代码快照。
训练日志（`overfit_out*.txt`）虽然还在，能反推**参数量指纹**和**每步 loss 数值**，
但**源码的精确形态**（尤其是方案 F 和 G 中间态的细节）已经不可考，只能靠日志 + 记忆重建差异。

**本次教训直接催生了版本快照规范**（见 README「版本快照规范」），此后每个版本都必须落快照。

## 方案 F（第九、十死穴：层级/形状正交分离 + 共享 μ）

**参数量指纹**：约 1,134,966（共享 μ 去重后）—— 与方案 H 相同，因为架构层面 F 和 H
只在「递推域」不同（F 是 log 域，H 是 log1p 域）。

**已知的架构差异（相对方案 D）**：
1. `a_gamma` 拆成两个冻结常量 `a_gamma_lvl=0.5`（层级）+ `a_gamma_shape=0.1`（形状）。
2. 残差零均值 `res = res - res.mean(dim=1)`。
3. 层级递推 `m_new = m + γ_lvl·(μ − m)`、形状递推 `δ_new = (1−γ_shape)·δ + res`。
4. μ 在 block 间共享，顶层 `PMNNCore.a_mu`（初值 log(0.05)=-3.0）。
5. 递推域仍是 **log 域**（`log_a = torch.log(a.clamp(min=1e-8))`，`a_new=exp(log_a_new)`）。

**loss 差异（相对方案 D）**：`loss_amp = (log(a) - log(a_tar))^2.mean()`，纯 log 域相对误差。
分组 lr：`a_mu ×100`。

**结果**（150 步验证）：profile_cos 0.186→0.972、谱跨 1x→98x；1000 步 profile_cos=0.994、
谱跨 638x，但频段比整体偏高 1.4×、frame-diff 11.21 反升（μ lr×100 震荡）。

**为何丢失**：F 是「架构修复对了、但 loss 换 log 域 + μ lr×100 引入震荡」的中间态，
随后被「方案 G 软截断」替换。

## 方案 G（第十二死穴前置：log 域无权重 + EPS_A 软截断）

**参数量指纹**：约 1,134,966。

**已知的 loss 差异（相对方案 F）**：
```python
# 方案 G：log 域 + 软截断，不加幅度权重
EPS_A = 0.01
la = torch.log(a.clamp(min=EPS_A))
lt = torch.log(a_tar.clamp(min=EPS_A))
loss_amp = (la - lt).pow(2).mean()
```
μ lr ×80，1000 步：profile_cos 0.975、谱跨 822x（最接近 target 727x）、frame-diff 5.91。

**结果**：软截断把 62/64 通道的 target 真值钉在 log(0.01)=-4.605——"屏蔽噪声"变成"屏蔽真值"，
非 DC 通道 μ 系统性偏高 4.1 个 log 单位（第十二死穴）。

**为何丢失**：G 是「发现软截断有害」的过渡态，随后被「去截断纯 log → 最终方案 H log1p」替换。
