# 版本说明 —— v3500（v2500 微调 · 只去 LED 网格）

> **一句话**：架构与 loss 口径**完全不动**，从 v2500 的 2500 步权重继续训练 1000 步，
> 只追加**一个**空间域正则项（patch 边缘比 `loss_edge`），**其他一律不碰**。
>
> **最终配置：`EDGE_W=1.0, NOISE_W=0`**（见第 9 节：noise loss 会经共享参数压低 DC，被移除）。

## 1. 需求（本轮的唯一目标）

用户明确（2026-10-12）：

> 「我的是的是细节和运动轨迹以及残影都和原图一样。2500 轮的那个就只是差了
> 平滑掉 LED 拼接屏 / LED 显示屏的感觉而已」

**因此本轮不做的事**：不修能量分布、不修对比度、不修相位、不改架构、不改 rfft2 参数。

## 2. 架构：完全沿用 v2500 的方案 D

从 `versions/v2500_方案D_2500步/` **原样复制** `src/`，未做任何修改：

| 项| v2500（基线） | v3500 | 说明 |
|---|---|---|---|
| 参数量 | 1,135,658 | **1,135,658** | 完全一致 |
| `a_gamma` | 单γ可学（每 block） | **单 γ 可学** | 未改 |
| `a_mu` | 每 block 独立 | **每 block 独立** | 未改（不是方案 I 的共享 μ） |
| 振幅 loss | log1p + `(a/a_max)^0.5` 加权 | **同** | 未改 |
| 相位 loss | `a_tar²` 功率加权 | **同** | 未改 |
| 优化器 | AdamW 统一 lr | **同** | 仅 lr 降低 |

> **与 v3000 系列的关键区别**：v3000 用的是方案 I（双 γ 冻结 + 共享 μ + log 域），
> 架构与 v2500 **不兼容**，权重无法加载。本轮必须用方案 D 代码才能载入 v2500 权重。

## 3. 唯一的改动：追加两个空间域正则项

### 3.1 `loss_edge` —— 去 LED 拼接屏网格感

```python
def edge_ratio_t(a, th):
    """图像空间口径：先把 [N, WIN*s_dim] 还原成 [TS*WIN, 128, 128] 完整图像，
    再按 PATCH=4 网格切边界。"""
    x = space_gray(a, th)
    x = x.reshape(TS, GRID, GRID, WIN, PATCH, PATCH, 3).permute(0, 3, 1, 4, 2, 5, 6)
    x = x.reshape(TS * WIN, GRID * PATCH, GRID * PATCH, 3).mean(-1)
    dh = (x[..., 1:] - x[..., :-1]).abs()
    dv = (x[..., 1:, :] - x[..., :-1, :]).abs()
    hb = ((torch.arange(dh.shape[-1]) + 1) % PATCH == 0)
    vb = ((torch.arange(dv.shape[-2]) + 1) % PATCH == 0)
    return dh[..., hb].mean() + dv[..., vb, :].mean(), \
           dh[..., ~hb].mean() + dv[..., ~vb, :].mean()

def loss_edge(a, th, tgt_ratio):
    e, i = edge_ratio_t(a, th)
    return (log(e) - log(i) - log(tgt_ratio)) ** 2
```

**关键设计**：只约束「边界相对内部有多跳」这个**比值**，不约束绝对强度。
所以它能压网格感，**不会削弱内部细节**——这正是需求要的。

### 3.2 `loss_noise` —— 降噪

```python
def loss_noise(a, at):
    """压低 AC 通道能量的过冲部分。target 能量 97.2% 在 DC，
    v2500 把 82% 塞进 AC（放大 60~120 倍）= 噪声源。
    只惩罚「超过 target 的部分」→ 欠幅不罚，细节不被削弱。"""
    e_m = (a ** 2).mean(0); e_t = (at ** 2).mean(0).clamp(min=1e-12)
    ac = [1.0 if c % 25 != 0 else 0.0 for c in range(D)]   # w=0 是空间 DC
    r = log((e_m + 1e-12) / e_t)
    return (relu(r) * ac).pow(2).sum() / ac.sum()
```

用 **log 比值**而非线性比值：AC 通道 `e_t` 极小（~1e-4），
线性除法会爆（实测 4.4e9）。log 比值尺度不变且有界。

## 4. 口径校准（本轮踩的坑，务必保留）

`edge_ratio_t` 最初写在 **patch 空间** `[TS,G,G,WIN,PATCH]`，
因 `s_dim = PATCH*PATCH*3 = 48` 需沿 `3*PATCH=12` 个值求均值——
**算的不是完整 48 像素 patch**，导致同一份 target 算出 **2.966** 而图像空间口径是 **1.229**，
目标值完全失去意义（甚至方向反了：loss 会推着网格感变大）。

**修正为图像空间口径后，各版本实测值**：

| | 网格比 | 内部跳变 |
|---|---|---|
| 原始素材（128px） | 1.010 | — |
| **codec 天花板（目标）** | **1.218** | 5.65 |
| **v2500（微调起点）** | **1.663** | 12.07 |
| v3000J（参照） | 20.663 | 1.30 |

**目标值必须现场从 target 计算，不允许硬编码外部数值**——
因为口径一旦改动，硬编码值就失效且不会报错（这是最危险的静默失败）。

## 5. 外部方案评估（2026-10-12，一份「去 LED 网格」技术建议）

收到一份外部建议方案，逐条核对后**大部分不适用**，原因如下（重要，避免以后重复评估）：

| 建议 | 前提是否成立 | 判定 |
|---|---|---|
| 加FiLM 通道调制（因「模型逐通道幅度 1x」） | ❌ **前提误读**。实际日志是「模型 **253x**」，表达能力正常，不存在通道调制缺失 | 不采用 |
| 训练时加**合成 LED 网格退化增强** | ❌ 本任务是**单样本过拟合**，target 就是唯一那张图。人为加退化会污染唯一目标 | 不采用（且违反「禁止注入数据先验」铁律） |
| 加 **depthwise conv 网格抑制分支 / 小波模块** | ❌ 用户明确要求**架构不要动** | 不采用 |
| **时序中值伪标签** | ❌ 等于改target = 注入数据先验 | 不采用 |
| **中高频 amp 比约束** | ✅ 成立。中高频确实过载（模型 AC 能量 log比 +0.40，最大 +1.26 = 3.7倍） | **已采用**（即本方案的 `loss_noise`） |
| 推理时 FFT 陷波 / NLM 后处理 | ⚠️ 原理可行，但属**推理期hack**，不改变模型本身 | 暂不考虑；本轮只做训练侧 |

**建议中被采用的唯一一条**（中高频能量约束），实现上比原文的 `notch_loss` 更直接：
不需要猜网格频率，而是直接约束**逐通道 log 能量比**，且**只惩罚过冲**（欠幅不罚），
所以不会削弱细节。

## 6. 实施中发现的致命 bug（已修）

首轮 150 步验证出现**方向完全相反**的结果：

| 步 | 网格比（目标 1.218） | 内部跳变（基线 12.07） |
|---|---|---|
| 1 | 1.663 | 12.07 |
| 75 | **2.281**（越修越大）❌ | **6.86**（细节丢失）❌ |

**根因**：`loss_noise` 拿到了带batch 维的 `a_tar`（`[1,N,D]`），
`(a_tar**2).mean(dim=0)` 在错误的维上求均值 → loss 量级 **1,553,134**，
比主 loss（phase 0.24）大 **650 万倍**，梯度完全压倒一切，
把模型往「牺牲内部细节换能量」的方向拽（恰好是 v3000J 失败的同一方向）。

**修复**：新增 `a_tar_n = a_tar[0]`（`[N,D]` 口径）专供新 loss 使用，
**原有 loss 一行未改**（它们依赖广播对齐，改了会破坏 v2500 复现性）。

修复后量级平衡：

| loss | 修复前 | 修复后 |
|---|---|---|
| amp | 0.0003 | 0.0003 |
| phase | 0.2399 | 0.2399 |
| edge | 0.0966 | 0.0966 |
| **noise** | **1,553,134** | **0.2324** ✅ |

> **教训**：微调场景下，**新加的 loss 必须先单测量级**再启动长训练。
> 一个手误的`.mean(dim=0)` 就能让 150 步白跑，且现象极具迷惑性
> （看起来像「这个方向不对」，实际是数值 bug）。

### 6.1 bug 修复后的 150 步验证（通过，据此启动正式训练）

| 步 | 网格比（目标 1.218） | 内部跳变（基线 12.07） | wcos | edge loss | noise loss |
|---|---|---|---|---|---|
| 1 | 1.663 | 12.07 | +0.8934 | 0.0966 | 0.2324 |
| 50 | 1.439 | 12.57 | +0.8924 | 0.0277 | 0.0657 |
| 100 | 1.330 | 12.82 | +0.8922 | 0.0077 | 0.0335 |
| 150 | **1.287** | **12.73** | +0.8915 | 0.0030 | 0.0176 |

**三项全部朝正确方向收敛，且没有一项指标被牺牲**：
- 网格比 1.663 → 1.287（降 23%，已接近 150 步内的极限）
- 内部跳变不降反升（12.07 → 12.73，细节保住了）
- wcos 全程只掉 0.0019（相位几乎没动）

## 9. 首版（EDGE+NOISE）验收 FAIL 与根因分析（2026-10-12）

### 9.1 验收结果

| 指标 | v2500 | v3500(EDGE+NOISE) | 保留率 | 判定 |
|---|---|---|---|---|
| 网格比 | 1.620 | 1.210 | −25% | ✅ 目标达成 |
| 边界跳变 | 19.92 | 14.90 | −25% | ✅ 目标达成 |
| 内部跳变 | 12.30 | 12.32 | 100.2% | ✅ |
| Sobel 锐度 | 11.33 | 10.32 | 91.0% | ✅ |
| **像素 std** | 27.81 | **22.53** | **81.0%** | ❌ 跌破 |
| **帧间差** | 7.96 | **6.23** | **78.2%** | ❌ 跌破 |

### 9.2 根因：noise loss 通过共享参数把 DC 一起拽下去了

快照扫描显示 std/帧间差在**第 1→250 步就崩到 77%**，之后稳定。逐通道能量比（模型/target）：

| w | v2500 | v3500(EDGE+NOISE) |
|---|---|---|
| **w=0（空间 DC）** | **1.00**（不过冲） | **0.73**（欠冲 27%）❌ |
| w=2 | 1.22 | 0.46 |
| w=8 | 1.30 | 0.54 |
| w=11~13（网格频率） | 1.4 | 0.8 |
| 其他 AC | 1.2 | 0.8 |

**关键事实**：`loss_noise` 只惩罚 `c%25!=0` 的 AC 通道，**不碰 w=0**。但 DC 仍从 1.00 掉到 0.73 —— 梯度经 FFN 等共享参数扩散，把整体振幅一并压低（`a_out` 0.2559→0.2166，−15%）。

**「网格频率集中」的假设被推翻**：w11-13 过冲只有 1.4x，其他 AC 也有 1.2x，**两者没有分离**。不存在「只压网格噪声、不碰细节质感」的频率窗口 —— v2500 的质感本身就建立在这批 AC 过冲上。

**另一个关键参照**：codec 天花板 std = **35.98** > v2500 的 27.82。若 DC 不欠冲，std 本该更高。std 崩塌的主因是 DC 欠冲，不是 AC 被压。

### 9.3 修法：去掉 noise loss，只留 edge loss

`loss_edge` 只约束「边界/内部」**比值**，不压绝对强度，因此不会拖低整体振幅。
而网格目标已完全由 `loss_edge` 达成（比值压到架构下限 1.218 附近），noise loss 是**多余且有害**的。

150 步验证（`NOISE_W=0`）：

| 指标 | v2500 | edge-only | 保留率 | 判定 |
|---|---|---|---|---|
| 网格比 | 1.662 | 1.240 | −25% | ✅ |
| 内部跳变 | 12.05 | **15.67** | **130%** | ✅ 细节更丰富 |
| 像素 std | 27.80 | 25.75 | **92.6%** | ✅ |
| Sobel 锐度 | 11.15 | 13.16 | **118%** | ✅ |
| 帧间差 | 7.83 | 7.48 | **95.5%** | ✅ |
| `a_out` | 0.2559 | 0.2500 | 97.7% | ✅ 振幅保住 |

**四个守卫全部通过，且内部细节与锐度不降反升** —— edge-only 通过「提升内部细节」降低网格比值，而非「压平边界」，完全符合「别动现有东西」的要求。

> **工作机理**：edge loss 让模型在 patch 内部补上更多真实细节（内部跳变 +30%），
> 使网格边界在视觉上被细节淹没，比值从 1.66 降到 1.24。这不是削平，是**充实**。

### 9.4 教训

- **微调时新加的 loss 必须先验证它不影响「不该动的量」**。noise loss 单看量级（0.23）是平衡的，
  但它通过共享参数间接压低了 DC，这种副作用只看 loss 数值发现不了，必须测终态指标
- **「只压过冲」的 relu 屏蔽不了梯度串扰**：relu 只保证「欠幅时不给该项贡献」，
  但该项在过冲期的梯度仍会流经共享参数改变其他通道的行为

## 10. 用户视觉反馈推翻验收基准（2026-10-12 12:18，决定性）

用户直接对比素材（`target_recon_ball.gif`）与 v3500_e 产物后指出：

- 高频（噪点）：素材 2.8 倍 → 用户看到"颗粒/网点/锯齿"
- 中低频（光影）：std 只有素材 75% → 用户看到"光影破碎、偏扁平、没立体感"

用户说的每一项视觉缺陷，都对应一个精确的数字。**之前把 v2500 的过度锐化当"质感"保护，

曾猜测 LED 网格能量集中在 w=12 附近（PATCH=4 在 48px patch 内的周期），试图做频率陷波。
实测：**网格频率 w11-13 过冲 1.4×，其他 AC 也 1.2×，两者没有分离窗口**。
v2500 的噪点与"质感"是同一批 AC 能量，**不存在「只压噪声不碰细节」的频率切分**。

## 11. 最终方案 v3500_t：texture + std 守卫（训练中）

### 11.1 两个 loss

```python
def loss_texture(a, th, tgt_e, tgt_i):
    """降噪（绝对强度）：边界/内部跳变的绝对值对齐 target。
    差分不含 DC，不误伤对比度；log 域梯度均匀。"""
    e, i = edge_ratio_t(a, th)
    return (log(e) - log(tgt_e))**2 + (log(i) - log(tgt_i))**2

def loss_std_guard(a, th, tgt_std, floor):
    """守卫：std 不许低于 target×floor。堵死「整体压低振幅」的捷径。"""
    s = _image_gray(a, th).std()
    return relu(log(tgt_std * floor) - log(s))**2
```

**`loss_std_guard` 的作用**：texture 类降噪 loss 的共同失败模式是模型用"整体压低振幅"
降低差分（差分天然变小），代价是 std 崩、光影更平。守卫把这条捷径堵死，
逼模型走「降高频 + 提低频」的正路。

### 11.2 参数

| 参数 | 值 | 说明 |
|---|---|---|
| lr | **1e-4** | 提高了。3e-5 太低，模型只能走"整体压低"捷径，守卫拦不住 |
| TEXTURE_W | 1.0 | 降噪 |
| STD_W | 2.0 | 守卫权重加大，压过 texture 的捷径梯度 |
| EDGE_W | 1.0 | 保留比值约束（防网格结构） |
| NOISE_W | **0** | 已弃用（会误伤 DC） |
| STD_FLOOR | 0.75 | std 下限 = target×0.75 ≈ v2500 现状（不许比现在更差） |

### 11.3 150 步验证（lr=3e-5 vs 1e-4 对比）

lr=3e-5 时守卫形同虚设（std 一路崩到 20.1）；提到 1e-4 后：

## 12. 第十八死穴：均值约束压平轮廓 = 「模糊」（2026-10-12 15:00）

### 12.1 跳变分布诊断

不再看均值，看**分布形状**（所有相邻像素差分的分位数）：

| | p50 | p75 | p90 | p95 | **p99** | 尾能量% | >20 占比 |
|---|---|---|---|---|---|---|---|
| **素材（真平滑）** | **0.00** | **1.00** | 8.00 | 17.00 | **47.0** | **61.6** | 4.03% |
| v2500（起点） | 4.00 | 9.00 | 16.00 | 23.00 | 46.0 | 27.0 | 6.20% |
| **v3500_t（模糊）** | **2.00** | **4.00** | 7.00 | 11.00 | **26.0** | 31.4 | 1.63% |

**素材是极端重尾**：一半相邻像素**完全相同**（p50=0），但轮廓处 p99=47，
**61.6% 的总能量集中在最尖锐的 5% 像素上**。

**v3500_t 的轮廓被压掉 45%**（p99 从 47 → 26），同时背景噪点没清干净（p50 从 0 → 2）。

### 12.2 根因

`loss_texture` 约束的是跳变**均值**。素材均值低，是靠「大量零 + 少数大」的极端重尾实现的。
模型为了把均值压到 target，选了**最省力的捷径——把所有跳变压到中等**：
- 大跳变（真实轮廓）被压平 45%
- 小跳变（背景噪点）反而还没清干净

**均值相同，分布完全不同**：素材是「干净背景 + 锐利轮廓」，v3500_t 是「微噪背景 + 模糊轮廓」。
这就是用户说的「模糊」。**与第十五死穴同源：平均值度量会骗人。**

### 12.3 修法：分位数感知降噪 `loss_jump_dist`

把「背景噪点」和「真实轮廓」**分开约束**：

```python
def loss_jump_dist(a, th, tgt_q75, tgt_q99):
    j = _jump_tensor(a, th)           # 所有相邻像素差分
    q75 = torch.quantile(j, 0.75)
    q99 = torch.quantile(j, 0.99)
    low  = (log(q75) - log(tgt_q75))**2              # 压背景噪点
    high = relu(log(tgt_q99) - log(q99))**2          # 保护轮廓（单侧）
    return low, high
```

- **低端 q75**：压到 target（素材 q75=0.88）→ 清背景噪点
- **高端 q99**：**relu 单侧保护**，轮廓可以更锐，但**不许更糊**（target q99=47.55）

> **关键设计**：高端用 relu 而非双向约束。双向约束会让 loss 倾向于
> 「把轮廓压到刚好等于 target」，仍然在压平轮廓；单侧保护只惩罚「变糊」，
> 允许模型保留甚至增强锐度。
