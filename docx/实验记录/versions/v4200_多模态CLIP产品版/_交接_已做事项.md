## 2. 当前架构与参数量

### 模型结构
```
GIF → 3D FFT(rfft2, 真实网格 5×25=125) → 复值振子场[B,N,125×2]
  → PMNNCore(12 block 物理演化) → 逆 FFT → GIF
条件入口（v4200 改造）：
  cond_vec[2049] = text_emb[1024] + image_emb[1024] + has_image[1]
  → CondProjector(256→896) → 4 个物理调制头(omega_bias/drift_target/kappa/T)
  → 另有 cond_field(CondFieldPredictor) 直接把条件预测成「吸引中心场」
```

## 3. 已完成的所有改动（逐条）

### A. 条件入口：Qwen → CLIP 双模态（2026-10-13）
- 用户解除「必须纯物理」约束（"这是产品"），条件入口从「冻结 Qwen 文本」升级为「冻结 jina-clip-v2 图文双塔」。
- `clip_condition.py` 新增 `ClipConditionEncoder`（塔级分裂：视觉上 GPU fp16、文本留 CPU fp32）、`CondProjector`（text/image 双 proj + 可学模态门）、`build_cond_vector`。
- 三种生成能力 = 同模型三种条件采样：文生(has_image=0)/图生(has_image=1,text=0)/图文(都给)。

### B. 训练主脚本 `train_multimodal.py`（新建）
完整功能：7 天预算自适应步数、实时进度条+ETA、断点续训(`--resume auto`)、
四条早停判据、WarmupCosineLR、group 级 train/val 划分、崩溃/中断/success 三路收尾都先落断点。

### C. 内容生成通路 `cond_field.py`（新建，本次核心）—— 演进过程
1. **定位病根**：drift_field 是唯一把 target 送进相位演化的通路，训练永远传
   `targets=真实场`，`if targets is None: 用 prototypes` 这条生成分支一次都没执行，
   prototypes 梯度恒为 0（best.pt 实测 std=0.01963 = 初始 randn×0.02 的值）。
   → generate() 拿随机原型当吸引中心，输出纯噪点。
2. **新增 CondFieldPredictor**：条件 → 驻波基混合预测场
   `field[b,n,c] = Σ_k softmax(w_k(cond)) · A_k(c) · SW_k(n)`。
   - 27 个驻波基（3×3×3，从 64 降下来省显存），每基 2×125 维复振幅。
   - 无 attention/FFN（物理驻波，与 StandingWaveFFN 同源）。
3. **训练双通路**：`train_multimodal.py` 里 `--gen-ratio`(默认0.7) 按步随机交替
   重建（targets=真实场）/生成（use_cond_field=True 用预测场当吸引中心）。
4. **直接监督 `supervise()`**：因为 cond_field 的梯度只能穿 12 个物理 block 反传，
   路径太长太弱（实测 40 步场差仅 1.7e-06），加了 `--gen-weight`(默认2.0) 的
   loss_sup 项，在 log1p 域对预测场与真实场做「幅度谱包络 + a_tar² 加权相位 cos」对齐。

### D. 模型 forward 改造（`aether_gif_model.py`）
- forward 加 `use_cond_field` 开关：True 时用 `cond_field(cond)` 当吸引中心，
  `drift_target=None`；False 时走原重建通路。
- diag 里回传 `pred_field` 供训练侧直接监督。
- `generate()` 已支持 `cond_vec` 直传（读离线特征，不加载 CLIP）。

### E. 已踩并修掉的坑（下一个 AI 别重新踩）
1. 早停判据二误停：batch=1 时 train loss 是单样本测量 vs val 是 48 样本均值，比值天然虚高。`gap_ratio` 从 1.15 提到 3.0。
2. `update_baseline` 引用未定义变量 `step`（NameError 死在第 2 步）。已修：显式传 step。
3. cond_field 早期 scalar gate 梯度被 tanh 压死（1.3e-08）。**已删 gate 参数**。
4. `--gen-weight` 从 2.0 加到 4.0 出现过 NaN（预测场冲太大→漂移场 softmax 溢出）。**上限卡 2.0**。

## 4. 当前卡点（最关键的未完成状态）

### 问题：条件仍没分化（还没修好，也没验证）
最新代码（`cond_field.py` 当前磁盘版本）做了两步重构，但**没跑完训练验证就中断**：

1. **chan_amp 从全局共享改成条件调制**（`to_chan` 层）：原来只有 27 个基权重 w 是
   条件相关的，chan_amp 全局共享，204 个 group 挤在 27 维里实在分不开。
   改成 `amp[b,k,c] = chan_amp[k,c] · (1 + tanh(to_chan(cond))[b,k,c]·0.5)`，
   条件自由度从 27 升到 27×250。
2. **supervise() 监督口径去归一化**：第一版做了 `lp/||lp||` 范数归一，把「整体幅度」
   这个自由度从 loss 里删掉了（而幅度正是 chan_amp 唯一的表达通道），导致 150 步
   后 chan_amp std=0.02015≈初值 0.02，几乎没动。改成只做**逐位置中心化**（去 DC 偏移），
   **保留幅度尺度**。

### ⚠️ 交接给下一个 AI 必须注意的两个事实
- **`cond_field.py` 的 `supervise()` docstring 与代码有矛盾**（残留未清理）：
  docstring 第 156 行还写着"逐通道归一"，但代码第 176-177 行已经是逐位置中心化了。
  以**代码为准**，但要顺手把 docstring 改一致，避免后面的人被带偏。
- 实测数据（从日志和诊断得来，全部是**短训**结果，不是全量）：
  - 30 步时 cos 从 -0.0005 → +0.9951（相位对齐学了，幅度没学）。
  - 150 步（实际只跑到 86 步就被超时中断）后：条件场差 5.7e-06、混合权重 std=0.00121。
  - 训练日志里 `[PLAN] 总步数 = 150/40/30/15` 这种小步数 = 都是 smoke/短测试，
    **真正的全量训练从没启动过**。

### 项目级铁律（从历史沉淀，v4200 同样适用）
- 架构递推与 loss 必须用同一 log1p 变换（改 loss 变换必须同步改 block.py + a_mu 初值 + μ 的 lr）。
- FFT 真实网格 = 5×25=125；通道 c ↔ (h=c//25, w=c%25)，**分频段必须按 w 切**。
- FFT 系数极重尾（中位数 0.0015/p99=5.4），振幅走 log1p、相位走 a_tar² 功率加权。
- 「平均值度量会骗人」：验收必须同时报空间域指标（对比度 std、p1-p99、Sobel）。
- 用户铁律：禁止注入数据先验（不用 target 谱初始化 μ、不造伪标签），让模型自己学。
- 架构中除条件入口外，**不得出现任何 Transformer/注意力/FFN**。
