## 1. 项目核心状态

### 1.1 核心目标
将 v3700 模型改造为**真正的条件生成模型**：只依赖 CLIP 特征作为条件，**不再使用原 GIF 作为监督信号**，实现从条件直接生成 GIF 的能力。

### 1.2 当前技术路线
- **条件编码器**: jina-clip-v2 图文双塔（XLM-R 文本塔 + EVA-02 视觉塔）
- **条件调制器**: `ConditionModulator` - 将 CLIP 条件映射为漂移场原型
- **物理核**: 保持不变（PMNNCore / TimeField / KuramotoSync / StandingWaveFFN / DriftField / Thermodynamics）
- **损失函数**: **CLIP 感知损失**（生成 GIF 的 CLIP 特征 vs 原始 CLIP 条件特征）

## 5. 已知问题和约束

### 5.1 核心约束（用户铁律）
1. **禁止注入数据先验**: 不用 target 谱初始化 μ、不用 set_amp_prior、不用时序中值造伪标签
2. **改 loss 同步**: 改 loss 变换必须同步改 block.py 递推 + `a_mu` 初值 + μ 的 lr 倍率
3. **架构中除语言模块外不得出现任何 Transformer/注意力/FFN**
4. **不行改物理核**: 用户明确要求不动物理核架构
5. **不行改编解码口径**: `D=125, GRID=32, PATCH=4, WIN=5, IMG=128, TS=6, NORM=10.0`

2. **C 盘仅 240MB 剩余**: 任何清理动作先经用户批准
3. **CUDA 设备**: RTX 3050 Laptop 4GB，空闲约 3.2GB
4. **Python 路径**: `C:\Python312\python.exe` (唯一可用)

### 5.3 技术约束
