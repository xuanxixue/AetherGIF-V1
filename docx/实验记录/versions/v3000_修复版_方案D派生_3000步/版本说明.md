## 2. 三个问题的诊断结论（2026-10-11 精确实测）

### 2.1 对比度偏淡 —— 出图口径 + AC 过冲
- **出图口径**：`normalize=True`（min-max）被离群系数绑架，暗部被抬到灰（灰度 std 24.5 vs target 53.2）。换固定 clamp 后 std 恢复到 34.7、PSNR 从 18.0 升到 20.0。
- **AC 过冲**：模型 AC 通道能量超 target 2~3.6 倍，把细节过度锐化、暗部填亮。

### 2.2 噪声 / LED 颗粒感 —— AC 分量过冲（根因）
- 颗粒感量化（边界跳变/内部跳变比）：原图 1.01、codec 天花板 1.23、v2500 模型 **1.65**。
  → 1.23 是 codec 固有（patch 结构），换 patch=8 反而更差（21.5 dB < 26.7 dB）；模型端能修的是把 1.65 压回 1.23，这正是 AC 过冲在加剧边界跳变。
- **AC 过冲的训练端根因（diag_amu.py）**：v2500 的 12 个独立 `a_mu` 全程停在初值 log(0.2)≈-1.6，频段间无分化，而 target 谱包络是 DC≈-3.15 / AC≈-8.73。μ 根本没学到。
- **量纲错位机制**：`a_mu` 在 log 域递推、loss 在 log1p 域（第十三死穴），AC 小通道梯度被 `a/(1+a)≈0.02` 压抑 40 倍。

### 2.3 关键数据纠错（旧记忆两处错误，避免误导）
1. **rfft2 真实输出 = (N, 5, 25) = 125 系数**（win=5 时间维完整 FFT × s_dim//2+1=25 空间维 rfft），不是旧笔记的 75。d_model=64 只保留 **51.2%** 谱，不是 85.3%。
2. **空间 DC 列 w=0 占 96.4% 能量**，被砍的 61 通道（时间高频 h=2,3,4）占 7.93%，不是"3 个 DC 通道 99.4%"。

## 4. 架构核心（block.py，方案 I）

| 维度 | v2500 方案 D | v3000 方案 H | **v3000 方案 I（本版本）** |
|---|---|---|---|
| γ | 单 γ 可训练，每 block 独立 | 双 γ 冻结（0.5/0.1） | **双 γ 冻结（0.5/0.1）** |
| μ | 每 block 独立 per-channel | block 间共享 | **block 间共享** |
| 振幅递推域 | log 域 | log1p 域（+expm1 截断死穴） | **log 域** |
| 层级/形状 | 未分离（res 可改层级） | 正交分离 | **正交分离** |

**核心递推（block.py forward，方案 I = 方案 H 的架构正确性 + 方案 D 的 log 域稳定性）：**
```python
log_a = torch.log(a.clamp(min=1e-8))
res = 2.0 * torch.tanh(log_res / 2.0)
res = res - res.mean(dim=1, keepdim=True)    # 残差零均值：只含形状
m = log_a.mean(dim=1, keepdim=True)          # 层级
m_new = m + a_gamma_lvl * (a_mu.view(1,1,-1) - m)   # γ_lvl=0.5 冻结
delta = log_a - m
delta_new = (1 - a_gamma_shape) * delta + res        # γ_shape=0.1 冻结
log_a_new = m_new + delta_new
a_new = torch.exp(log_a_new.clamp(-20.0, 5.0))
```

**为什么这是正确合成**：
- 方案 H 修对了「双 γ + res 零均值 + 共享 μ」（第九死穴），但错在 log1p 域 + `expm1(clamp(0,6))` 把 51% 位置钉死 a=0（第十四死穴）。
- 方案 D log 域稳定（无截断死穴），但错在单 γ + res 未零均值，μ 被架空不分化学不到谱包络。
- 方案 I = 取两者之长。log 域 `exp(clamp(-20,5))` 无死穴，双 γ 冻结让 μ 逐通道独立收敛。

## 5. loss 口径（精确公式）

```python
# 振幅：log 域 + eps 软地板 + 等权（修第十三死穴量纲错位）
la = torch.log(a.clamp(min=0.0) + 1e-3)
lt = torch.log(a_tar.clamp(min=0.0) + 1e-3)
loss_amp = (la - lt).pow(2).mean()      # 等权，无幅度权重

# 相位：功率加权（与 v2500 一致）
w_ph = (a_tar ** 2).clamp(min=1e-8)
loss_ph = (w_ph * pe.pow(2)).sum() / w_ph.sum()

loss = loss_amp + loss_ph
```

**关键决策依据**（150 步三组对照，AC 过冲 [DC/低/中/高]）：
| loss 口径 | DC | 低频 | 中频 | 高频 |
|---|---|---|---|---|
| log1p + 权重 0.5（方案 D 原样） | 1.18 | 7.38 | 10.87 | 13.01 |
| log + 权重 0.5 | 0.75 | 3.24 | 4.06 | 5.03 |
| **log + 等权** | 0.25 | **1.06** | 2.51 | 3.28 |

log 域天然拉平重尾，**不该再加幅度权重**（log+权重把 AC 小通道压低、DC 抬高，方向错）。等权下 res 零均值后 μ 逐通道独立收敛，无需 DC 特判权重。

## 9. 第十五死穴：log 域校准与视觉质量可以完全脱钩

### 9.1 现象

用 log 域振幅比（0.92~0.98，接近 1.0）+ wcos（0.9118，超越 v2500 的 0.893）宣布修复成功，
但**出图明显更糊**。两个指标都「通过」，视觉却退化。

### 9.2 根因

`log`域 loss 只约束 `mean_N(log(a+eps))`，`a_tar²` 功率加权相位 loss 只约束加权平均 cos。
**这两者都是「平均值」形式的度量，而对比度损失恰好会在平均值里互相抵消**：
- 一部分位置振幅偏高、另一部分偏低 → 平均值校准完美，但像素域被摊平
- 相位误差在不同位置符号相反 → 加权 cos 很高，但干涉后能量互相抵消

### 9.3 判据（写进验收流程）

**任何 log 域振幅比/ wcos 指标都不能单独作为验收依据。**
必须同时报告空间域指标：
- 对比度 std（相对target 的比例，目标 ≥0.85）
- 动态范围 p1–p99（目标 ≥0.85×target）
- Sobel 锐度 / 拉普拉斯 std（相对 target）

### 9.4 修法

新增空间域对比度 loss（`overfit.py` 的 `contrast_loss`），把监督从「系数域平均值」搬到「空间域」：

```python
def space_gray(a, th):   # 可微解码，不走 numpy（contrast_loss 需要梯度）
    ...
    flat = flat.clamp(-1.0, 1.0) * 127.5   # 与 codec clamp 口径严格对齐
    return flat.reshape(N, WIN * s_dim)

def contrast_loss(a, th):
    x = space_gray(a, th).mean(-1)
    xc = x - x.mean()
    std_m = xc.std()
    # log 比值保证尺度对称，避免 std_m→0 时数值爆炸
    return (torch.log(std_m.clamp(min=1e-3)) - math.log(TGT_STD)) ** 2
```

`TGT_STD` 必须用**与 `space_gray` 完全相同的口径**算出（同一个 irfft2 + clamp + ×127.5），
否则 loss 目标错位（第一版写成`decode_field_to_frames` 的 numpy 路径，std差 100倍）。

空间域损失对「能量被摊平」是**线性响应**，不像功率加权平均那样互相抵消。

### 9.5 权重标定实测（150 步短验证）

`contrast_loss` 用 `log(std_m/std_t)` 的平方，权重 `CST_W` 通过命令行第9 参数传入。

| CST_W | 100 步时对比度 | 150 步时对比度 | cst loss 终值 | 观察 |
|---|---|---|---|---|
| 1.0 | 0.5 / 34.3 | 13.6 / 34.3（40%） | 0.85 | 方向正确但**梯度自激发太晚** |
| 4.0 | 待测 | 待测 | — | 验证能否拉到 target 附近 |

**自激发机理**（CST_W=1.0 的 150 步曲线）：
- 1→100 步：对比度 0.2→0.5，cst loss 24.76→18.50，**几乎线性但极慢**
- 100→150 步：对比度 0.5→**13.6**，cst loss 18.50→**0.85**，总 loss 33.6→15.0
- 即：梯度打通后模型**自激发**——对比度铺开后，振幅/相位 loss 也跟着快速下降

**已知局限**：cst loss 降到 0.85 就基本停止施压，但对比度仍只有 40%。
原因是 `log` 比值形式在 `std_m` 远小于 `std_t` 时梯度被压缩（`d log(std)/d std = 1/std`）。
若 150 步后对比度停在 40% 附近不再上升，说明需要：
- 提高 CST_W，或
- 改用 `(std_m/std_t - 1)²`（线性比值，梯度更强但可能过冲，需同时约束上界）

### 9.6 顺带修复的真实 bug

- `codec/gif_codec.py` 第 302 行：`torch.zeros(...)` 缺 `device=z.device` → **任何 GPU 调用必崩**

### 11.4 修法：逐帧对比度 loss（方案 K）

```python
# 每帧对齐自己的 target 值，低对比帧不再被牵连
x = space_gray(a, th).reshape(TS*GRID*GRID, WIN, -1).mean(-1)   # 灰度
x = x.reshape(TS, GRID*GRID, WIN).permute(0, 2, 1).reshape(TS*WIN, GRID*GRID)
xc = x - x.mean(dim=1, keepdim=True)
std_m = xc.std(dim=1)                                          # [30] 逐帧 std
return (torch.log(std_m.clamp(min=1e-3)) - torch.log(TGT_STD_PER_FRAME)).pow(2).mean()
```

**关键细节**：逐帧 reshape 的顺序必须与 `decode_field_to_frames` 的真实 permute 一致
（`reshape(TS,GRID,GRID,WIN,patch,patch,3)` → `permute(0,3,1,4,2,5,6)`，
帧序号 `f = t*WIN + w`）。用简单的 `[TS*WIN, GRID², pix]` 是**错的**——
那把 win 维当成了帧序。正确口径实测 `corr=0.99999, maxabs=0.26`。

target 逐帧 std 实测（30 帧）：
`44 45 44 44 42 39 41 41 39 36 | 26 22 18 15 16 16 16 16 16 17 | 28 33 35 35 35 39 40 42 42 42`
其中帧 12~19 就是低对比度区（15~17），帧 0~9 和 25~29 是高对比区（39~45）。

### 11.5 配套改动

- **崩塌检测判据**：日志新增 `崩塌帧=N` / `过冲帧=N`，判据用**相对各自 target 的 50%**

- **best ckpt 判据**：从「全局 std 偏离度」改为「**逐帧最大相对偏差**」，
  这样全局完美但个别帧崩塌的 ckpt 不会被误选为best
- 叠加**第十六死穴**的 `energy_loss`（EN_W=0.5），治频段能量占比失真

### 13.5 新的修复方向（方案 L）

**给 patch 边界跳变加惩罚**，把高频能量从边界搬到内部：

```python
def patch_edge_loss(gray):
    """惩罚 patch 边界的跳变，引导能量进入 patch 内部。
    边界跳变/内部跳变 → 目标 1.0（原图 1.021）
    """
    dh = |diff(gray, axis=-2)|   # 水平差分
    dv = |diff(gray, axis=-1)|   # 垂直差分
    hb = (j+1) % PATCH == 0      # 边界列掩码（按差分后长度构造）
    edge = mean(dh[:, hb]) + mean(dv[vb, :])
    inner = mean(dh[:, ~hb]) + mean(dv[~vb, :])
    return (log(edge/inner) - log(1.02)) ** 2      # 目标 = 原图的 1.021
```

**判据升级**：网格比必须 ≤ **1.8**（v2500 是 1.62，原始是 1.02），
同时内部跳变必须 ≥ **4.5**（保住 v2500 的 6.15，至少不塌到 v3000J 的 0.65）。

## 12. 本轮三处误判的记录（重要，防止复发）

### 误判1：「v2500 的能量骨架是对的」
- **错误结论**：认为 v2500 把 81.9% 能量放在低频大系数上、骨架正确。
- **实测**：v2500 的 DC 能量只占 **18.1%**（target 是 97.2%），82% 的能量在**高频**（放大 60~120倍）。
- **为什么会错**：把「能量集中」等同于「能量在低频」。实际上 target 的重尾分布决定了能量**绝大部分必须集中在 DC**。

### 误判2：「μ 被压低 2~3 个 log 单位导致糊」
- **错误结论**：μ 的 AC 通道比target 低 2~3 log（c=1 差 -3.43）。
- **实测**：用错公式了。Jensen 不等式陷阱——
  - 错误口径 `log(mean_N(a)+eps)` → bias -2.53, corr 0.8674
  - **正确口径 `mean_N(log(a+eps))`** → bias **-0.51**, corr **0.9953**
- **为什么会错**：架构稳态是 `mean_N(log(a+eps))`（loss 就是逐位置 log 后平均），
  我却用了 `log(mean_N(a)+eps)`。重尾分布下两者差异巨大（log(mean) 被尾部拉高）。
- **教训**：诊断谱包络时，**必须与 loss 的实际聚合顺序完全一致**，不能想当然换顺序。

### 误判3：「log 域振幅比校准 = 视觉好」
- 即第十五死穴，见§9。

### 通用教训

**能量占比、log 域振幅比、wcos 全都是「平均值」度量。**
判断视觉质量必须补空间域指标（对比度 std、动态范围、Sobel 锐度），
否则会被平均值完美地骗过去。验收脚本 `eval_v3000.py` 已包含空间域指标。

### 12.5 根因：第十六死穴 —— log1p 关不住尖峰

诊断脚本 `scripts/diag_outlier_energy.py`（只读）定位：

- **能量集中度**：模型 top-393 系数（0.1%）占能量 **80.84%**，target 只占 19.23%。
- **元凶是单通道 c=16**（h=0, w=16）：能量比 **235.7x**，模型均幅 3.25 vs target 0.304。
- `a_out.max = 148.41` —— 恰好等于架构硬边界 `exp(5.0)`（`block.py: log_a_new.clamp(-20,5)`），
  说明**尖峰被顶在 clamp 上限**，不是自然收敛。
- **为什么 log1p 关不住**：`d/da log1p(a) = 1/(1+a)`，a=148 时梯度 0.0067，
  只有线性域的 **0.67%**。重尾分布下尖峰只占 20/393216 个系数，被海量近零系数淹没。

这解释了那个矛盾读数：**训练日志「四段振幅比全 < 1.0」（欠幅）与验收「w13-18 能量超载 61 倍」并存**——
log1p 看的是**位置级相对幅度**，验收看的是**频段能量占比**，二者不是一回事。

**修法（`energy_loss`，不注入数据先验、不改架构递推）**：直接监督逐通道能量比的 log 差
`(log E_m − log E_t)²`。选log 比值而非线性比值的理由：
- 尺度不变，10x 与 100x 过载给同量级梯度；
- **梯度不随尖峰幅度衰减**（`d/da log E_m = 2a/E_m`，尖峰主导时 ≈ 2/N），
  与 log1p 的 `1/(1+a)` 正好相反；
- 直接对齐验收第 3 项，不是代理指标。

实测梯度压制比：**energy 项在尖峰处的梯度是 amp 的 9.4 倍**。
