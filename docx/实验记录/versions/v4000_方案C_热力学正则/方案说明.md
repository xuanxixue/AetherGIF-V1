# v4000 · 方案 C：热力学正则

> 状态：**待命骨架**（代码已复制自 v3700，未做任何修改）
> 创建：2026-10-13 03:25

## 目的
把 `Thermodynamics` 从"只做诊断"变成**真正参与训练**，提供温度调度的软约束。

## ⚠️ 关键前提（务必先读）
**当前 `Thermodynamics` 类是 0 梯度接入的。** 代码原文：
```python
class Thermodynamics(nn.Module):
    """热力学判据层：U / S / F，只做诊断，不参与梯度。"""
```
全项目搜索只有 import / `self.thermo = Thermodynamics()`（实例化未用）/ 文档字符串三处，
**loss 里没有任何一项引用 U、S、F**。

所以：
- 网上/第三方建议里"新热分布会与现有 −T·S 冲突"的前提**不成立**（−T·S 从未生效）
- 但"热力学层已经在管这件事只是方向不对"**同样是错的**（它根本没在管）
- **本方案等于新增一条梯度通路，风险最高，必须放最后做**

## 附带发现的 bug（顺手记一下）
`thermodynamics.py` 的 `amplitude_entropy_channel`：
```python
p = F.softmax(a, dim=1)          # 注释说"每个通道一个分布"
S = -(p * torch.log(p+1e-12)).sum(dim=1)
return S / torch.log(torch.tensor(float(a.shape[1])))   # 归一化也按 N
```
注释说"通道维"，实现是沿 **N 维** softmax，归一化也按 N 算 —— **实现与文档不一致**。
因为未参与训练所以暂不影响，但启用前必须先修。

## 方案
定义频率能量，作为**单边正则项**加进 loss，用温度调度控制权重：
```
E_freq = Σ_c w_c · a_c²,     w_c 随频率递增
λ(T) = λ_max · (T / T_max)    早期高温允许探索，后期低温压制高频
```

## 改动点
- 文件：`src/physics/thermodynamics.py`（修 bug + 加能量项）、`scripts/overfit.py`（加 loss）
- 参数量：**~2**
- 前置：先修 `amplitude_entropy_channel` 的维度问题

## 风险
**中高**。会同时影响 U（相位锁）和 S（振幅均匀）两个**已经工作的方向**，
而当前高通过冲是纯粹的单边问题（只有过冲没有欠幅），S 的"驱向均匀"不一定对症。

## 验证判据
1. 单边消融：只加 E_freq，不启用 −T·S，看是否已足够
2. 温度调度真的起作用（λ 随步数下降）
3. 若同时启用 −T·S，观察是否与 E_freq 冲突

## 备注
**这是最重的一个方案，只有在 A 和 B 都证明"耦合层面解决不了"时才值得做。**
优先做最小验证（单边 E_freq 正则），不要一上来上完整的 F=U−TS 框架。
