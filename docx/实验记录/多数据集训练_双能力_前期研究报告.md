# AetherGIF 多数据集全量训练 · 前期研究报告

> **日期**：2026-10-13 00:50
> **状态**：纯研究，未改动任何代码。所有结论基于阅读 `v3600_方案D_D125` 快照源码 + 实测。
> **触发**：用户决定——2500 步跑完（不论效果）即开始多数据集全量训练，目标双能力：
> - 能力 A：图片 + 文字 → GIF
> - 能力 B：文字 → GIF（纯文本，无需输入图）

---

## 摘要：三句话

1. **能力 A 的链路在架构上已经存在**，但当前是「作弊通路」——训练时直接把 target 场
   喂进漂移场，等于开卷考试。要变成真能力必须换成**可学习的图像编码器**。
2. **能力 B 缺一个关键模块**：模型现在没有「无 target 时的自持吸引子」。
   `DriftField.prototypes` 只有 16 个固定向量，没有跟文本绑定，无法表达"生成摇曳百合"。
3. **两者不是两个模型，是同一个模型的两个条件入口**。建议做成一次训练、两个推理模式，
   共享全部物理核参数——这样 A 的图像表征能力可以帮 B，B 的语义能力可以帮 A。

---

## 第一部分：现状盘点（读码结论）

### 1.1 当前模型的三个条件入口

`aether_gif_model.py::forward` 实际有三条信息通路：

| 通路 | 入口 | 现状 | 影响能力 |
|---|---|---|---|
| **文本** | `texts` → `omega_bias_head` / `drift_target_head` / `kappa_scale_head` / `T_scale_head` | `use_qwen=False` 时走 `self.text_param`（**单个可学习向量 `randn(1,896)*0.02`**）| 只影响 ω/κ/T 三个**全局标量或逐通道偏置**，不携带内容信息 |
| **图像** | `target_field` → `PhysicsBlock.forward(targets=...)` → `DriftField.forward(targets)` | 训练时传真 target | **这是唯一携带像素信息的通路，但它是真值泄漏** |
| **噪声起点** | `a0`/`theta0` 随机采样 | `a0 = exp(randn*0.8-2.5)` | 起点随机，ω 确定性（已按记忆铁律锁定） |

### 1.2 ★ 关键发现：训练时是「开卷考试」

```python
# aether_gif_model.py:211
a, theta, d = self.pmnncore.blocks[i](
    a, theta, omega, t_coord, s_coord,
    kappa=tf["kappa"] * kappa, T=tf["T"] * T,
    omega_d=tf["omega_d"],
    targets=target_field,      # ← 训练时把答案直接给漂移场
)
```

`DriftField.forward` 拿到 `targets` 后做两件事（`drift_field.py:224-232`）：
1. `tar = targets` 当吸引中心（`_attract_phase` 相位空间吸引）
2. `theta_tar = atan2(im_t, re_t)` 取目标相位，算 `sin(θ_tar - θ_i)` 逐点精确吸引

记忆里记着这条：**「漂移场是唯一把 target 送进相位演化的通路」**，两者缺一就死。

**这意味着**：
- 现在测出的任何"还原度"都不代表模型能力，因为模型**看到了答案**
- `profile_cos` 0.996、`wcos` 0.998 这些数字衡量的是「物理核能把给定目标场演化多好」，
  **不是「模型能不能从零生成出这个场」**
- 这也解释了为什么两天来画质一直修不好——**瓶颈从来不在模型侧，而在"模型根本没在学生成"**

> ⚠️ **这条要写进后续所有验收报告**：单样本过拟合的指标 ≠ 生成能力指标。
> 两者必须分开报，否则会重蹈"看 loss 下降就以为变好了"的覆辙。

### 1.3 `use_qwen=False` 的真相

```python
# aether_gif_model.py:106
self.text_param = nn.Parameter(torch.randn(1, self.text_dim, device=device) * 0.02)
```

- `text_dim = 896`（硬编码，即使 Qwen2.5-0.5B 实际 hidden_size=896 ✅ 恰好一致）
- `text_param` 形状 `[1, 896]`，`forward` 里 `.expand(len(texts), -1)`
- **所有样本共享同一个向量**，且**与文本内容完全无关**——传 `"台球"` 还是 `"hatched"``"，
  进入模型的向量一模一样

所以：**过去 2500 步的训练，文本通路等于不存在**。`texts=["台球"]` 这个参数
从头到尾没有产生任何有效作用。

### 1.4 推理路径 `generate()` 的现状

`aether_gif_model.py:238-304`，这条路径**从未被真正验证过**：

- 调 `self.qwen.encode([text])` —— 但 `use_qwen=False` 时 `self.qwen = None`，
  **直接 AttributeError**
- 内部 `targets=None` → 漂移场退化到 `self.prototypes`（16 个 `[n_prototypes, 2D]` 随机向量）
- `_field_to_frames` 里 `grid = int(round((N/T_step)**0.5))` 反推网格，
  变量名 `time_step=self.time_step`（模型构造时=5）而训练用 `WIN=5`，**恰好一致**，
  但这是巧合不是设计——`AetherGIFModel(time_step=5)` 默认值与 codec 的 `WIN=5` 没有耦合

**结论：`generate()` 是一条死代码，需要重写而不是修补。**

## 第二部分：两个能力各自的难点

### 2.1 能力 A：图片 + 文字 → GIF

#### 现状
链路"通"，但通的方式没有意义——见 §1.2，训练时直接吃 target。

#### 真能力需要什么
把 `targets=target_field` 换成 **`targets=ImageEncoder(reference_image)`**：

```
参考图 --[冻结视觉编码器]--> image_emb --[投影]--> [N, 2D] 条件场 --> DriftField
```

#### 候选编码器（按本机可行性排序）

| 方案 | 显存 | 本机可行性 | 备注 |
|---|---|---|---|
| **复用 Qwen 的视觉塔** | Qwen2.5-0.5B 是纯文本模型，**无视觉塔** | ❌ 不可行 | 别考虑 |
| **SigLIP/CLIP ViT-B/16** | ~0.4 GB (fp16) | ✅ 本地无权重，需下载 | 输出 512 维，与 text_dim=896 不同，需投影层 |
| **冻结 Qwen 隐状态做图像编码**（复用文本塔）| 0 | ⚠️ 折中方案 | 把图像 patch 序列当"句子"喂进去取 hidden_states。零额外显存，但不是预训练视觉特征，效果打折 |
| **复用现有 codec 反向** | 0 | ✅ **零成本，先试这个** | 参考图 → `encode_gif_to_field` 单帧 → 得到 `[N,2D]` 场。**与推理时的物理场同构，天然对齐** |

> ★ **强烈建议第一个难关走"复用 codec"路线**：
> 零额外参数、零额外显存、编码空间与漂移场输入完全同构，
> 且逻辑上自洽（"图和 GIF 是同一种物理场的两种来源"）。
> 缺点是必须先有图→场的编码，且只能编码到 125 系数（但 D=125 已经全保留了）。

#### 文字在能力 A 里的角色
- **训练时**：图给内容，文字给"这个动作是什么/什么情绪"
  → 二次元数据集的 `sentiments` + `characters` 标签**正好派上用场**
- **推理时**：图 + 文字 → GIF。文字必须是**条件**而非噪声

### 2.2 能力 B：文字 → GIF

这是**最难的一个**，因为它要求模型从纯噪声自持演化出正确内容。

#### 三个根本缺口

**缺口 1：没有「文本→吸引子」的通路**

当前 `DriftField` 只有两种吸引中心：
- `targets`（训练真值）
- `self.prototypes`：**16 个固定的 `[2D]` 向量，与文本无绑定**

模型无法表达"现在要生成摇曳百合的表情"。需要：
```
text --[Qwen]--> text_emb [896]
                --[映射]--> dynamic_prototype [2D]
                              ↓
                    DriftField 用它当吸引中心（替代固定 prototypes）
```

映射网络可以是 MLP（`896 → 2D`），参数量很小。

**缺口 2：起点噪声的语义**

现在是 `a0 = exp(randn*0.8-2.5)` 纯随机。要做条件生成，
起点应该由文本调制（不同文本 → 不同起点），否则同一个种子不同文本的演化轨迹
无法区分。**但记忆里有铁律：「ω 必须确定性，每次前向重采样 = 每次换动力系统」**——
a0 随机是可以的（它是初始状态不是动力系统），但要让文本**可学地调制**它的统计特性。

**缺口 3：无 target 时漂移场的梯度**

`self.prototypes` 是 nn.Parameter，梯度能回传。但 `use_checkpoint` 分支
（`drift_field.py:235`）在 `self.training and z.requires_grad` 时启用检查点，
**推理路径（`torch.no_grad()`）不走检查点**，两者数值行为需验证一致。

### 2.3 ★ 一个结构性矛盾必须先解决

记忆里有两条铁律：
- 「漂移场是唯一把 target 送进相位演化的通路」
- 「两者缺一就死」

**现在要做能力 B（无 target），就必须打破"必须有 target"这条。**
这不是新增功能，是**把「target 直连」换成「target 或 文本原型」二选一或多路融合**。

物理上对应：漂移场需要一个吸引子，吸引子可以是
- 训练时：图像编码器给出的场（能力 A）
- 训练时：文本映射给出的原型（能力 B）
- 推理时：由输入条件决定

**这是整个改造的核心，也是第一个难关。**

## 第三部分：难关拆解（建议顺序）

用户明确要求「分成好几个小的难关，一个个解决，出现新问题再解决」。
以下按**依赖顺序**排序，每关都有明确的验证判据和失败时的备选方案。

### 难关 0：把评测口径切开（**必须最先做**）

**问题**：现在所有指标都是"给定 target 的还原度"，无法评估生成能力。

**做什么**：搭两套独立评测
- `eval_recon`：现有指标（复现能力），保留但改名，避免误解
- `eval_generate`：真正的生成评测——给条件、不给 target、出图、评质量

**判据**（先定死，避免以后自欺）：
- 生成图不能是常量/纯噪声/过曝二值图
- 逐帧 std 不能全塌（第十七死穴：全局达标但部分帧崩塌）
- 生成的 GIF 内部帧差要与素材同量级（动态不足/过冲）
- 不同文本生成的图必须**可区分**（文本有效性检验）

**为什么放最前**：不做这个，后面每一关的"成功"都无法判定。
记忆里已有铁律「平均值度量会骗人」「降噪类验收必须以素材为及格线」，同理适用。

### 难关 1：修通 `use_qwen=True` 的文本通路

**问题**：`use_qwen=False` 下 `text_param` 与文本无关，文本通路等于不存在。

**做什么**：
1. 单独测 `QwenTextEncoder.encode()` 在本机跑通（权重完整，988MB，fp16 仅 0.49GB，显存够）
2. **预计算 + 缓存所有文本的 embedding**（数据集固定，文本不变，
   离线算好存盘，训练时直接查表）→ 训练时零 Qwen 显存开销
3. 打开 `use_qwen=True`，把缓存 embedding 喂进 `text_embs` 参数
   （`forward` 已支持 `text_embs` 直传，`aether_gif_model.py:161`）

**关键**：`forward` 已经预留了 `text_embs` 入口，这是个利好——不用改架构。

**验证判据**：同一批训练中，`omega_bias_head` 对**不同文本**产出**不同**的 ω；
且 `text_embs` 的方差在 batch 维度上非零。

**已知风险**：Qwen 输出经 mean pooling 后，不同文本的 embedding 余弦相似度可能都很高
（同质化）。**必须先测文本可分性**，如果 cosine 全在 0.95+，
说明需要换 pooling 策略（取最后 token 而非 mean），
或者干脆换成可训练的文本编码器（那就与"冻结 Qwen"的原则冲突，需和用户确认）。

### 难关 2：文本 → 动态原型（打通能力 B 的最小通路）

**问题**：`prototypes` 是固定 16 个向量，与文本无关。

**做什么**：加一个映射头
```
text_emb [B,896] --MLP--> proto [B, 2D]
```
在 `DriftField.forward` 里：`targets=None` 时用 `proto` 替代 `self.prototypes`。

**先做最小版本**：先用 `text_emb` 直接线性映射到 `[2D]`，不追求表达力，
只看「文本 → 不同吸引子 → 不同输出」这条链是否成立。

**验证判据**：固定 seed，用 5 个不同文本跑推理，输出图两两之间必须有**可测的差异**
（像素级 L2 距离 > 阈值，或 Sobel 场相关性 < 0.9）。
**如果 5 个文本生成结果几乎一样 → 映射没生效，别急着加容量，先查梯度是否回传。**

**这一步是能力 B 的最小可验证闭环**，通了才有资格谈质量。

### 难关 3：图像编码器接入（能力 A 的真通路）

**建议先走"复用 codec 单帧编码"路线**（§2.1 表格），零额外参数。

**做什么**：
```
参考图 → encode_gif_to_field(单帧) → [N,2D] → DriftField(targets=...)
```
训练时 `targets` 不再是 target 真值，而是参考图编码。

**关键设计问题（需决策）**：
- 参考图是 GIF 的**第一帧**？还是**任一帧**？还是**另一张无关图**？
  - 若用第一帧 → 模型学会"补全后续帧"，本质是预测任务，不是生成
  - **建议用另一张无关图**（或同素材的随机帧 + 大幅裁剪扰动），
    强制模型学"视觉风格 → 动图"，避免退化成帧间插值
- **必须配一个 text dropout**：训练时随机丢弃图像条件（置空），
  这样同一个模型在推理时既能"图+文"也能"纯文"。
  **这是双能力共享一个模型的关键技巧**，类似 classifier-free guidance 的训练侧做法。

**验证判据**：`targets` 换成图像编码后，`profile_cos` **必然大幅下降**
（因为不再有真值捷径）。**这是预期行为不是坏事**——
但同时必须看到生成结果开始"像"参考图的风格。

### 难关 4：多数据集训练管线

**问题**：现在是单样本过拟合（`batch=1`，一个 GIF 训 2500 步）。

**做什么**：
1. **Dataset 类**：扫描 `data/gif_raw/` 全部子目录，返回 (field, text_emb, meta)
   - 现有素材：9882 个（noto 878 + 老库 9004）
   - 二次元：下载中，已 52 个 / 29 部番剧
2. **文本构造策略**（没标签的素材怎么办？）：
   - 有标签（二次元库）：`f"{character} {sentiment}"`，例如 `"Yuuko Aioi fail"`
   - 无标签（noto/老库）：用**文件名/分类目录**当文本，例如 `"CAP"` `"BLOWING"`
   - **这本来就是一种数据增强**：文本的语义粒度不同，逼模型学不同层级的条件
3. **batch size**：显存允许时 >1，但要注意 `DriftField` 的
   `_attract_phase` 在 M=N 时是 `[B,N,N]` → 已用分块 + 梯度检查点处理，
   batch>1 会成倍吃显存。**先测 batch=2 的显存，再定**
4. **验证集划分**：必须留出 holdout（按**番剧**划分而非按 GIF，
   否则同一番剧的表情会泄漏到训练集，测出来的泛化是假的）

**验证判据**：holdout 上的 `eval_generate` 指标 vs 训练集上的，差距不应过大。
如果差距巨大 → 过拟合素材分布，不是泛化。

### 难关 5：两能力联合训练与评测

**做什么**：同一模型，训练时随机切换三种模式：
| 模式 | 图条件 | 文本条件 | 目的 |
|---|---|---|---|
| A | ✓ | ✓ | 图文生 |
| B | ✗ | ✓ | 纯文生 |
| C | ✓ | ✗ | 图生（可选，检验文本贡献）|

**推理评测**：同一个 ckpt，分别跑 A 和 B 两种模式，出对比图。

**这是最终验收关口**，判据：
- 模式 A：输出与参考图同风格，动图合理
- 模式 B：不同文本产出可区分的不同 GIF（内容可以糙，但不能千篇一律）
- 两模式共用同一份物理核参数（不是两个模型）

## 第五部分：风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| **Qwen embedding 同质化** | 文本条件无效，能力 B 归零 | 难关1 先测可分性，别等到训练才发现 |
| **图像编码退化成帧插值** | 能力 A 变成"补帧"而非"生成" | 难关3 用无关图 + 强制裁剪扰动 |
| **两模式互相干扰** | 纯文生时也想要图，或图文生时忽略文 | text dropout（难关3）+ 模式平衡采样（难关5）|
| **DriftField [B,N,N] 显存爆** | batch>1 训不动 | 已分块+检查点，需实测 batch=2 |
| **holdout 泄漏** | 泛化指标虚高 | 按番剧划分而非按 GIF |
| **旧指标误导** | 以为变好了实际没变 | 难关0 拆开口径 |
| **改架构推翻 D=125 成果** | 白干 | D=125 已验证有效，改动只在条件入口，物理核不动 |

> ★ 最后一条是本报告的**核心设计约束**：
> **所有改造只动「条件入口」，物理核（PMNNCore / DriftField 动力学 / Kuramoto /
> StandingWaveFFN / TimeField / Thermodynamics）一行不改。**
> D=125 已经把画质天花板抬到 49.82 dB（网格比 1.373→1.172），
> 这个成果不能因为要做双能力而丢掉。
